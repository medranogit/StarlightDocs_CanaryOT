Visualização completa de como o servidor Canary inicia, carrega de dados e gerencia dependências entre `data/` e `data-otservbr-global/`.

        ┌──────────────────────────────────────────┐

**Ordem Crítica de Carregamento:**
1. Items PRIMEIRO (referencias por monsters/npcs)
2. Monsters (usam items para loot)
3. NPCs (podem vender items)

**Se falhar:**
- ❌ Item não carregado → Monster com loot inválido
- ❌ Monster não carregado → Spawn inválido
- ❌ NPC não carregado → Vendor não existe

- ♻️ Scripts em data-otservbr-global/ **SUBSTITUEM** scripts em data/ com mesmo path
- 🔧 Callbacks são registrados, executados quando evento disparar

## ⚠️ Pontos Críticos de Falha

<Card title="O que pode quebrar a inicialização?" icon="warning">

### CRÍTICO (Servidor não inicia)

```
❌ config.lua AUSENTE
   → main() não consegue rodar
   → Erro: "config.lua not found"

❌ MySQL OFFLINE
   → DatabaseManager falha
   → Erro: "Cannot connect to MySQL"

❌ OTBM CORROMPIDO
   → IOMap::loadMap() falha
   → Erro: "Invalid OTBM file"
```

### ALTO (Funcionalidade quebrada)

```
❌ items.xml INVÁLIDO
   → Monstos não loadem (referenciam items)
   → Error: "Unknown item ID: 99999"

❌ startup/storage_keys_update.lua CARREGADO ANTES DA HORA
   → Players perdem quest progress
   → Storage values com valor errado
   → Critical: DEVE ser ÚLTIMO em startup

❌ scripts/lua COM SYNTAX ERROR
   → Callback não executa
   → Errores "Lua runtime error" no log
```

### MÉDIO (Performance)

```
⚠️ Múltiplos config.lua em data/ E data-otservbr-global/
   → Qual é carregado?
   → Usar config.lua.dist como template

⚠️ Muitos scripts customizados
   → Pode slow down startup
   → Memory usage aumenta
```

</Card>

<Aside>
**Resumo Executivo:**

1. **Ordem é CRÍTICA**: Config → DB → Items → Monsters → NPCs → Map → Lua → Network

2. **data/ vs data-otservbr-global/**:
   - `data/` = Base game padrão (Tibia)
   - `data-otservbr-global/` = Customizações do servidor
   - Arquivos com mesmo path em ambas: **data-otservbr-global/ GANHA**

3. **Dependências Absolutas**:
   - config.lua (MUST EXIST)
   - MySQL (MUST RUNNING)
   - Items loaded BEFORE Monsters
   - Monsters/NPCs loaded BEFORE Map
   - Items/Monsters/NPCs loaded BEFORE Scripts use them
   - startup/storage_keys_update.lua MUST BE LAST

4. **Personalização**:
   - Customize em `data-otservbr-global/` (não em `data/`)
   - Preserve `data/` para atualizações
   - Scripts: colocar em `scripts/` com mesmo path tree

5. **Debugging**:
   - Sempre checar `logs/canary.log`
   - Verificar `netstat -an | grep 7171` para port conflict
   - Testar MySQL: `mysql -u user -p database -e "SELECT 1;"`
</Aside>
