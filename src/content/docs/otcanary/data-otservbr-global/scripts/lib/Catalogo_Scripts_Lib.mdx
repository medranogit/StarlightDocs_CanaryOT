## 🧟 Monster Functions

Script de funções compartilhadas para comportamentos de monstros.

### **monster_functions.lua**
- **Caminho**: `data-otservbr-global/scripts/lib/monster_functions.lua`
- **Tipo**: Lib (Biblioteca de Funções)
- **Importação**: `local monsterFunctions = require("lib.monster_functions")`
- **Tamanho**: ~10 linhas de código

#### Funções Disponíveis

##### `Monster:handleCobraOnSpawn()`
- **Tipo**: Método
- **Descrição**: Manipula spawn especial da cobra com verificação de storage.
- **Parâmetros**: 
  - `self` - Objeto Monster (vinculado automaticamente)
- **Comportamento**:
  - Verifica se `Global.Storage.CobraFlask` >= tempo atual (os.time())
  - Se verdadeiro: Reduz saúde do monstro para 75% da máxima
  - Envia efeito visual CONST_ME_GREEN_RINGS
  - Se falso: Reseta storage para -1
- **Storage Usado**: `Global.Storage.CobraFlask`
- **Efeito Visual**: `CONST_ME_GREEN_RINGS`
- **Exemplo de Uso**:
```lua
local monsterFunctions = require("lib.monster_functions")

-- Em um script de spawn de monstro (como monster spawn script)
-- Chamado automaticamente durante spawn da cobra
function onSpawn(monster)
    monster:handleCobraOnSpawn()
end
```

#### Casos de Uso

1. **Spawn Especial de Cobra**
   - Aplicar efeito visual durante spawn
   - Reduzir vida baseado em tempo decorrido
   - Rastrear último spawn via storage

2. **Verificações de Tempo**
   - Usar `os.time()` para comparações de timestamp
   - Gerenciar cooldowns de spawn

#### Integração

Este script é importado e usado em:
- Scripts de spawn de monstros relacionados a cobra
- Sistema de Flask da cobra (CobraFlask)
- Eventos regulados por tempo

## 🎯 Register Actions

Sistema de registro e implementação de múltiplas ações do servidor em um único arquivo consolidado.

### **register_actions.lua**
- **Caminho**: `data-otservbr-global/scripts/lib/register_actions.lua`
- **Tipo**: Action Script (Registro de Múltiplas Ações)
- **Tamanho**: 1,177 linhas de código
- **Registro**: Automático ao carregar
- **Status**: Script de registro principal do servidor

#### Estrutura do Arquivo

<Card title="Componentes Principais" icon="layers">

**1. Configurações e Constantes** (linhas 1-200)
- Listas de IDs de itens (holes, fruits, items para moer, etc)
- Coordenadas especiais (lava positions, secretLibrary crystals)
- Strings de configuração (exhaustMessage, timers)
- Tabelas de mapeamento de transformação

**2. Funções Auxiliares** (linhas 201-400)
- `revertItem(position, itemId, transformId)` - Reverter transformação de item
- `removeRemains(toPosition)` - Remover restos/debris
- `revertCask(position)` - Reverter barril para estado original

**3. Registro de Ações** (linhas 401+)
- Múltiplas ações (action.onUse) implementadas
- Validações de player, storage, level, etc
- Transformações de items, teleportações, criação de monstros

</Card>

    local wagonItem = Tile(Position(32717, 31492, 11)):getItemById(7131)

    end

## 🔄 Comparação: Monster Functions vs Register Actions

| Aspecto | Monster Functions | Register Actions |
|---------|------------------|------------------|
| **Tipo** | Lib (Biblioteca) | Action Script |
| **Tamanho** | ~10 linhas | 1,177 linhas |
| **Importação** | Via require() | Carregado automaticamente |
| **Funções** | 1 função | 50+ ações |
| **Escopo** | Monstros | Ações diversas (dig, craft, etc) |
