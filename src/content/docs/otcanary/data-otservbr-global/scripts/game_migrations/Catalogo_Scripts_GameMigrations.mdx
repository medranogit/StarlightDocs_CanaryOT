# 🔄 Catálogo de Scripts - Game Migrations

Documentação técnica completa de todos os scripts de migração de dados do servidor, incluindo conversões de storage, atualizações de sistemas e resets globais.

## 🎯 Sobre essa Pasta de Scripts

<Card title="O que é?" icon="information">
A pasta `data-otservbr-global/scripts/game_migrations/` contém scripts **Lua** que executam **transformações de dados únicas** durante o boot do servidor. Cada migration move dados de um formato antigo para novo, atualiza infraestrutura ou realiza operações administrativas em todos os players automaticamente - nunca rodando mais de uma vez.
</Card>

<Card title="Como Usar o Catálogo" icon="star">
Este catálogo lista **todos os scripts de game_migrations** com:
- **Arquivo**: Nome exato do arquivo Lua
- **Timestamp**: ID único e ordem de execução
- **Função**: O que a migration faz
- **Dados Migrados**: Storages antigos → KV novos
- **Players Afetados**: Quantos/quais sistemas tocam
- **Efeitos**: Resultado após execução
- **Depen dências**: Outros sistemas impactados

Use **Ctrl+F** para buscar por nome de script ou tipo de dado.
</Card>

## 🔹 Migration 1: Move Hireling Data to KV

### **20231128213358_move_hireling_data_to_kv.lua**

**Timestamp**: `20231128213358` (primeira em ordem)  
**Tipo**: Storage → KV Conversion  
**Sistema**: Hireling (Contratados)

### Função Principal

Migra dados de hirelings (locações contratadas) do sistema antigo baseado em **bits de flags** nos storages para o novo sistema **KV (Key-Value)** com métodos especializados.

### Dados Migrados

**Skills Hirelings** (4 total):
```
Storage Antigo: 28800 (SKILL)

Skills:
  - BANKER     → Bit 1 (1<<0)
  - COOKING    → Bit 2 (1<<1)
  - STEWARD    → Bit 4 (1<<2)
  - TRADER     → Bit 8 (1<<3)

Conversão: Verifica cada bit e habilita correspondente via player:enableHirelingSkill(name)
```

**Outfits Hirelings** (9 total):
```
Storage Antigo: 28900 (OUTFIT)

Outfits:
  - BANKER     → Bit 1 (1<<0)
  - COOKING    → Bit 2 (1<<1)
  - STEWARD    → Bit 4 (1<<2)
  - TRADER     → Bit 8 (1<<3)
  - SERVANT    → Bit 16 (1<<4)
  - HYDRA      → Bit 32 (1<<5)
  - FERUMBRAS  → Bit 64 (1<<6)
  - BONELORD   → Bit 128 (1<<7)
  - DRAGON     → Bit 256 (1<<8)

Conversão: Verifica cada bit e habilita correspondente via player:enableHirelingOutfit(name)
```

### Algoritmo

```
Para cada player:
  1. Lê storage 28900 (outfits flags)
  2. Para cada outfit possível:
     - Se bit está ativo (hasBitSet):
       - Chama HIRELING_OUTFITS[outfitName]
       - Habilita outfit via player:enableHirelingOutfit(name)
       - Loga sucesso ou erro
  3. Lê storage 28800 (skills flags)
  4. Para cada skill possível:
     - Se bit está ativo (hasBitSet):
       - Chama HIRELING_SKILLS[skillName]
       - Habilita skill via player:enableHirelingSkill(name)
       - Loga sucesso ou erro
  5. Completa (dados agora em KV interno do hireling system)
```

### Validações

- ✅ Verifica se player e flags existem (flag `<= 0` = pula)
- ✅ Valida tableIDs contra HIRELING_OUTFITS e HIRELING_SKILLS
- ✅ Registra detalhes de cada outfit/skill processado
- ✅ Logs de erro se outfit/skill inválido

### Efeitos Colaterais

- **Antes**: Skills em storage 28800, Outfits em storage 28900
- **Depois**: Todos os skills/outfits no sistema KV do hireling
- **Lógica de Reset**: Storage não é explicitamente resetado em -1 (deixa intacto para referência)

### Players Afetados

Todos os players que tivessem:
- Menos de 4 combinações de hirelings ativo
- Até 9 outfits diferentes habilitados

### Dados de Referência

**Tabelas Externas** (definidas em arquivo de configuração):
```
HIRELING_OUTFITS = {
  BANKER = { id, "banker_outfit_name" },
  COOKING = { id, "cooking_outfit_name" },
  -- ... (9 total)
}

HIRELING_SKILLS = {
  BANKER = { id, "banker" },
  COOKING = { id, "cook" },
  STEWARD = { id, "steward" },
  TRADER = { id, "trade" },
}
```

## 🏆 Migration 2: Move Achievement to KV

### **20241708000535_move_achievement_to_kv.lua**

**Timestamp**: `20241708000535` (segunda em ordem)  
**Tipo**: Storage → KV Conversion  
**Sistema**: Achievements

### Função Principal

Migra **progresso de achievement** e **status de conclusão** do sistema antigo (storages) para o novo KV, além de recalcular **pontos totais** de achievements.

### Dados Migrados

**Achievement Progress** (por achievement ID):
```
Storage Antigo: 20000 + achievementID

Exemplo: Achievement ID 1
  Storage Key: 20001 (20000 + 1)
  Valor: número (progresso, ex: 50/100)

Conversão: Para cada achievement
  - KV Scoped: "achievementName-progress"
  - Valor: progressNumber (numérico)
```

**Achievement Completion** (por achievement ID):
```
Storage Antigo: 30000 + achievementID

Exemplo: Achievement ID 1
  Storage Key: 30001 (30000 + 1)
  Valor: > 0 = completo, <= 0 = incompleto

Conversão: Se valor > 0
  - Chama player:addAchievement(achievement.name)
  - Move para sistema nativo de achievements
```

**Points Recalculation**:
```
Algoritmo:
1. Coleta todas achievements desbloqueadas do player
2. Para cada achievementID obtido:
   - Busca informação via Game.getAchievementInfoById()
   - Se points > 0:
     - Incrementa total points
3. Adiciona total via player:addAchievementPoints(points)
```

### Estrutura de Dados

```lua
achievementProgressStorage = 20000  -- Base para progresso
achievementStorage = 30000          -- Base para status

-- Iteração através de ACHIEVEMENTS global
for id, achievement in pairs(ACHIEVEMENTS) do
    -- achievement.name = string (ex: "fireworkmaster")
    -- achievement.points = inteiro (pontos do achievement)
    
    oldStorageKey = 20000 + id
    oldCompletionKey = 30000 + id
end
```

### Algoritmo Detalhado

```
Para cada player:
  1. Para cada achievement definido em ACHIEVEMENTS:
     - Lê storage 20000 + id (progresso antigo)
     - Se progresso > 0:
       - Cria KV scoped: achievementName + "-progress"
       - Escreve valor de progresso
       - Reseta storage antigo em -1

  2. Para cada achievement definido em ACHIEVEMENTS:
     - Lê storage 30000 + id (conclusão antigo)
     - Se conclusão > 0:
       - Chama player:addAchievement(achievement.name)
       - Reseta storage antigo em -1

  3. Calcula pontos totais:
     - players:getAchievements() = lista de IDs obtidos
     - Para cada ID:
       - Info = Game.getAchievementInfoById(ID)
       - Se Info.points > 0:
         - total += Info.points
     - Adiciona pontos: player:addAchievementPoints(total)
```

### Validações

- ✅ Verifica se `progressNumber > 0` antes de migrar
- ✅ Verifica se `oldAchievement > 0` antes de adicionar
- ✅ Valida ACHIEVEMENTS table existe
- ✅ Calcula pontos apenas para achievements obtidos

### Efeitos Colaterais

- **Antes**: Progresso em storage 20000, Status em storage 30000
- **Depois**: Tudo em sistema KV nativo de achievements
- **Recalculação**: Todos os 100+ achievements revalidados e pontos recalculados

### Players Afetados

Todos os players com:
- Qualquer achievement desbloqueado
- Qualquer achievement em progresso (não completo)

### Dados de Referência

**Dependência Externa**:
```
ACHIEVEMENTS = {
  [1] = { name = "fireworkmaster", points = 50, ... },
  [2] = { name = "bonecarver", points = 50, ... },
  -- ... (100+ achievements)
}

Game.getAchievementInfoById(id) - Fornece informações do achievement
```

## 💎 Migration 3: Move VIP System to KV

### **20241708362079_move_vip_system_to_kv.lua**

**Timestamp**: `20241708362079` (terceira em ordem)  
**Tipo**: Storage → KV Conversion  
**Sistema**: VIP Account

### Função Principal

Migra **status VIP** de um simples storage inteiro para o novo **KV account-scoped**, facilitando verificações futuras e integrações com sistema de VIP.

### Dados Migrados

**VIP Status** (por account):
```
Storage Antigo: 150001 (isVipStorage)

Valor Original:
  > 0  = É VIP
  <= 0 = Não é VIP

Conversão:
  KV Scoped: "account"
  KV Key: "vip-system"
  KV Valor: true/false (boolean)
```

### Algoritmo Simples

```
Para cada player:
  1. Lê storage 150001 (VIP status antigo)
  2. Se valor > 0:
     - Chama player:kv():scoped("account"):set("vip-system", true)
     - Reseta storage em -1 para marcar como migrado
  3. Se valor <= 0:
     - Pula (já é não-VIP)
```

### Validações

- ✅ Verifica se `valor > 0` antes de processar
- ✅ Simples migração de boolean

### Efeitos Colaterais

- **Antes**: Status em storage 150001 (inteiro)
- **Depois**: Status em KV account "vip-system" (boolean)
- **Resultado**: Vérificações de VIP agora legem de KV em vez de storage antigo

### Players Afetados

Apenas players com:
- Storage 150001 > 0 (eram VIP no sistema antigo)

### Implementation

```lua
local isVipStorage = 150001

local function migrateIsVipSystem(player)
    local isVipValue = player:getStorageValue(isVipStorage)
    if isVipValue > 0 then
        player:kv():scoped("account"):set("vip-system", true)
        player:setStorageValue(isVipStorage, -1)
    end
end
```
