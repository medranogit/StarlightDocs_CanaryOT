## 💪 Script 1: Gaz'haragoth Heal

### **gaz_haragoth_heal.lua**

**Tipo**: CreatureEvent - onThink  
**Sistema**: Boss Ability  
**Função**: Gaz'haragoth cura 300k HP automaticamente quando atinge HP crítico

### Boss: Gaz'haragoth

```
Nome: Gaz'haragoth (Boss nomeado)
Tipo: Monstro
Habilidade: Cura automática no HP crítico
Trigger: HP < 12.5%
```

### Mecânica de Cura

#### Trigger (Condição de Ativação)

```lua
local hp = (creature:getHealth() / creature:getMaxHealth()) * 100
if hp < 12.5 and not creature:getCondition(...) then
    -- Ativa cura
end
```

- **HP Crítico**: < 12.5% (25% / 2)
- **Cooldown**: Usa condition com ID 88888 (não pode executar enquanto ativa)

#### Fase 1: Preparação (Imediato)

```
1. Adiciona CONDITION_REGENERATION ao boss
2. Boss grita: "Gaz'haragoth begins to draw on the nightmares to HEAL himself!"
3. Condição dura 7000ms (7 segundos)
4. Regeneração configurada para:
   - HEALTHGAIN: 0.01 (1% de HP a cada tick)
   - HEALTHTICKS: 7000ms
```

#### Fase 2: Cura Grande (Após 7 segundos)

```
1. AddEvent disparado após 7000ms
2. Valida se boss ainda existe (Creature(cid))
3. Cura 300.000 HP direto
4. Envia efeito CONST_ME_MAGIC_BLUE (efeito de magia)
5. Boss grita: "Gaz'haragoth HEALS himself!"
```

### Implementação Técnica

```lua
local condition = Condition(CONDITION_REGENERATION, CONDITIONID_DEFAULT)
condition:setParameter(CONDITION_PARAM_SUBID, 88888)          -- ID único
condition:setParameter(CONDITION_PARAM_TICKS, 7 * 1000)       -- 7 segundos
condition:setParameter(CONDITION_PARAM_HEALTHGAIN, 0.01)      -- 1% HP/tick
condition:setParameter(CONDITION_PARAM_HEALTHTICKS, 7 * 1000) -- 7 segundos

local gazHaragothHeal = CreatureEvent("GazHaragothHeal")

function gazHaragothHeal.onThink(creature)
    local hp = (creature:getHealth() / creature:getMaxHealth()) * 100
    
    -- Verificar HP e condição anterior
    if hp < 12.5 and not creature:getCondition(CONDITION_REGENERATION, CONDITIONID_DEFAULT, 88888) then
        -- Adiciona regeneração
        creature:addCondition(condition)
        creature:say("Gaz'haragoth begins to draw on the nightmares to HEAL himself!", TALKTYPE_MONSTER_YELL)
        
        -- Agendaa cura grande
        addEvent(function(cid)
            local creature = Creature(cid)
            if not creature then return end
            
            creature:addHealth(300000)
            creature:getPosition():sendMagicEffect(CONST_ME_MAGIC_BLUE)
            creature:say("Gaz'haragoth HEALS himself!", TALKTYPE_MONSTER_YELL)
            return true
        end, 7000, creature:getId())
    end
end

gazHaragothHeal:register()
```

### Efeitos Visuais

```
Efeito Visual: CONST_ME_MAGIC_BLUE
Descrição: Explosão azul mágica
Timing: Ao completar cura (7 seg depois)
Posição: Onde boss está
```

### Audio/Mensagens

```
Antes: "Gaz'haragoth begins to draw on the nightmares to HEAL himself!"
       (TALKTYPE_MONSTER_YELL - grito de monstro)

Depois: "Gaz'haragoth HEALS himself!"
        (TALKTYPE_MONSTER_YELL - grito de monstro)
```

### Cooldown e Reusabilidade

```
Condição ID: 88888 (único para este ability)
Duration: 7 segundos
Efeito: Enquanto condição está ativa, não pode executar novamente
Result: Mínimo 7 segundos entre curas
```

### Players Afetados

Boss **Gaz'haragoth** apenas - aplicado durante combate com players.

### Cálculo de HP

```
HP Total: creature:getMaxHealth()
HP Atual: creature:getHealth()
HP%: (Atual / Total) * 100

Exemplo:
- Max HP: 2.000.000
- Atual: 200.000
- HP%: (200000 / 2000000) * 100 = 10% < 12.5% → Dispara cura
```

### Timeline Completo

```
t=0s:      Boss atinge < 12.5% HP
           onThink(boss) é chamado

t=0.1s:    Cria condition de regeneração (7s)
           Mostra mensagem "begins to draw..."
           Agenda event para t=7s

t=0-7s:    Boss regenera continuamente durante 7 segundos

t=7s:      addEvent(function...) dispara
           Cura 300k HP
           Mostra efeito MAGIC_BLUE
           Mostra mensagem "HEALS himself!"
           
t=7s+:     Cooldown termina (condition expira)
           Pode executar novamente se HP < 12.5%
```

### Variações Possíveis

```lua
-- Mais frequente
if hp < 30 then  -- Em vez de < 12.5

-- Menos regeneração
condition:setParameter(CONDITION_PARAM_HEALTHGAIN, 0.005)

-- Mais cura
creature:addHealth(500000)  -- Em vez de 300000

-- Sem delay
-- Remove addEvent, cura imediatamente

-- Múltiplos boss

    if creature:getName() == name then
        -- Execute
    end
end
```

## 🛡️ Script 2: Grand Master Oberon Immunity

### **grand_master_oberon_immunity.lua**

**Tipo**: CreatureEvent - onHealthChange  
**Sistema**: Boss Immunity  
**Função**: Envia efeito especial (HOLYAREA) toda vez que Grand Master Oberon recebe dano

### Boss: Grand Master Oberon

```
Nome: Grand Master Oberon (Boss nomeado)
Tipo: Monstro
Habilidade: Resposta visual ao receber dano
Trigger: Qualquer dano (physical/magic/elemental)
```

### Mecânica de Resposta

#### Trigger

```lua
function onHealthChange(creature, attacker, primaryDamage, primaryType, 
                        secondaryDamage, secondaryType, origin)
    if creature and creature:isMonster() then
        -- Dispara a QUALQUER dano
    end
end
```

- **Acionador**: Qualquer tipo de dano (sem filtro)
- **Validação**: Apenas se é monstro

#### Ação

```lua
creature:getPosition():sendMagicEffect(CONST_ME_HOLYAREA)
return true  -- Aceita dano normalmente
```

**Efeito**: HOLYAREA (Área sagrada/divina)

### Implementação Técnica

```lua
local grandMasterOberonImmunity = CreatureEvent("OberonImmunity")

function grandMasterOberonImmunity.onHealthChange(creature, attacker, primaryDamage, primaryType, 
                                                   secondaryDamage, secondaryType, origin)
    if creature and creature:isMonster() then
        creature:getPosition():sendMagicEffect(CONST_ME_HOLYAREA)
    end
    return true  -- Dano completo aceito
end

grandMasterOberonImmunity:register()
```

### Efeitos Visuais

```
Efeito: CONST_ME_HOLYAREA
Nome: Holy Area / Divina Area
Descrição: Aura sagrada/divina
Timing: TODA VEZ que recebe dano
Frequência: Cada hit causa um efeito
Posição: Onde boss está
```

### Comportamento

```
Player ataca Oberon com 500 dano
  ↓
onHealthChange dispara
  ↓
Efeito HOLYAREA enviado
  ↓
Oberon recebe 500 dano (completo)
  ↓
HP -= 500
```

### Players Afetados

Boss **Grand Master Oberon** apenas - aplicado durante qualquer combate.

### Diferença com Verdadeira Immunity

```lua
-- Este script:
-- NÃO bloqueia dano (return true)
-- Só mostra efeito visual
-- Dano é aceito completamente

-- Se quisesse immunity real:
return false  -- Bloquearia dano
-- ou
return true com dano = 0  -- Reduziria para 0

-- Atual: Efeito visual cosmético + dano normal
```

### Variações Possíveis

```lua
-- Apenas dano específico (fogo)
if primaryType == COMBAT_FIREDAMAGE then
    creature:getPosition():sendMagicEffect(CONST_ME_HOLYAREA)
end

-- Immunity verdadeira
if primaryType == COMBAT_HOLYDOMAGE then
    return false  -- Cancela dano sagrado
end

-- Dano reduzido
if primaryType == COMBAT_PHYSICALDAMAGE then
    -- primaryDamage = primaryDamage / 2  -- Metade do dano
    return true
end

-- Efeitos diferentes por tipo
if primaryType == COMBAT_FIREDAMAGE then
    creature:getPosition():sendMagicEffect(CONST_ME_FIREAREA)
elseif primaryType == COMBAT_ICEDAMAGE then
    creature:getPosition():sendMagicEffect(CONST_ME_ICEAREA)
else
    creature:getPosition():sendMagicEffect(CONST_ME_HOLYAREA)
end
```

### Padrão de Proteção

```
Tipo 1: Immunity (bloqueia dano - return false)
Tipo 2: Redução (dimininui dano - modifica primaryDamage)
Tipo 3: Cosmético (mostra efeito apenas - return true, sem modificação)

Este script é: TIPO 3 (Cosmético)
```

## 🎁 Script 3: Reward Exercise

### **reward_exercise.lua**

**Tipo**: CreatureEvent - onLogin  
**Sistema**: Player Reward  
**Função**: Notifica player ao login se pode receber arma de exercício

### Trigger

```
Evento: Player faz login (onLogin)
Condição 1: Config TOGGLE_RECEIVE_REWARD ativa
Condição 2: Town do player >= AB_DENDRIEL (cidades avançadas)
Condição 3: Player NÃO recebeu reward ainda
```

### Implementação Técnica

```lua
local winReward = CreatureEvent("WinReward")

function winReward.onLogin(player)
    -- Verificar se config permite
    if configManager.getBoolean(configKeys.TOGGLE_RECEIVE_REWARD) then
        -- Verificar se town é avançada
        if player:getTown():getId() >= TOWNS_LIST.AB_DENDRIEL then
            -- Verificar se já recebeu
            if player:getStorageValue(tonumber(Storage.PlayerWeaponReward)) ~= 1 then
                -- NOTIFICAR
                player:sendTextMessage(MESSAGE_LOGIN, 
                    "You can receive an exercise weapon using command !reward")
            end
        end
    end
    return true
end

if configManager.getBoolean(configKeys.TOGGLE_RECEIVE_REWARD) then
    winReward:register()  -- Só registra se config ativa
end
```

### Configuração

```lua
-- Registração Condicional
if configManager.getBoolean(configKeys.TOGGLE_RECEIVE_REWARD) then
    winReward:register()
else
    -- System desativado - script não funciona
end
```

### Storage Usado

```lua
Storage.PlayerWeaponReward
    = 0: Não recebeu reward
    = 1: Já recebeu reward (não mostra mensagem novamente)
```

### Towns Permitidos

```
TOWNS_LIST.AB_DENDRIEL (e superiores)

Tibia Towns por progressão:
1. Rookgaard (iniciante)
2. Thais
3. Venore
4. Carlin
5. Edron
6. Kazordoon
7. AB_DENDRIEL ← Aqui em diante pode receber
8. Yalahar
9. Farmine
10. Oramond
```

### Mensagem Exibida

```
Tipo: MESSAGE_LOGIN (mensagem de login)
Texto: "You can receive an exercise weapon using command !reward"

Significado: Player pode usar comando !reward no servidor
              para reclamar uma arma de exercício grátis
```

### Fluxo Completo

```
1. Player faz login
   ↓
2. onLogin(player) é chamado
   ↓
3. Verifica TOGGLE_RECEIVE_REWARD (config)
   ↓ SIM
4. Verifica Town >= AB_DENDRIEL
   ↓ SIM
5. Verifica Storage.PlayerWeaponReward
   ↓ == 0 (não recebeu)
6. Envia mensagem: "You can receive an exercise weapon..."
   ↓
7. Player vê mensagem no chat
   ↓
8. Player usa comando !reward
   ↓
9. Recebe arma
   ↓
10. Storage atualizado para = 1
    (próximo login não mostra mensagem)
```

### Players Afetados

**Todos os players** que fazem login, mas filtra por:
- Config estar ativa
- Town >= AB_DENDRIEL
- Ainda não ter recebido reward

### Exercício Weapon

```
Weapon de exercício: Arma gratuita
Propósito: Iniciantes treinar skills
Stats: Baixos (balanced para training)
Comando: !reward (comando específico para reclamar)
```

### Storage Pattern

```lua

    -- Não recebeu (== 0 ou nil)

    -- Já recebeu (== 1)

```

Status: true/false (feature ligada/desligada)

Se false: CreatureEvent não é registrado

### Algoritmo de Execução

```lua
function winReward.onLogin(player)
    if not player then return false end
    
    -- Itera todas as quests no table
    for _, questData in ipairs(questTable) do
        -- Obtém storage atual do player
        local currentValue = player:getStorageValue(questData.storage)
        
        -- Verifica se valor é menor
        if currentValue < questData.storageValue then
            -- Atualiza para valor desejado
            player:setStorageValue(questData.storage, questData.storageValue)
        end
    end
    
    return true
end
```

**Lógica**:
1. Para cada quest na tabela
2. Lê valor atual do player em `storage`
3. Se atual < desejado, atualiza para desejado
4. Repete para todas as quests

### Efeito Visual

```
Nenhum efeito visual direto
Mas quests aparecem como "completas" se o player checar
Storage é atualizado silenciosamente
```

### Players Afetados

**Todos os players** ao fazer login (sem filtros)

### Casos de Uso

```
Novo player:
  1. Faz login
  2. onLogin(player) auto-marca 100+ quests
  3. Quests aparecem como "done" no journal
  4. Pode focar em conteúdo avançado
  
Vantagem: Não fica preso em quests base
Desvantagem: Perde rewards de quests
```

### Valores de Storage

**Padrão**: Cada quest tem um storageValue final
- storageValue = 1: Quest simples (completa/não)
- storageValue = 2-50: Quests com múltiplos estágios
- storageValue = 7: Número fixo para certos marcos

### Exemplo de Fluxo

```
Quest: Bigfoot's Burden QuestLine
  Setting: storage = Storage.Quest.U9_60.BigfootsBurden.QuestLine
           storageValue = 2 (primeiro marco)

Player login:
  1. Obtém currentValue (ex: 0 ou null)
  2. Verifica: 0 < 2? SIM
  3. player:setStorageValue(storage, 2)
  4. Primeira stage marcada como feita

Next login:
  1. Obtém currentValue (agora = 2)
  2. Verifica: 2 < 2? NÃO
  3. Não atualiza (já tem valor)
  4. Progresso preservado
```

## 💪 Script 5: Greater Minion

### **greater_minion.lua**

**Tipo**: CreatureEvent - onThink  
**Sistema**: Minion Transformation

## 🎓 Relatório Técnico

### Padrões Observados

```
Tipos de Evento (6 mapeados):
1. onThink: Boss mechanics periódicos (12 scripts)
2. onLogin: Player systems ao conectar (5 scripts)
3. onHealthChange: Reações a dano (4 scripts)
4. onDeath: Ao morrer (3 scripts)
5. onPrepareDeath: Antes de morrer (2 scripts)
6. onAdvance: Ao ganhar level/skill (2 scripts)

Principais Padrões:
1. Boss Abilities (health-triggered) - 6 scripts
2. Login Validations (config-gated) - 5 scripts
3. Transformations (timed/triggered) - 3 scripts
4. Death Spawns (probabilístico) - 3 scripts
5. Progression Gates (level-check) - 4 scripts
6. Helper Functions (método-based) - 2 scripts
```

### Storage Management

```
Métodos de Persistência:
- Conditions: Para cooldowns e estados (IDs únicos: 88888)
- Storage Values: Para tracking de progress
- Item IDs: Para spawn/remove
- Monster Methods: Para registration/unregistration

Padrão Storage:
Storage.Dawnport.DoorVocation (quest-like)
Storage.PlayerWeaponReward (binary)
Game.getStorageValue(112416) (global quest counter)
```

### Configuration & Registration

```
Patterns:
1. Always Active: gaz_haragoth_heal, greater_minion, etc
2. Config-Gated: reward_exercise, freequests, login
3. Conditional: invulnerable (função helper)
4. Multi-Event: login_events (registra outros)

Conditional Registration:
if configManager.getBoolean(configKeys.FEATURE) then
    event:register()
end
```

### Escalabilidade

```
Fácil adicionar:
- Novos bosses: Cópia de script existente + novo nome
- Novos eventos: Append à estrutura data table
- Transformações: Adicionar novo tipo à lista

Difícil modificar:
- Omrafir_explode: Hardcoded positions
- Shargon_growth_check: Item IDs fixos
- Dawnport/Rookgaard: Tied to TOWNS_LIST constants
```

<Aside type="note">
**Padrões em 25 Scripts**:

1. Boss scripts usam **onThink** para periodic check + HP thresholds
2. Player scripts usam **onLogin** para one-time checks e validation
3. Death events usam **onDeath** para spawns/loot/cleanup
4. Progression usa **onAdvance** para level gates
5. Pre-death healing usa **onPrepareDeath** para último HP save
6. Todos validam creature/player existence antes de usar
7. Storage + Condition IDs são principal método de persistência
8. Conditions usam IDs únicos (88888 é padrão)
9. Delayed events (addEvent) para timed transformations
10. Magic effects para feedback visual (MORTAREA, TELEPORT, etc)

**Técnicas Avançadas Observadas**:

✅ onReceivDamageSL() - Shared life pool splitting  
✅ creature:setType() - Runtime name changes  
✅ creature:getMaster() - Summon tracking  
✅ creature:inSharedLife() - Pool detection  
✅ Game.createMonster() - Dynamic spawning  
✅ addEvent() + Creature(cid) - Safe delayed execution  
✅ Condition parameters - Cooldown management  
✅ item:setActionId() - Item tagging  
✅ player:getTown():getId() - Location-based logic  
✅ creature:registerEvent/unregisterEvent - Dynamic registration  

**Escalabilidade**:

- Boss abilities: Trivial add (copy pattern)
- Login systems: Simple append to events table
- Transformations: Add new form to creature type list
- Death events: Edit creature XML + script

**Performance Considerations**:

- onThink: Executado constantemente, manter leve
- onHealthChange: Cada hit, avoid heavy computations
- onLogin: Raro, pode fazer processing pesado
- onDeath: Once per death, OK for bulk operations
- addEvent delays: Não bloqueia thread principal

</Aside>
