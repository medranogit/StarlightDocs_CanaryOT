# 📄 startup.lua

Arquivo principal de inicialização do servidor responsável por orquestrar o carregamento de todos os módulos e funções de startup. Carrega dois sub-loaders que trazem tabelas e funções globais.

## 📋 Resumo Executivo

<Card title="O que este arquivo faz?" icon="info">

Arquivo extremamente simples mas crítico com responsabilidade clara:

**Orquestar o carregamento de dois subsistemas essenciais**:

```lua
dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")
dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
```

**Efeito Cascata**:
1. Primeiro: Carrega **tabelas globais** (constantes, storage keys, etc)
2. Segundo: Carrega **funções globais** (item creation, map loading, etc)
3. Resultado: Servidor totalmente inicializado e pronto

**Padrão**: Inicialização em duas etapas
- **Etapa 1**: Tabelas (dados estáticos)
- **Etapa 2**: Funções (lógica executável)

</Card>

## 🔍 Análise Detalhada

<Card title="Breakdown de Cada Linha" icon="magnifying-glass">

### Linha 1: Carregamento de Tabelas

```lua
dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")
```

**Propósito**: Carregar todas as tabelas, constantes e dados estáticos necessários.

**Sequência**:
1. `dofile()` executa `tables/load.lua`
2. `tables/load.lua` carrega seus sub-arquivos:
   - `const.lua` → Constantes do servidor
   - `storage.lua` → Storage keys de players
   - `keys.lua` → Chaves especiais
   - Etc...
3. Todas estas tornam-se **variáveis globais**
4. Disponíveis para próxima etapa

**Resultado**: Servidor com toda configuração estática pronta.

---

### Linha 2: Carregamento de Funções

```lua
dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
```

**Propósito**: Carregar todas as funções executáveis e lógica.

**Sequência**:
1. `dofile()` executa `others/load.lua`
2. `others/load.lua` carrega:
   - `functions.lua` → 6 Funções de inicialização de mapa
   - Pode carregar mais no futuro
3. Todas as funções tornam-se **disponíveis globalmente**
4. Podem ser chamadas por qualquer outro script

**Resultado**: Servidor com todas as funções prontas para executar.

---

### Dependência de Ordem

```
Tabelas (Linha 1) ← DEVE SER PRIMEIRO
    ↓
Funções (Linha 2) ← USA tabelas da Linha 1
```

**Crítico**: Inverter a ordem causaria erro!

```lua
-- ❌ ERRADO (função precisa de tabelas)
dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")

-- ✅ CORRETO (tabelas primeiro)
dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")
dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
```

</Card>

## 🎯 Padrão de Orquestração

<Card title="Arquitetura de Dois Loaders" icon="lightbulb">

### Por que dois arquivos separados?

| Aspecto | Tabelas | Funções |
|---------|---------|---------|
| **Mudança** | Raro | Frequente |
| **Complexidade** | Baixa | Alta |
| **Dependências** | Mínimas | Precisa de tabelas |
| **Recarregamento** | Crítico evitar | Seguro recarregar |
| **Ordem** | Rígida (PRIMEIRO) | Flexível |

### Separação em Dois Estágios

```
┌─ ESTÁGIO 1: DADOS
│  dofile(...tables/load.lua)
│  ├─ Define constantes
│  ├─ Define storage keys
│  ├─ Sem lógica complexa
│  └─ Rápido, seguro
│
└─ ESTÁGIO 2: LÓGICA
   dofile(...others/load.lua)
   ├─ Define funções
   ├─ Usa dados do estágio 1
   ├─ Pode ser complexo
   └─ Pronto para executar
```

### Vantagens

1. **Clareza**: Duas responsabilidades bem definidas
2. **Manutenção**: Fácil adicionar tabelas ou funções
3. **Performance**: Tabelas carregadas primeiro (mais rápido)
4. **Segurança**: Ordem garantida
5. **Escalabilidade**: Suporta crescimento

</Card>

## 🛡️ Considerações de Implementação

<Card title="Notas Técnicas Importantes" icon="shield">

### DATA_DIRECTORY Path

- Crítico estar definido corretamente
- Tipicamente: `/path/to/data/` ou `C:\\otserver\\data\\`
- Concatenado com strings de path relativo

### Sem Tratamento de Erro

**Atual**:
```lua
dofile(...) -- Se erro, falha silenciosamente/trava
```

**Potencial Melhoria**:
```lua
if not dofile(...) then
  error("Failed to load tables!")
end
```

### Bloqueia Startup

Neste arquivo, há **espera síncrona**:
- Linha 1 executa completamente
- Linha 2 só inicia após Linha 1 terminar
- Nenhuma paralelização possível

### Ordem Crítica

**É literalmente a coisa mais importante**:

```lua
-- Trocar a ordem = CRASH no startup
-- Qualquer erro = CRASH no startup
-- Arquivo faltando = CRASH no startup
```

### Reutilização de Nomes

Se `tables/load.lua` e `others/load.lua` definirem o mesmo nome:

```lua
-- ❌ Conflito
dofile("tables.lua")   -- Define: MyFunction() = version1
dofile("others.lua")   -- Define: MyFunction() = version2
MyFunction()           -- Qual versão? (version2, último carregado)
```

**Solução**: Namespacing (encapsulamento em tabelas)

</Card>

## 🎓 Extensibilidade Futura

```lua
dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")
dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
```

```lua
logger.info("Starting server initialization...")

dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")
logger.info("Tables loaded")

dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
logger.info("Functions loaded")

logger.info("Server initialization complete")
```

### Adicionar Validação

```lua
local tablesOK = dofile(DATA_DIRECTORY .. "/startup/tables/load.lua")

  error("Failed to load startup tables")
end

local functionsOK = dofile(DATA_DIRECTORY .. "/startup/others/load.lua")
if not functionsOK then
  error("Failed to load startup functions")
end
```
