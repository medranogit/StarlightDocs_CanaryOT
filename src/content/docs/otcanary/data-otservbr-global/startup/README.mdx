## 🚪 Door Level - Sistema de Portas por Level

<Card title="Faixa 1000-1999" icon="door">

### Como Funciona

As portas com system level usam um formato especial onde o número após 1 define o level:

```
Padrão: 1[level]
Exemplos:
1010 = Level 10
1050 = Level 50
1100 = Level 100
1250 = Level 250
```

### Exemplos de Uso

| Action ID | Level | Descrição |
|-----------|-------|-----------|
| 1010 | 10 | Porta Level 10 |
| 1020 | 20 | Porta Level 20 |
| 1050 | 50 | Porta Level 50 |
| 1100 | 100 | Porta Premium/Elite |
| 1250 | 250 | Porta Max Level |

### Regra Importante

Nesta faixa **1000-1999**:
- Sistema de level é **fixo** (três dígitos determinam o level)
- Nenhuma outra funcionalidade deve usar esta faixa
- Comportamento predefinido: validar level do player

</Card>

## 🚀 Teleportes e Magic Forcefields

<Card title="TeleportItem vs Teleport" icon="warp">

### TeleportItem (Action/Unique: 15001-20000)

**Items de teleporte** que jogador coloca no backpack:

```
15001 = Teleport Item #1
15500 = Teleport Item #500
20000 = Teleport Item #5000
```

**Comportamento**:
- Item no backpack do player
- Usa action ID para definir destino
- Exemplo: 15001 teleporta para posição X

### Teleport Magic Forcefield (Action/Unique: 35001-40000)

**Magic Forcefield** - teleporte por walking through:

```
35001 = Magic Forcefield #1
35500 = Magic Forcefield #500
40000 = Magic Forcefield #5000
```

**Comportamento**:
- Piso no mapa (não item carregável)
- Ao pisar, teleporta automaticamente
- Usa coordenadas pré-definidas

### Diferença Crítica

| Aspecto | TeleportItem | Magic Forcefield |
|---------|---|---|
| **Tipo** | Item (backpack) | Piso/Tile |
| **Acionamento** | Use item | Pisar na área |
| **Faixa Action** | 15001-20000 | 35001-40000 |
| **Movimento** | Manual | Automático |

</Card>

```
30001 = Lever #1
```

```lua
-- Cada uma incrementa storage
```

## 📌 Melhores Práticas

<Card title="Como Usar Este Guia" icon="star">

### Ao Criar Nova Funcionalidade

1. **Identificar Tipo**:
   - Porta? → Use 1000-1999
   - Baú? → Use 5000-12000 ou 12001-15000
   - Teleporte? → Use 15001-20000 ou 35001-40000
   - Etc...

2. **Verificar Faixa Livre**:
   - Confirmar que ID não foi usado
   - Deixar "gaps" para crescimento
   - Documentar uso novo

3. **Registrar em Documentação**:
   - Atualizar este documento
   - Adicionar comentário no código
   - Marcar range como "reserved"

### Convenções

```lua
-- ✅ BOM: Comentar faixa usada
local TELEPORT_ACTION_ID = 15500
-- Teleport Item para quest especial
-- Faixa: 15001-20000 (TeleportItem)

-- ❌ RUIM: Sem documentação
local MY_ACTION_ID = 15500

-- ❌ RUIM: Conflitar com outra faixa
local DOOR_ACTION_ID = 25000  -- Isso é Tile!
```

### Evitar Conflitos

- Nunca reutilize IDs já reservados
- Se absolutamente necessário, retire do código anterior
- Documente qualquer mudança
- Comunique com team

## ⚠️ Notas Importantes

<Card title="Cuidados e Avisos" icon="alert">

### Storage Keys vs Action IDs

**Action ID**:
- Usado em items do mapa
- Via `item:setAttribute(ITEM_ATTRIBUTE_ACTIONID, id)`
- Executado ao usar/pisar/pegar item

**Storage Key**:
- Usado em player storage
- Via `player:setStorageValue(key, value)`
- Rastreia estado persistente

**Não confunda**: Action 103 ≠ Storage 103 (pode ambos existir)

### Door Storage Especial

```lua
-- DoorStorage usa storage como action
-- Não tem action ID numérico
-- Unique ID: 22001-25000

-- Exemplo:
door:setAttribute(ITEM_ATTRIBUTE_UNIQUEID, 22001)
-- Funcionamento definido via script customizado
```

### Reversion de Ordem

A ordem de faixas é **arbitrária mas consistente**:

```
Não há "melhor" faixa
Todas funcionam igual
Order é apenas para organização
```

### Crescimento Futuro

```
0-999      = Reservado para core/internals
1000-5000  = Medium systems
5000-42000 = Main game systems
42000+     = Custom servers
```

</Card>

## 📚 Organização de Arquivos

<Card title="Estrutura da Pasta Startup" icon="folder">

```
startup/
├── startup.lua                (Entry point)
├── README.mdx                (Este arquivo)
│
├── tables/
│   ├── load.lua             (Carrega tabelas)
│   ├── const.lua            (Constantes)
│   ├── storage.lua          (Storage keys)
│   └── keys.lua             (Key definitions)
│
└── others/
    ├── load.lua             (Carrega funções)
    └── functions.lua        (Funções de inicialização)
```

### Por Que Essa Estrutura?

- **Tabelas** carregam primeiro (dados estáticos)
- **Funções** carregam segundo (usam dados)
- **Others** para tudo que não é tabela
- **Separação clara** de concerns
