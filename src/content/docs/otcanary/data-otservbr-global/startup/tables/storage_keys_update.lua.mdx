## 📋 Resumo Executivo

<Card title="O que este arquivo faz?" icon="info">

**Propósito**: Versioning de storage keys

**O Problema**:
- Servidor evolui, storage keys mudam
- Old players têm valores nos antigos
- Novos jogadores usam novos keys
- Inconsistência de dados!

**A Solução**: QuestKeysUpdate

```lua
[versionNumber].latest = 4  -- Versão atual
[versionNumber][oldKey] = newKey  -- Mapear migração
```

**Exemplo**:
```
Storage.Quest.BansheeQuest.OldKey (obsoleto)
    ↓ (migração)
Storage.Quest.BansheeQuest.NewKey (atual)
```

</Card>

## 📊 Variáveis Globais

<Card title="Tabela Principal" icon="database">

### QuestKeysUpdate

**Propósito**: Definir migrações de storage keys

**Estrutura**:
```lua
QuestKeysUpdate = {
    [0].latest = 4,  -- Versão mais recente
    
    [1] = {
        [Storage.Quest.BansheeQuest.OldKey1] = Storage.Quest.BansheeQuest.NewKey1,
        [Storage.Quest.BansheeQuest.OldKey2] = Storage.Quest.BansheeQuest.NewKey2,
    },
    
    [2] = {
        -- Migrações da versão 1→2
    },
    
    [3] = {
        -- Migrações da versão 2→3
    },
    
    [4] = {
        -- Migrações da versão 3→4
    }
}
```

**Campos**:
- `[0].latest`: Número da versão atual
- `[version]`: Hash de migrações para essa versão
- `oldKey → newKey`: Mapeamento

## 🔄 Fluxo de Migração

<Card title="Como Funciona a Atualização" icon="flow">

**Quando Player Faz Login**:

1. **Carrega character**:
   ```lua
   playerStorages = {
       [OLD_STORAGE_1] = value1,
       [OLD_STORAGE_2] = value2,
       -- valores antigos
   }
   ```

2. **Verifica versão**:
   ```lua
   playerVersion = player:getStorageValue(STORAGE_PLAYER_VERSION)
   if playerVersion < QuestKeysUpdate[0].latest then
       -- Precisa atualizar
   end
   ```

3. **Aplica migrações**:
   ```lua
   for v = playerVersion + 1, QuestKeysUpdate[0].latest do
       for oldKey, newKey in pairs(QuestKeysUpdate[v]) do
           if playerStorages[oldKey] then
               playerStorages[newKey] = playerStorages[oldKey]
               playerStorages[oldKey] = nil
           end
       end
   end
   ```

4. **Atualiza versão**:
   ```lua
   player:setStorageValue(STORAGE_PLAYER_VERSION, QuestKeysUpdate[0].latest)
   ```

</Card>

## 🎛️ Integração com Sistema

<Card title="Uso em Conjunto" icon="link">

**Em `storage_keys_update.lua`**:
```lua
QuestKeysUpdate = {
    [0].latest = 4,
    [1] = {
        [Storage.Quest.BansheeQuest.DoorOld] = Storage.Quest.BansheeQuest.Door
    }
}
```

**Em `startup/others/functions.lua`** (ou similar):
```lua
function updateKeysStorage(player)
    local playerVersion = player:getStorageValue(STORAGE_PLAYER_VERSION) or 0
    
    if playerVersion >= QuestKeysUpdate[0].latest then
        return  -- Already up to date
    end
    
    -- Aplica migrações progressivas
    for version = playerVersion + 1, QuestKeysUpdate[0].latest do
        for oldKey, newKey in pairs(QuestKeysUpdate[version]) do
            local oldValue = player:getStorageValue(oldKey)
            if oldValue > 0 then
                player:setStorageValue(newKey, oldValue)
                player:setStorageValue(oldKey, -1)  -- Clear old
            end
        end
    end
    
    -- Atualiza versão do player
    player:setStorageValue(STORAGE_PLAYER_VERSION, QuestKeysUpdate[0].latest)
end
```

**No Login** (creaturescripts):
```lua
local function onLogin(player)
    updateKeysStorage(player)
    return true
end
```

## 💡 Por Que É Importante

<Card title="Impacto do Sistema" icon="lightbulb">

### Cenário SEM Migração:
```
Server v1:
- Storage.Quest.X = 1000

Server v2 (renomeou para NewX = 5000):
- Players with v1 data: Perderam progresso!
- Quest broken, impossível continuar
```

### Cenário COM Migração:
```
Server v1:
- Storage.Quest.X = 1000

Server v2:
- QuestKeysUpdate[1] = {[1000] = 5000}
- Login: Player's 1000 → 5000 automaticamente
- Quest continua funcionando!
```

**Resultado**: Continuidade garantida mesmo com alterações de keys.

</Card>
