# 🚀 Arquitetura - Startup Scripts

Guia completo sobre a arquitetura e estrutura técnica do **sistema de startup** do servidor OTServ Canary. Entenda como o servidor se inicializa, como tabelas são carregadas, como funcionalidades são integradas e como estender o sistema.

---

## 🎯 Sobre o Sistema de Startup

<Card title="O que é?" icon="information">
O **sistema de startup** é a infraestrutura que **carrega e configura o servidor** no momento da inicialização. Ele organiza todos os dados (tabelas de items, portas, teleportes, etc) e funções que precisam estar disponíveis globalmente para scripts, quests e sistemas do jogo funcionarem corretamente.

O startup consegue ser a **espinha dorsal do servidor**, definindo estruturas de dados, constantes compartilhadas, e lógica de inicialização que todo resto do jogo depende.
</Card>

<Card title="Estrutura em 2 Fases" icon="layers">

O startup opera em **duas fases distintas**:

```
┌─────────────────────────────────────────┐
│         STARTUP INITIALIZATION          │
└────────────┬────────────────────────────┘
             │
    ┌────────┴────────┐
    │                 │
    ▼                 ▼
PHASE 1            PHASE 2
TABLES             FUNCTIONS
    │                 │
├─ load.lua        ├─ functions.lua
├─ chest.lua       ├─ load.lua (others)
├─ corpse.lua      └─ Integração com
├─ item.lua            scripts globais
├─ lever.lua
├─ doors (3x)
├─ teleports (2x)
├─ tiles (2x)
├─ writeable.lua
├─ storage_update.lua
└─ (16 tabelas)
```

**Fase 1 (Tables)**:
- Carrega todas as 16 tabelas de dados
- Order crítica: storage_keys_update DEVE ser último
- Disponibiliza dados globais para todo servidor

**Fase 2 (Functions)**:
- Carrega funções globais que usam as tabelas
- Registra action IDs, unique IDs, signs
- Inicializa estruturas que scripts precisam
</Card>

<Card title="Casos de Uso" icon="target">
Você trabalhará com o sistema de startup quando precisar:

- **Adicionar novo item/porta/teleporte**: Criar nova tabela entry
- **Estender funcionalidade global**: Adicionar função em `others/functions.lua`
- **Debug de inicialização**: Investigar por que item/porta não funciona
- **Otimizar carregamento**: Reorganizar ordem de carregar tabelas
- **Integrar novo sistema**: Adicionar nova tabela ou fase
- **Entender fluxo**: Rastrear como dados fluem através do startup
- **Customizar servidor**: Modificar constantes globais ou estruturas
</Card>

## 🎯 Orquestrador Principal

<Card title="startup.lua - Entry Point" icon="target">

### Arquivo: startup.lua

```lua
dofile('data/startup/tables/load.lua')      -- Phase 1
dofile('data/startup/others/load.lua')      -- Phase 2
```

**Comprimento**: 2 linhas  
**Complexidade**: Máxima (conceptualmente)  
**Criticidade**: ⚠️ CRÍTICA

### Por que tão simples?

A simplicidade é **propositalmente arquitetada**:

```
startup.lua (2 linhas)
      │
      ├─ Phase 1: Tabelas
      │  └─ tables/load.lua (16 dofiles)
      │
      └─ Phase 2: Funções
         └─ others/load.lua (1 dofile)
              └─ functions.lua (6 funções)
```

**Vantagem**:
- ✅ Entrada única e clara
- ✅ Separação de responsabilidades
- ✅ Fácil de manutenír
- ✅ Ordem garantida

### Ordem Imutável

```lua
-- ✅ CORRETO
dofile('tables/load.lua')    -- Tabelas PRIMEIRO
dofile('others/load.lua')    -- Funções DEPOIS

-- ❌ ERRADO - Scripts quebram
dofile('others/load.lua')    -- Funções tentam usar tabelas que não existem!
dofile('tables/load.lua')    -- Tabelas carregam tarde demais
```

### Por que esta ordem?

A ordem parece arbitrária, mas tem lógica:

1. **Chest/Corpse** primeiro - Containers básicos
2. **Create_item** cedo - Mapeia items simples
3. **Doors** (key, level, quest) - Sistema de portas
4. **Items** (daily, unmovable, item, lever) - Itens e botões
5. **Teleports** (item, magic) - Sistema de viagem
6. **Tiles** (pick, tile) - Sistema de tiles
7. **Writeable** - Conteúdo (menos crítico)
8. **storage_keys_update ÚLTIMO** - Migrations finais

## 🔐 Sistema de Storage Keys

<Card title="Rastreamento de Progresso" icon="key">

### O Problema: Dados de Player

```
Player progressão:
├─ Quest 1: Completado?
├─ Quest 2: Em que etapa?
├─ Quest 3: Quantas items coletadas?
└─ ... (centenas de questões)

Solução: Storage Keys
├─ Storage.Quest.Quest1.Completed
├─ Storage.Quest.Quest2.Progress
├─ Storage.Quest.Quest3.ItemCount
└─ ... (centenas de chaves)
```

### Migração de Dados (storage_keys_update.lua)

```lua
QuestKeysUpdate = {
    [0].latest = 4,  -- Versão atual
    
    [1] = {
        -- Mudanças da v0 → v1
        [STORAGE_QUEST_OLD_1] = STORAGE_QUEST_NEW_1,
    },
    
    [2] = {
        -- Mudanças da v1 → v2
        [STORAGE_QUEST_OLD_2] = STORAGE_QUEST_NEW_2,
    },
    
    [3] = {
        -- Mudanças da v2 → v3
        [STORAGE_QUEST_OLD_3] = STORAGE_QUEST_NEW_3,
    },
    
    [4] = {
        -- Mudanças da v3 → v4
        [STORAGE_QUEST_OLD_4] = STORAGE_QUEST_NEW_4,
    }
}
```

### Por que ÚLTIMO?

```
❌ Se carregar ANTES:
   - Scripts usam IDs antigos
   - Migrações não funcionam
   - Dados de player quebram

✅ Se carregar ÚLTIMO:
   - Todas as tabelas disponíveis
   - Migrações podem referenciar antigas E novas
   - Garantido funcionar corretamente
```

</Card>

## ⚠️ Ordem Crítica de Carregamento

<Card title="Lições de Ordem" icon="warning">

### Regra 1: Tabelas ANTES de Funções

```lua
-- ✅ CORRETO
dofile('tables/load.lua')    -- Cria ChestAction, ItemAction, etc
dofile('others/load.lua')    -- Funções usam essas tabelas

-- ❌ ERRADO
dofile('others/load.lua')    -- Tenta usar ChestAction... NÃO EXISTE!
dofile('tables/load.lua')    -- Chega tarde demais
```

**Resultado de erro:**
```
[ERROR] ChestAction is nil
[ERROR] Cannot iterate over nil value
[CRASH] Server startup failed
```

### Regra 2: storage_keys_update SEMPRE ÚLTIMO

```lua
-- ✅ CORRETO
-- ... todas outras 15 tabelas ...
dofile('storage_keys_update.lua')  -- ÚLTIMO
-- Agora todas as constantes Storage existem

-- ❌ ERRADO
dofile('storage_keys_update.lua')  -- Muito cedo
-- ... outros arquivos ...
dofile('item.lua')  -- Tenta referenciar Storage que não foi migrado
```

**Resultado de erro:**
```
[ERROR] Storage.Quest.XYZ is nil
[ERROR] Cannot reference undefined migration
[CRASH] Server startup failed
```

### Regra 3: Dependências dentro de Fase 1

Dentro de Phase 1, geralmente a ordem não importa **muito** (exceto storage_update), porque são só tabelas sem lógica de dependência.

```lua
-- ✅ Ordem "natural"
dofile('chest.lua')           -- Container basics
dofile('item.lua')            -- Items que podem ser em chests
dofile('door_*.lua')          -- Doors usam storage keys
dofile('lever.lua')           -- Buttons para portas
dofile('storage_keys_update') -- Migration system

-- ✅ TAMBÉM FUNCIONA
dofile('item.lua')           
dofile('chest.lua')          -- Ordem invertida ok
dofile('door_quest.lua')
dofile('storage_keys_update') -- Desde que seja ÚLTIMO
```

</Card>

## 🔧 Troubleshooting

<Card title="Problemas Comuns" icon="bug">

### Problema: Server não inicia

**Causa**: Erro em startup.lua  
**Debug**:
```
1. Checar console para mensagem de erro
2. Qual arquivo falha? (vê a linha do erro)
3. Sintaxe Lua há erro?
4. Arquivo existe no path?
```

**Solução**:
```lua
-- Adicionar debug
print("[Startup] Loading Phase 1...")
dofile('tables/load.lua')
print("[Startup] Phase 1 complete")

print("[Startup] Loading Phase 2...")
dofile('others/load.lua')
print("[Startup] Phase 2 complete")
```

### Problema: "ChestAction is nil"

**Causa**: Tentando usar tabela antes dela carregar  
**Solução**:
```lua
-- Verificar ordem em load.lua
-- Garantir que:
-- 1. chest.lua carrega
-- 2. Funções que usam ChestAction carregam DEPOIS
-- 3. Não fazer dofiles circulares
```

### Problema: Players perdem progresso ao atualizar

**Causa**: storage_keys_update.lua não está último  
**Solução**:
```lua
-- Em tables/load.lua, mover para ÚLTIMO
-- ... todas outras tabelas ...
dofile('storage_keys_update.lua')  -- AQUI - sempre por último
```

### Problema: Tabela que criei não funciona

**Causa**: Não foi adicionado em load.lua, ou não foi globalizado  
**Solução**:
```lua
-- 1. No arquivo da tabela
local myTable = {}
-- ... dados ...
_G.MyTable = myTable  -- ESSENCIAL

-- 2. Em tables/load.lua
dofile('data/startup/tables/mytable.lua')  -- Adicionar o dofile

-- 3. Reiniciar servidor
```

</Card>
