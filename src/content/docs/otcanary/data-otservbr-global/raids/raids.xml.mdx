## 🛠️ Configuração Mestre de Raids

Sistema **centralizado de carregamento de raids** com **61+ raids** distribuídas em **15 cidades**, cada uma com **intervalo customizável** e **margem de tempo**.

<Card title="Caminho Original" icon="document">
  `data-otservbr-global/raids/raids.xml`
</Card>

<Aside type="tip">
  Este arquivo atua como índice mestre: cada entrada `<raid>` referencia um arquivo XML individual localizado em subdiretórios por cidade. Intervalo define frequência de disparo, margem de tempo define variação aleatória.
</Aside>

---

## 📄 Visão Geral

O arquivo `raids.xml` centraliza o carregamento de todas as raids do servidor:

- **61 Raids Ativas**: Distribuídas em 15 cidades
- **1 Raid Comentada/Desativada**: Ferumbras (Liberty Bay)
- **Intervalo Customizável**: De 300ms até 6000ms
- **Margem Temporal**: Variação aleatória de 20-180 minutos
- **Estrutura Simples**: Apenas um elemento (`<raid>`) com atributos

---

## 🔧 Estrutura

### Estrutura Geral

```xml
<?xml version="1.0" encoding="UTF-8"?>
<raids>
    <!-- Raids organizadas por cidade (comentários) -->
    <raid name="Badger" file="abdendriel/badger.xml" 
          interval2="500" margin="60" />
</raids>
```

### Elemento: Raid

```xml
<raid name="Badger" file="abdendriel/badger.xml" 
      interval2="500" margin="60" />
```

**Atributos:**

<Card title="Atributos da Raid" icon="parameters">

| Atributo | Tipo | Descrição |
|----------|------|-----------|
| `name` | string | Nome identificador da raid (ex: "Badger", "Dragons") |
| `file` | path | Caminho relativo ao arquivo XML da raid (ex: "abdendriel/badger.xml") |
| `interval2` | number | Intervalo base em centisegundos (1 = 10ms), típico 300-6000 |
| `margin` | number | Margem de variação em minutos (aleatória, ±margem) |

</Card>

## 💡 Utilidade

O arquivo `raids.xml` serve como **índice mestre centralizado** que referencia todos os arquivos de raid individuais. Sua função principal é:

1. **Carregamento Dinâmico**: O engine C++ lê este arquivo ao inicializar e carrega todas as raids
2. **Controle de Intervalo**: Define com que frequência cada raid pode ocorrer (em centisegundos)
3. **Variação Temporal**: A margem permite variação aleatória no tempo de execução
4. **Organização**: Comentários agrupam raids por cidade para fácil navegação
5. **Ativação/Desativação**: Raids podem ser comentadas para desativar sem deletar

## 📄 Visão Geral do Código Resumo Executivo

O arquivo `raids.xml` implementa um sistema de **carregamento dinâmico de raids**:

- **Estrutura Simples**: Apenas elemento `<raid>` com 4 atributos
- **15 Cidades**: Raids distribuídas geograficamente
- **61 Raids Ativas**: Uma desativada (Ferumbras)
- **Intervalo Flexível**: De 300ms a 6000ms
- **Margem Aleatória**: Variação temporal de ±20 a ±170 minutos
- **Referências**: Cada raid aponta para arquivo XML individual em subdiretório

**Padrão de Intervalo:**
- **300-430 ms**: Raids rápidas (Mad Mage, Rottie2, Orc Backpack)
- **500 ms**: Padrão para maioria (42 raids)
- **1440 ms**: Raids longas/bosses (8 raids como Orshabaal, Ghazbaran)
- **6000 ms**: Ultra-longa (Zushuka)

### Sub-Elemento: Raid

```xml
<raid name="Badger" file="abdendriel/badger.xml" 
      interval2="500" margin="60" />
```

**Responsabilidade**: Define uma raid individual com seus parâmetros de temporização.

**Atributos Detalhados:**

| Atributo | Tipo | Faixa | Descrição | Exemplo |
|----------|------|-------|-----------|---------|
| `name` | string | N/A | Identificador único da raid | `"Dragons"` |
| `file` | path | relativo | Caminho do arquivo XML | `"abdendriel/dragons.xml"` |
| `interval2` | number | 300-6000 | Intervalo base em centisegundos | `500` = 5 segundos |
| `margin` | number | 20-180 | Margem de variação em minutos | `60` = ±60 minutos |

## Fluxo de Carregamento

1. **Leitura**: Engine lê arquivo XML no boot
2. **Parse**: Cada elemento `<raid>` é extraído
3. **Inicialização**: Raid é registrada com seus parâmetros
4. **Agendamento**: Timer calcula próxima execução (intervalo + margem aleatória)
5. **Execução**: Arquivo individual XML da raid é carregado e executado
