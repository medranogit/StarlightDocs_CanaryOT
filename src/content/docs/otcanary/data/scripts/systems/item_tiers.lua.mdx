## 📄 Visão Geral do Código - Resumo Executivo

O arquivo `item_tiers.lua` implementa sistema de classificação de items com 4 tiers de upgrade escalados exponencialmente, cada um com custos em gold (regular), items core necessários, e opcionalmente convergence fusion/transfer prices. É arquivo de configuração + registro que define 1D-10D tiers por classificação com estrutura aninhada [classificationId][tierId]. Os tiers C1-C3 são simples (regular + core), C4 é premium com até 10 tiers e convergence para fusion/transfer mechanics com preços massivos até 300 bilhões de gold. A implementação utiliza loop que itera classificações, cria Upgrades array, registra via Game.createItemClassification() factory. Padrão de escalação exponencial com alternativas de upgrade (fusion vs transfer).

## 🔧 Estrutura de Funcionalidades

```lua
-- 1. Tabela de Classificações de Items
local itemTierClassifications = {
    -- Classification 1: 1 tier (tier 0)
    [1] = {
        [1] = {
            regular = 25000,        -- gold price
            core = 1,               -- items needed
        },
    },
    
    -- Classification 2: 2 tiers (tier 0-1)
    [2] = {
        [1] = { regular = 750000, core = 1 },
        [2] = { regular = 5000000, core = 1 },
    },
    
    -- Classification 3: 3 tiers (tier 0-2)
    [3] = {
        [1] = { regular = 4000000, core = 1 },
        [2] = { regular = 10000000, core = 2 },
        [3] = { regular = 20000000, core = 3 },
    },
    
    -- Classification 4: 10 tiers (tier 0-9) + convergence
    [4] = {
        [1] = { 
            regular = 8000000, 
            core = 1,
            convergence = { 
                fusion = { price = 55000000 }, 
                transfer = { price = 65000000 } 
            },
        },
        [2] = { ... convergence ... },
        -- ... até tier 10
    },
}

-- 2. Loop de Registro
for classificationId, classificationTable in ipairs(itemTierClassifications) do
    local itemClassification = Game.createItemClassification(classificationId)
    local classification = {}
    
    -- Cria Upgrades array
    classification.Upgrades = {}
    for tierId, tierTable in ipairs(classificationTable) do
        table.insert(classification.Upgrades, {
            TierId = tierId,
            Core = tierTable.core,
            RegularPrice = tierTable.regular,
            ConvergenceFusionPrice = tierTable.convergence and tierTable.convergence.fusion.price or 0,
            ConvergenceTransferPrice = tierTable.convergence and tierTable.convergence.transfer.price or 0,
        })
    end
    
    -- Registra classificação
    itemClassification:register(classification)
end
```

## 🤖 Documentação das Funções

### **Game.createItemClassification(classificationId)**

**Descrição:** Engine function que cria nova instância de classificação de items.

**Parâmetros:**
- `classificationId` (number): ID único (1-4 neste arquivo)

**Retorno:**
- `ItemClassification`: Instância para configurar + registrar

---

### **itemClassification:register(classification)**

**Descrição:** Registra classificação com array de tiers no jogo.

**Parâmetros:**
- `classification` (table): Tabela com campo Upgrades (array de tiers)

**Estrutura de classification:**

```lua
{
    Upgrades = {
        {
            TierId = 1,
            Core = 1,
            RegularPrice = 8000000,
            ConvergenceFusionPrice = 55000000,
            ConvergenceTransferPrice = 65000000,
        },
        -- ... tiers adicionais
    }
}
```

---

### **Upgrades Array (dentro de classification)**

**Estrutura:**

| Campo | Tipo | Descrição |

| `ConvergenceFusionPrice` | number | Preço convergence fusion (0 se N/A) |

## 📌 Resumo

**Item Tiers** é sistema de classificação de items com 4 tiers escalados (C1: 1 tier, C2: 2 tiers, C3: 3 tiers, C4: 10 tiers), cada tier com regular price em gold + core items necessários + opcionalmente convergence fusion/transfer prices (alternadas). Classification 1-3 são simples (preços pequenos 25K-20M), C4 é premium exponencial até 300 bilhões de gold com 10 tiers e core escalada (1-85 items). Implementação registra via Game.createItemClassification() factory + loop automático. Padrão de escalação exponencial oferece progression end-game com múltiplas estratégias de upgrade (regular vs fusion vs transfer). Core items crescem simultaneamente com preços para balanceamento de custo.

A implementação segue padrão de factory registration, diferenciando-se por: (1) 4 classificações distintas, (2) 1-10 tiers por classificação, (3) escalação exponencial em C4, (4) convergence fusion/transfer alternativas, (5) preços até 300 bilhões, (6) core items escalonados paralelos.
