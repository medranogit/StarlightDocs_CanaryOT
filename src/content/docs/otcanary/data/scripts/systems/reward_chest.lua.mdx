## 📄 Visão Geral do Código - Resumo Executivo

O arquivo `reward_chest.lua` implementa sistema sofisticado de boss death rewards com scoring multi-participante, stamina checking, loot factoring, bosstiary scaling e gem atelier integration. É conjunto de 4 CreatureEvents (BossDeath, BossParticipation, LoginBossPlayer, BossThink) que trabalham juntos para track dano/healing, calcular contributions, gerar loot baseado em score e performance, aplicar bonuses para slots bosses e boosted boss, suportar offline players. O sistema normaliza scores (0-1) via contribuição relativa, escala loot inversamente por participantes (cubic root) e exponencialmente por performance, aplica bosstiary slot bonus (+X% por slot assignment), Gem Atelier generation, múltiplos rolls baseado em stamina. Implementação demonstra padrão avançado de scoring + factoring com offline support.

## 🎯 Padrões Identificados

### 1. **Padrão de Cálculo de Score Normalizado**

```lua
local score = (con.damageOut / totalDamageOut) + (con.damageIn / totalDamageIn) + (con.healing / totalHealing)
con.score = score / 3  -- Normaliza 0-1
```

Score = média de 3 contribuições percentuais (dano saíndo, dano entrando, cura).

### 2. **Padrão de Loot Factor Escalado**

```lua
local lootFactor = 1
lootFactor = lootFactor / participants ^ (1 / 3)  -- Scaledown por participants
lootFactor = lootFactor * (1 + lootFactor) ^ (con.score / expectedScore)  -- Scale up por performance
```

Reduz loot se muitos participantes (cubic root), aumenta se player outperforma expected score exponencialmente.

### 3. **Padrão de Bosstiary Slot Bonus**

```lua
local rolls = 1
if isBoss and monsterType:raceId() ~= 0 then
    if monsterType:raceId() == player:getSlotBossId(1) then
        rolls = rolls + player:getBossBonus(1) / 100.0
    elseif monsterType:raceId() == player:getSlotBossId(2) then
        rolls = rolls + player:getBossBonus(2) / 100.0
    else
        rolls = rolls + configManager.getNumber(configKeys.BOOSTED_BOSS_LOOT_BONUS) / 100
    end
end
```

Bonus rolls baseado em slot1, slot2, ou boosted assignment.

### 4. **Padrão de Roll Probabilístico**

```lua
if math.random(0, 100) < (rolls % 1) * 100 then
    rolls = math.ceil(rolls)
else
    rolls = math.floor(rolls)
end
```

Se rolls tem fração (e.g., 1.7), 70% chance de ceil, 30% chance de floor.

### 5. **Padrão de Offline Player Support**

```lua
if con.player then
    -- Online player: send message
    player:sendTextMessage(MESSAGE_LOOT, lootMessage)
else
    -- Offline player: create and save
    player = Game.getOfflinePlayer(con.guid)
    player:save()
end
```

Verifica se online, senão cria offline player e salva.

## 🤖 Documentação das Funções

### **BossDeath Event Handler**

**Descrição:** Event principal que calcula scores, determina loot factor, gera rewards, aplica bosstiary bonus.

**Parâmetros:**
- `creature` (Creature): Boss que morreu
- `corpse` (Container): Container corpse
- `killer` (Creature): Killer (não usado)
- `mostDamageKiller` (Creature): Maior dano dealer
- `lastHitUnjustified` (boolean): Hit unjustified
- `mostDamageUnjustified` (boolean): Damage unjustified

**Fluxo:**

1. **Validações**:
   - Rejeita summons (`creature:getMaster()`)
   - Rejeita players
   - Valida boss via `monsterType:isRewardBoss()`

2. **Corpse Setup**:
   - Se corpse não é container: cria novo bag
   - `corpse:registerReward()` para storage reward ID

3. **Obtenção de Stats**:
   - `damageMap = creature:getDamageMap()` (total damage por player durante lifetime)
   - `info = _G.GlobalBosses[bossId]` (stats específicos de boss)
   - Combina ambas fontes

4. **Cálculo de Scores**:
   - Agregação: damageOut, damageIn, healing
   - Normalização: (prop_out + prop_in + prop_healing) / 3 = score (0-1)
   - Sorting por score descending

5. **Determinação de Participantes**:
   - Conta scores não-zero (participantes ativos)

6. **Loop de Distribuição de Loot**:
   - Para cada score:
     - `lootFactor = 1 / participants^(1/3) * (1 + lootFactor)^(score/expectedScore)`
     - Determina rolls com bosstiary bonus
     - Determina fração via `math.random()`
     - Gera Gem Atelier loot via `creature:generateGemAtelierLoot()`
     - Chama `monsterType:getBossReward(lootFactor, isFirst, isExtra, playerLoot, player)` por cada roll
     - Adiciona itens ao reward via `reward:addRewardBossItems(playerLoot)`

7. **Mensagens**:
   - Online: Colored message (se client > 1200) com lista de items
   - Boss bonus indicator se rolls > 1
   - Stamina check (comentado, futuro)
   - Offline: Auto-save via `player:save()`

8. **Cleanup**:
   - `_G.GlobalBosses[bossId] = nil` (libera memory)

---

### **BossParticipation Event Handler**

**Descrição:** Tracks dano/healing durante boss fight em onHealthChange.

**Parâmetros:**
- `creature` (Creature): Boss
- `attacker` (Creature): Atacador
- `primaryDamage` (number): Dano primário
- `primaryType` (constant): Tipo de dano
- `secondaryDamage` (number): Dano secundário
- `secondaryType` (constant): Tipo secundário

**Fluxo:**

1. **Validações**:
   - Se GlobalBosses vazio: return (skip)
   - Se creature/attacker nil: return (skip)
   - Se creature não em boss fight: return (skip)

2. **Tracking de Dano Saindo**:
   - Se attacker é boss (stats.bossId == attackerId):
     - `stats.damageIn += primaryDamage`

3. **Tracking de Cura**:
   - Se primaryType é HEALING e attacker é player e não é caster:
     - Lookup/cria healerStats para attacker guid
     - `healerStats.healing += primaryDamage`

4. **Retorno**:
   - Propagação de valores originais (no modification)

## 📌 Resumo

Reward Chest é sistema sofisticado de boss death rewards com 4 CreatureEvents integrados: BossDeath calc rewards, BossParticipation track dano/cura, LoginBossPlayer register, BossThink periodic reset. Implementação calcula contribution scores normalizados entre 0 e 1 via média de damageOut %, damageIn %, healing %, escala loot inversamente por participants (cubic root) e exponencialmente por performance relativa. Aplica bosstiary bonuses para slot1/slot2/boosted assignments, determina rolls probabilisticamente, gera Gem Atelier loot, suporta online/offline players com stamina checking. GlobalBosses tracks bossId com guid para stats persistentemente. Padrão avançado de scoring e scaling demonstra sistema end-game complexo com múltiplos fatores de balanceamento.

A implementação segue padrão avançado de event-driven reward distribution, diferenciando-se por: 4 events integrados, normalized 0 a 1 scoring, cubic root scale factor, exponential performance multiplier, bosstiary bonus application, probabilistic rolls, online/offline dual support, Gem Atelier integration.
