## Padrões & Implementação

### 1. Padrão de Hook/Callback Extensível

Arquivo que serve apenas como **ponto de injeção** sem lógica própria:

```lua
-- Padrão A: Hook vazio (como está)
function callback.eventHook(param1, param2)
    return RETURNVALUE_NOERROR
end

-- Padrão B: Hook com logging
function callback.eventHook(param1, param2)
    logger.info("Event triggered: {} at {}", param1, param2)
    return RETURNVALUE_NOERROR
end

-- Padrão C: Hook com early guard
function callback.eventHook(param1, param2)
    if not isValid(param1) then
        return RETURNVALUE_NOTPOSSIBLE
    end
    return RETURNVALUE_NOERROR
end
```

**Vantagens**:
- Desvínculo completo (não quebra ao não ter lógica)
- Pronto para injetar complexidade quando necessário
- Sem overhead (return imediato)

**Onde Usar**:
- Pre-hooks (antes de ação ocorrer)
- Validação de pre-condições
- Logging/telemetria
- Feature flags que podem ativar/desativar

### 2. Padrão de Return Code (RETURNVALUE_*)

Sistema de códigos de retorno para sinalizar sucesso/falha:

```lua
-- Sucesso (permite ação)
return RETURNVALUE_NOERROR

-- Falhas bloqueáveis
return RETURNVALUE_NOTPOSSIBLE       -- Genericamente não possível
return RETURNVALUE_YOUARENOTABLE     -- Criatura não pode fazer
return RETURNVALUE_NEEDLEVELONEHVL   -- Falta habilidade
return RETURNVALUE_NEEDPROFESSIONVL  -- Falta profissão
```

**Convenção na Engine**:
- Retorno `nil` ou sem return → interpretado como falha
- Retorno `true` → siglas para `RETURNVALUE_NOERROR`
- Retorno falsy (`false`, `0`) → falha

**Prática Recomendada**:
```lua
-- ✅ Correto: usar constante
return RETURNVALUE_NOERROR

-- ⚠️ Ambíguo: usar boolean
return true  -- Funciona mas menos claro

-- ❌ Errado: sem return
-- Engine interpreta como falha
```
