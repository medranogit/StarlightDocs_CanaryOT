## 📄 Visão Geral do Código

### Resumo Executivo

O módulo `on_disband.lua` implementa **hazard cleanup trigger** que intercepta `partyOnDisband` disparado quando party é dissolvida. Coleta membros (members + leader), prepara array de IDs filtrando por `playerId` (variável não definida - bug?), agenda async callback com 100ms delay que itera IDs e chama `member:updateHazard()` para cada player. Padrão de **deferred async update** deixando room para outras operações antes recalcular hazard (evita short circuit).

### Arquitetura de Componentes

```
Party Disband Handler
│
├─ MEMBER COLLECTION (4 operações)
│  ├── members = party:getMembers()
│  ├── Adiciona leader: table.insert(members, party:getLeader())
│  │
│  ├─ MEMBER FILTERING (1 loop)
│  │  ├── for each member:
│  │  │  └── if member:getId() ~= playerId  ← UNDEFINED VARIABLE
│  │  │     └── memberIds[] += member:getId()
│  │
│  └─ Result: memberIds array (filtered)
│
├─ ASYNC SCHEDULING (2 operações)
│  ├── addEvent(function, 100)  ← 100ms delay
│  │
│  └─ Event Callback:
│     ├── for each memberId in memberIds:
│     │  ├── member = Player(memberId)
│     │  └── if member:
│     │     └── member:updateHazard()
│
└─ COMPLETION (1)
   └── return true
```

## Detalhes da Função Global

### `callback.partyOnDisband(party)`

**Tipo**: EventCallback hook

**Descrição**: Função disparada quando party é dissolvida. Prepara hazard update para todos membros, agenda async callback com delay.

**Parâmetros**:

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `party` | userdata | Party que está sendo dissolvida |

**Retorna**: 
- `true` (sempre, callback completa com sucesso)

**Algoritmo**:

```lua
function callback.partyOnDisband(party)
    -- 1. COLLECT MEMBERS
    local members = party:getMembers()
    table.insert(members, party:getLeader())

    -- 2. PREPARE MEMBER IDs (filtered)
    local memberIds = {}
    for _, member in ipairs(members) do
        -- Filter out playerId (???)
        if member:getId() ~= playerId then
            table.insert(memberIds, member:getId())
        end
    end

    -- 3. SCHEDULE ASYNC HAZARD UPDATE
    addEvent(function()
        -- Callback body executes 100ms later
        for _, memberId in ipairs(memberIds) do
            local member = Player(memberId)
            if member then
                -- Update hazard state (now that party disbanded)
                member:updateHazard()
            end
        end
    end, 100)  -- 100ms delay

    -- 4. RETURN
    return true
end
```

**Características Principais**:

| Característica | Valor | Notas |
|---|---|---|
| Timing | Async deferred | 100ms delay |
| Members | Todos exceto filtered | Filtra por playerId (undefined) |
| Action | updateHazard call | Cada member |
| Return | true | Sempre sucesso |
| Closure | Captura memberIds | Persistido no closure |

## Padrões & Implementação

### 1. Padrão de Async Deferred Execution

Usar `addEvent()` para agendar callback com delay:

```lua
-- ❌ BLOCKING: Executa imediatamente
for _, memberId in ipairs(memberIds) do
    Player(memberId):updateHazard()  -- Pode ser lento
end

-- ✅ NON-BLOCKING: Defer com delay
addEvent(function()
    for _, memberId in ipairs(memberIds) do
        Player(memberId):updateHazard()
    end
end, 100)  -- 100ms delay
```

**Benefício**:
- Party disband callback retorna imediatamente
- Hazard update ocorre depois (não bloqueia)
- Outro event loop processament continue
- 100ms delay deixa buffer para cleanup

### 2. Padrão de Closure Capture

Capturar variáveis local no closure de addEvent:

```lua
local memberIds = {}  -- Coletado aqui
for _, member in ipairs(members) do
    table.insert(memberIds, member:getId())
end

-- Closure captura memberIds
addEvent(function()
    -- memberIds ainda acessível 100ms depois
    for _, memberId in ipairs(memberIds) do
        -- ...
    end
end, 100)
```

**Vantagem**:
- memberIds persistido no closure
- Não precisa global ou passar parâmetro
- Automatic garbage collection

### 3. Padrão de Nil Guard with Player Constructor

Defender contra player offline/deleted:

```lua
for _, memberId in ipairs(memberIds) do
    local member = Player(memberId)
    if member then
        member:updateHazard()
    end
end
```

**Razão**:
- Player pode ter logout entre disband e callback
- `Player(id)` pode retornar nil se offline
- Guard previne `nil:updateHazard()` crash
