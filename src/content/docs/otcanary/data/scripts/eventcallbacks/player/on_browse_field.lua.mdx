## 💡 Tip

<Aside type="tip">
**Fluxo de Visualização de Campo (Browse Field)**

Quando um jogador inspeciona uma área/campo:

1. **Trigger:** playerOnBrowseField é disparado
2. **Validação:** Callback retorna booleano (true = permitir, false = bloquear)
3. **Ação:** Se retorna true, visualização é permitida; se false, ação é cancelada

**Exemplo Teórico - Implementação Completa:**
```lua
function callback.playerOnBrowseField(player, position)
    local tile = Tile(position)
    if not tile then return false end
    
    -- Exemplo: bloquear visualização em áreas PvP
    if configManager.getBoolean("BLOCK_BROWSE_PVPAREA") then
        return false
    end
    
    return true  -- Permitir visualização
end
```

**Nota:** Atualmente este arquivo é apenas um stub. Para estender, adicionar lógica de validação conforme necessário.
</Aside>

## 🎯 Padrões & Boas Práticas

### Padrão 1: Callback Passthrough (Stub)

**Técnica:** Implementar callback como stub que sempre retorna true.

```lua
function callback.playerOnBrowseField(player, position)

end
```

**Vantagem:** Permite future extension sem breaking changes. Baseline permissiva.

**Aplicação:** Callbacks simples que podem necessitar validação adicional (permissões, restrições, logging).

### Padrão 2: Boolean Return for Permission

**Técnica:** Usar booleano para controlar permissão de ação.

```lua
-- Exemplo de extensão potencial:
if not player:getGroup():getAccess() then
    return false  -- Bloqueia non-admins
end
return true  -- Permite admins
```

**Vantagem:** Simples, direto, sem exceções. Permite/bloqueia decisão na wrapper.

**Aplicação:** Qualquer callback de validação.
