## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `on_remove_count.lua` implementa o callback de rastreamento de remoção. Quando um item é removido do inventário:

- **Captura evento de remoção** automaticamente
- **Extrai ID do item** para identificação
- **Notifica sistema de waste** para estatísticas

### Arquitetura

O script usa um padrão simples de **event propagation**:

```
playerOnRemoveCount (entrada)
  ├─ item:getId()
  └─ player:sendWaste(itemId)
```

### Fluxo Lógico Resumido

| Entrada | Processamento | Saída |
|---------|---------------|-------|
| `player, item` | Extrai item ID | Notifica waste system |

---

## 🔧 Estrutura de Funcionalidades

### Função Principal (Callback)

#### **playerOnRemoveCount(player, item)**

```lua
function callback.playerOnRemoveCount(player, item)
	player:sendWaste(item:getId())
end
```

**Propósito:** Entry point do callback. Notifica jogador e sistema quando item é removido.

**Fluxo de Execução:**

1. **Trigger:** Evento disparado quando item é removido
2. **Extração:** Obtém ID do item via `item:getId()`
3. **Notificação:** Chama `player:sendWaste(itemId)` para rastrear

**Parâmetros:**
- `player` - Player proprietário do item
- `item` - Item object sendo removido

**Sem retorno** - Callback é void (apenas notifica)

## 🎯 Padrões & Boas Práticas

### Padrão 1: Event Propagation

**Técnica:** Propagate eventos simples para subsistemas superiores.

```lua
function callback.playerOnRemoveCount(player, item)
	player:sendWaste(item:getId())  -- Simples propagação
end
```

**Vantagem:** Desacoplado. Sistema de waste é independente. Fácil adicionar handlers.

**Aplicação:** Qualquer evento que necessite notificação a subsistemas.

---

### Padrão 2: ID-Based Tracking

**Técnica:** Usar item ID para rastreamento invés de objeto inteiro.

```lua
player:sendWaste(item:getId())  -- ID é identificador único e estável
```

**Vantagem:** IDs são simples, estáveis, e permitem lookup em qualquer contexto.

**Aplicação:** Rastreamento de itens para estatísticas, logging.

---

### Padrão 3: Callback Delegation

**Técnica:** Delegar responsabilidade de processamento para método de jogador.

```lua
-- on_remove_count.lua - apenas notifica
player:sendWaste(item:getId())

-- Player:sendWaste() - lida com lógica complexa
-- Pode implementar: logging, statistics, auction house cleanup, etc
```

**Vantagem:** Desacoplamento. Lógica de waste focalizada em um lugar.

**Aplicação:** Arch pattern quando múltiplos callbacks precisam notificar.
