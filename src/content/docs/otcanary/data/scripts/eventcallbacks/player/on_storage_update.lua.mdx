## 💡 Tip

<Aside type="tip">
**Fluxo de Atualização de Storage (Storage Update)**

Quando qualquer valor no storage do jogador é alterado:

1. **Trigger:** `player:kv():set(key, value)` é executado
2. **Callback:** playerOnStorageUpdate é disparado automaticamente
3. **Processamento:** Callback pode reagir à mudança
4. **Ação:** Delega para player:updateStorage() para processamento

**Exemplo de Uso - Rastreamento de Eventos:**
```lua
-- Em outro script:
player:kv():set("familiar-summon-time", os.time() + 10800)

-- on_storage_update.lua:
playerOnStorageUpdate(player, "familiar-summon-time", os.time() + 10800, 0, frameTime)
  └─ player:updateStorage("familiar-summon-time", ..., frameTime)

-- Usa: Atualizar UI, notificações, cascata de efeitos
```

**Chaves Comuns de Storage:**
- `familiar-summon-time` - Timestamp de summon de familiar
- `hazard-status` - Status do sistema hazard
- `prey-status` - Status de prey loot
- `custom-quests` - Dados de quests customizadas
</Aside>

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `on_storage_update.lua` implementa o callback de notificação de storage. Quando um valor é alterado no key-value storage do jogador:

- **Captura evento de mudança** automaticamente
- **Passa contexto completo** (chave, novo valor, valor antigo, frame time)
- **Delega processamento** para player:updateStorage() para ações específicas

### Arquitetura

O script usa um padrão simples de **change notification**:

```
playerOnStorageUpdate (entrada)
  ├─ Captura: key, value, oldValue, currentFrameTime
  └─ player:updateStorage(key, value, oldValue, currentFrameTime)
```

### Fluxo Lógico Resumido

| Entrada | Processamento | Saída |
|---------|---------------|-------|
| `key, value, oldValue, frameTime` | Notifica mudança | Delega updateStorage |

## 🔧 Estrutura de Funcionalidades

### Função Principal (Callback)

#### **playerOnStorageUpdate(player, key, value, oldValue, currentFrameTime)**

```lua
function callback.playerOnStorageUpdate(player, key, value, oldValue, currentFrameTime)
	player:updateStorage(key, value, oldValue, currentFrameTime)
end
```

**Propósito:** Entry point do callback. Processa mudanças no key-value storage.

**Fluxo de Execução:**

1. **Trigger:** Qualquer script executa `player:kv():set(key, value)`
2. **Callback:** playerOnStorageUpdate é disparado automaticamente
3. **Delegação:** Passa todos os parâmetros para player:updateStorage()
4. **Processamento:** updateStorage() realiza ações necessárias

**Parâmetros:**
- `player` - Player cujo storage foi atualizado
- `key` - Chave (string) que foi alterada
- `value` - Novo valor armazenado
- `oldValue` - Valor anterior (antes da mudança)
- `currentFrameTime` - Timestamp do frame (para sync temporal)

**Sem retorno** - Callback é void (apenas delega)

## 🎯 Padrões & Boas Práticas

### Padrão 1: Change Notification Callback

**Técnica:** Callback disparado automaticamente quando mudança ocorre.

```lua
function callback.playerOnStorageUpdate(player, key, value, oldValue, currentFrameTime)
	player:updateStorage(key, value, oldValue, currentFrameTime)
end
```

**Vantagem:** Automático, não necessita polling. Sempre sincronizado.

**Aplicação:** Qualquer sistema que necessite reagir a mudanças (events, triggers, cascatas).

---

### Padrão 2: Value Delta Tracking

**Técnica:** Passar valor antigo e novo para detectar tipo de mudança.

```lua
-- Callback recebe:
-- oldValue: 0, value: 10800 → Valor foi criado/incrementado
-- oldValue: 10800, value: 21600 → Valor foi incrementado
-- oldValue: 10800, value: 0 → Valor foi zerado
```

**Vantagem:** Permite lógica condicional. Detecta direção de mudança.

**Aplicação:** Incrementos, contadores, flags de estado.

---

### Padrão 3: Frame Time Synchronization

**Técnica:** Passar timestamp de frame para sincronizar com game loop.

```lua
player:updateStorage(key, value, oldValue, currentFrameTime)
```

**Vantagem:** Garante timing sincronizado. Evita race conditions.

**Aplicação:** Sistemas temporais (buffs, cooldowns, summons, eventos).

## ⚙️ Fluxo de Operação

### Cenário 1: Familiar summon time atualizado

```
[Outro script]:
player:kv():set("familiar-summon-time", os.time() + 10800)

playerOnStorageUpdate(player, "familiar-summon-time", 1708369200, 0, frameTime)
  ├─ Detecta: chave = "familiar-summon-time", novo = 1708369200
  ├─ player:updateStorage("familiar-summon-time", 1708369200, 0, frameTime)
  └─ [updateStorage action]
     ├─ Scheduled: Despawn de familiar em 10800s
     ├─ UI Update: Mostra timer de familiar
     └─ Notify: Player vê summon de familiar
```

**Resultado:** Familiar é summoned com timer de 3 horas
