## 💡 Tip

<Aside type="tip">
**Propósito de Default Callbacks (Fallback Handlers)**

Em um sistema de eventos, é necessário ter handlers padrão:

**Sem defaults:**
```lua
-- MoveEvent sem handler definido
moveEvent:onStepIn(nil)  -- X Crash: handler inválido
```

**Com defaults:**
```lua
-- MoveEvent sem handler customizado
moveEvent:onStepIn()     -- ✓ Usa defaultStepIn (permite ação)
```

**Quando Usado:**
```
MoveEvent("tile_123") 
  ├─ Não tem onStepIn() definido
  └─ Usa defaultStepIn() ← Allows movement
```

**Comportamento Padrão:**
- Todos retornam `true` (permitir ação)
- Sem efeitos colaterais (passthrough)
- Serve como base para herança/override
</Aside>

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `defaults_move_event.lua` fornece **callbacks fallback** para sistema de movimento:

- **Step In/Out:** Quando criatura entra/sai de tile
- **Add/Remove Item:** Quando item é adicionado/removido de tile
- **Equip/Deequip:** Quando item é equipado/desequipado por jogador

### Arquitetura

Script usa padrão de **default handler stubs**:

```lua
function defaultStepIn(...) return true end      -- Permite tudo
function defaultStepOut(...) return true end     -- Permite tudo
function defaultAddItem(...) return true end     -- Permite tudo
-- ... etc
```

Cada função é global e pode ser referenciada quando nenhum handler customizado existe.

### Fluxo Lógico Resumido

| Evento | Handler Padrão | Comportamento | Retorno |
|--------|----------------|---------------|---------|
| **Criatura pisa em tile** | `defaultStepIn()` | Permite | `true` |
| **Criatura sai de tile** | `defaultStepOut()` | Permite | `true` |
| **Item adicionado a tile** | `defaultAddItem()` | Permite | `true` |
| **Item removido de tile** | `defaultRemoveItem()` | Permite | `true` |
| **Item equipado** | `defaultEquip()` | Permite | `true` |
| **Item desequipado** | `defaultDeEquip()` | Permite | `true` |

## 🔧 Estrutura de Funcionalidades

### Função 1: defaultStepIn()

```lua
function defaultStepIn(creature, item, position, fromPosition)
	return true
end
```

**Propósito:** Callback padrão quando criatura pisa em tile.

**Parâmetros:**
- `creature` - Criatura que pisou (Player ou Creature)
- `item` - Item no tile (tile object)
- `position` - Posição atual (Position table: x, y, z)
- `fromPosition` - Posição anterior (Position table)

**Comportamento:** Sempre retorna `true` (permite movement)

**Quando Chamado:**
```
Creature moves to tile
  ├─ MoveEvent.onStepIn() definido?
  ├─ Sim → Executa customizado
  └─ Não → Executa defaultStepIn() ✓
```

**Casos de Uso Real:**
```lua
-- Customizado com efeito
local event = MoveEvent(250)  -- floor ID
function event.onStepIn(creature, item, pos, fromPos)
	creature:say("Você pisou em um tile especial!")
	return true
end

-- Sem customização
local event2 = MoveEvent(100)  -- floor padrão
-- Usa defaultStepIn() automaticamente
```

```
  ├─ defaultStepOut() (sai do tile anterior)
```

**Exemplo Customizado:**

```lua
	return true
end
```

**Parâmetros:**

```
Jogador move item
  ├─ Pickup item A
  ├─ Drop em tile B
  └─ MoveEvent.onAddItem() dispara
     ├─ Custom handler?
     └─ Senão: defaultAddItem() ✓
```

**Exemplo Customizado:**
```lua
local teleportTile = MoveEvent(100)  -- tile ID
function teleportTile.onAddItem(moveItem, tileItem, pos)
	if moveItem:getId() == 1234 then  -- Key ID
		-- Teleporta jogador ao colocar chave
		moveItem:getParent():remove(moveItem)
		return false  -- Não permite drop normal
	end
	return true
end
```

### Função 5: defaultEquip()

```lua
function defaultEquip(player, item, slot, isCheck)
	return true
end
```

**Propósito:** Callback padrão quando jogador equipa item.

**Parâmetros:**
- `player` - Jogador equipando
- `item` - Item sendo equipado
- `slot` - Slot destino (CONST_SLOT_*)
- `isCheck` - Boolean se é apenas verificação (sim/não)

**Comportamento:** Sempre retorna `true` (permite equip)

**Retorno Significado:**
- `true` - Permite equipar
- `false` - Nega equipamento

**Quando Chamado:**
```
Jogador clica para equipar
  ├─ isCheck=true → Apenas verifica se permitido
  │  └─ Se true → Procede com equip
  └─ isCheck=false → Equipa (efeitos aplicados)
```

**Exemplo Customizado:**
```lua
local cursedSword = 1234
local event = MoveEvent()
function event.onEquip(player, item, slot, isCheck)
	if item:getId() == cursedSword then
		if isCheck then
			return true  -- Permite
		else
			-- Aplica curse ao jogador
			player:addCondition(curseCondition)
		end
	end
	return true
end
```

## 🎯 Padrões & Boas Práticas

### Padrão 1: Fallback Handler Pattern

**Técnica:** Fornecer implementação padrão que permite tudo quando não há customização.

```lua
-- Sem fallback: X Erro se handler não definido
event.onStepIn = nil  -- Crash ao disparar

-- Com fallback: Sistema checa
if handler then
	handler()
else
	defaultStepIn()  -- ✓ Seguro
end
```

**Vantagem:**
- Robustez: nunca há crash por handler faltante
- Simplicidade: não precisa definir handler mínimo
- Flexibilidade: pode ser override seletivamente

**Aplicação:** Qualquer sistema de callbacks.

---

### Padrão 2: Early Returns para Validation

**Técnica:** Usar padrão `isCheck` para separar validação de execução.

```lua
function defaultEquip(player, item, slot, isCheck)
	if item:getLevel() > player:getLevel() then
		return false  -- Válido para ambas fases
	end
	if not isCheck then
		-- Apenas executa efeitos aqui
		item:onEquipped(player)
	end
	return true
end
```

**Vantagem:**
- Separação clara: validação vs side-effects
- Performance: check sem side-effects
- Segurança: evita aplicar efeito duas vezes

**Aplicação:** Validação com side-effects.

---

### Padrão 3: True Default (Allow-All)

**Técnica:** Handlers padrão sempre retornam `true` (mais permissivo).

```lua
function defaultStepIn(...) return true end
```

**Vantagem:**
- Seguro por padrão: não bloqueia gameplay
- Explícito para negar: scripts devem retornar `false`
- Evita surpresas: customização opta-in

**Aplicação:** Qualquer sistema de permissões de jogador.
