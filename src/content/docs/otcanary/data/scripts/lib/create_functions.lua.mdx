## 💡 Tip

<Aside type="tip">
**Propósito de Create Functions (Auto-Generated Accessors)**

Em linguagens como Lua com engine C++, propriedades nativas não têm getters/setters automáticos. Esta biblioteca resolve isso:

**Sem createFunctions:**
```lua
-- Impossível acessar propriedade diretamente
monsterType->getName()  -- X Erro: sem suporte Lua
```

**Com createFunctions:**
```lua
-- Auto-gerado: getter
local name = monsterType:getName()

-- Auto-gerado: setter
monsterType:setName("New Name")
```

**Como Funciona:**
```
createFunctions(MonsterType)
  ├─ Itera propriedades de MonsterType (C++)
  ├─ Para cada prop: cria método get*Prop()
  ├─ Para cada prop: cria método set*Prop() se mutável
  └─ Adiciona à metatable do tipo
```

**Resultado:** Interface consistente para todos tipos nativos
</Aside>

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `create_functions.lua` é um **setup bootstrap** que gera automaticamente:

- **Getter functions:** Para ler propriedades de tipos nativos
- **Setter functions:** Para modificar propriedades de tipos nativos
- **Nomeação idiomática:** Segue padrões Lua (`get*`, `set*`)

### Arquitetura

Script usa padrão de **declarative initialization**:

```lua
createFunctions(Type1)  -- Gera getters/setters para Type1
createFunctions(Type2)  -- Gera getters/setters para Type2
createFunctions(Type3)  -- Gera getters/setters para Type3
```

Cada chamada modifica a metatable do tipo nativo, adicionando novos métodos.

### Fluxo Lógico Resumido

| Tipo | Ação | Resultado |
|------|------|-----------|
| **MonsterType** | `createFunctions()` | Métodos `getName()`, `setName()`, etc |
| **NpcType** | `createFunctions()` | Métodos `getName()`, `setName()`, etc |
| **Spell** | `createFunctions()` | Métodos `getName()`, `setCastSound()`, etc |

## 🔧 Estrutura de Funcionalidades

### Operação 1: createFunctions(MonsterType)

```lua
createFunctions(MonsterType)
```

**Propósito:** Gera getters/setters para MonsterType (tipos de monstros).

**Efeito:**

- Para cada propriedade de MonsterType (ex: `name`, `health`, `experience`):
  - Cria método `getPropertyName()` - readonly accessor
  - Cria método `setPropertyName()` se mutável - write accessor

**Exemplo de Métodos Gerados:**
```lua
local monster = MonsterType("Minotaur")
monster:getName()              -- Getter para name
monster:getHealth()            -- Getter para health
monster:getExperience()        -- Getter para experience
monster:setHealth(200)         -- Setter para health (se mutável)
```

**Propriedades Típicas:**
- `name` - Nome do tipo
- `description` - Descrição
- `health` - HP base
- `experience` - XP ao matar
- `corpseId` - ID do corpse
- `speed` - Velocidade de movimento
- `outfit` - Aparência visual

---

### Operação 2: createFunctions(NpcType)

```lua
createFunctions(NpcType)
```

**Propósito:** Gera getters/setters para NpcType (tipos de NPCs).

**Efeito:** Similar ao MonsterType, mas com propriedades específicas de NPC.

**Exemplo de Métodos Gerados:**
```lua
local npc = NpcType("Elane")
npc:getName()                  -- Getter para name
npc:setGreeting("Greetings")   -- Setter para greeting text
npc:getFarewell("Farewell")    -- Getter para farewell text
```

**Propriedades Típicas:**
- `name` - Nome do NPC
- `greeting` - Texto de saudação
- `farewell` - Texto de despedida
- `outfit` - Aparência visual
- `speed` - Velocidade de movimento

---

### Operação 3: createFunctions(Spell)

```lua
createFunctions(Spell)
```

**Propósito:** Gera getters/setters para Spell (tipos de magias).

**Efeito:** Gera accessors para propriedades de feitiço.

**Exemplo de Métodos Gerados:**
```lua
local spell = Spell("Fireball")
spell:getName()                -- Getter para name
spell:getManaCost()            -- Getter para mana necessário
spell:setCastSound(123)        -- Setter para som de cast
spell:getLevel()               -- Getter para level requerido
```

**Propriedades Típicas:**
- `name` - Nome da spell
- `manaCost` - Mana requerido
- `level` - Level mínimo
- `castSound` - ID do som de cast
- `effect` - Efeito visual (magic effect ID)

## 🎯 Padrões & Boas Práticas

### Padrão 1: Reflection-Based Accessor Generation

**Técnica:** Usar reflexão/introspection para gerar métodos automaticamente.

```lua
-- Sem createFunctions:
monsterType1:getName()  -- Possível (nativo)
-- E dezenas de outras chamadas nativas

-- Com createFunctions:
-- Todas as propriedades têm getters/setters consistentes
monsterType:getName()
monsterType:setName()
```

**Vantagem:**
- Evita código boilerplate (DRY principle)
- Interface consistente para todos tipos
- Fácil manutenção (novo property → novo accessor automático)

**Aplicação:** Qualquer binding C++/Lua com múltiplas propriedades.

---

### Padrão 2: Declarative Type Setup

**Técnica:** Listar tipos a serem processados de forma clara.

```lua
createFunctions(MonsterType)
createFunctions(NpcType)
createFunctions(Spell)
```

**Vantagem:**
- Explícito: claro quais tipos foram modificados
- Manutenível: adicionar tipo é trivial
- Sem magia: setup visível

**Aplicação:** Inicialização de tipos nativos em bindings.

---

### Padrão 3: Bootstrap Timing

**Técnica:** Executar setup no início do Lua boot, antes de scripts de jogo.

```
core.lua (setup scripts)
  ├─ create_functions.lua ← Executa AQUI (tipos pronto para usar)
  │  └─ Popula metatables
  └─ game scripts
     └─ Usam tipos com getters/setters
```

**Vantagem:**
- Tipos estão prontos quando scripts de jogo rodam
- Evita race conditions (setup antes de uso)
- Centralizado (um lugar para manutenção)

**Aplicação:** Inicialização do engine Lua.

## 📈 Impacto de Performance

### Memory Overhead
- **Baixo:** Uma cópia de método por tipo (não por instância)
- Metatables são compartilhadas

### Execution Speed
- **Setup (uma vez):** ~1ms para criar todos os accessors
- **Runtime:** Sem overhead (métodos são nativos C++)

### Escalabilidade
- Linear com número de tipos e propriedades
- Típico: ~10-20 tipos × ~20-30 properties = ~200-600 métodos criados
