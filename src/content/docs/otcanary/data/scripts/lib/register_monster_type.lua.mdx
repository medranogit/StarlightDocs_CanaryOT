## 💡 Tip

<Aside type="tip">
**Propósito de Monster Registration (Declarative Configuration)**

Configurar um monstro requer 100+ propriedades (health, spells, loot, sounds, etc):

**Sem registration DSL:**
```lua
local mtype = MonsterType()
mtype:name("Rat")
mtype:health(15)
mtype:experience(5)
mtype:corpseId(3058)
-- ... 50 linhas mais, repetitivas
local spell = MonsterSpell()
spell:setType("melee")
spell:setAttackValue(5, 10)
mtype:addAttack(spell)
-- Verbose demais
```

**Com registration (declarative):**
```lua
MonsterType():register({
	name = "Rat",
	health = 15,
	experience = 5,
	corpse = 3058,
	attacks = {
		{
			name = "melee",
			attack = 5,
			skill = 10
		}
	}
})
```

**Pattern:**
```
registerMonsterType metatable
  ├─ __call intercepta
  ├─ Itera 30+ parsers
  ├─ Cada parser valida/aplica sua seção
  └─ Monstrço configurado completo
```

**Benefício:** DSL limpa, reutilizável, validável, mantenível

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `register_monster_type.lua` implementa **monster configuration DSL**:

- **Define registerMonsterType** metatable com dispatcher e 30+ parsers
- **Estende MonsterType** com método `.register(definitionTable)`
- **Suporta nested configuration** (Bestiary, flags, sounds, loot hierarchical)
- **Valida inputs** em time real com logging de erros
- **Auto-mapeia sounds** baseado em tipo de spell e effect
- **Processa loot hierarchical** com parent/child items e validação de IDs
- **Lê spells complexos** com suporte a melee, combat, condition, custom scripts

### Arquitetura

Script usa padrão de **massive multi-parser dispatcher**:

```lua
registerMonsterType = {}
setmetatable(registerMonsterType, {
	__call = function(self, mtype, mask)
		for _, parse in pairs(self) do
			parse(mtype, mask)
		end
	end,
})
```

Mais 30 parsers especializados: `name`, `description`, `variant`, `experience`, `Bestiary`, `bosstiary`, `flags`, `light`, `attacks`, `defenses`, `loot`, `elements`, `reflects`, etc.

### Fluxo Lógico Resumido

| Fase | Ação | Validação |
|------|------|-----------|
| **Definição** | Table com proprietades é passado | Cada propriedade é chave do parser |
| **Dispatch** | `__call` intercepta | Itera todos parsers em registerMonsterType |
| **Per-Parser** | Parser específico executa se mask.propriedade existe | `if mask.propriedade then` |
| **Validação** | Nested validators (ex: Bestiary, flags, sounds) | Conditional checks cascata |
| **Aplicação** | Chama metodos C++ do MonsterType | `mtype:method(value)` |
| **Persistência** | Configuração é salva no MonsterType | Sobrevive ao jogo |

```lua
registerMonsterType.bosstiary = function(mtype, mask)
	local bossClass = nil
	if mask.bosstiary then
		if mask.bosstiary.bossRace then
			if mask.bosstiary.bossRace == RARITY_BANE then
				bossClass = "Bane"
			elseif mask.bosstiary.bossRace == RARITY_ARCHFOE then
				bossClass = "Archfoe"
			elseif mask.bosstiary.bossRace == RARITY_NEMESIS then
				bossClass = "Nemesis"
			end
		end
		if bossClass == nil then
			logger.error("Attempting to register a bosstiary boss without a race. Boss name: {}", mtype:name())
			return
		end
		if mask.bosstiary.bossRaceId then
			mtype:bossRaceId(mask.bosstiary.bossRaceId)
		else
			logger.error("Attempting to register a bosstiary boss without a raceId. Boss name: {}", mtype:name())
		end
		mtype:bossRace(mask.bosstiary.bossRace, bossClass)
	end
end
```

**Propósito:** Registrar boss no sistema Bosstiary (boss encyclopedia).

**Fluxo:**

1. **Map bossRace (enum) para bossClass (string)**
   ```lua

       bossClass = "Bane"
   ```
   - Converte numeric RARITY enum para string readable

2. **Validação Obrigatória: bossClass**
   ```lua
   if bossClass == nil then
       logger.error(...)
       return
   ```
   - Se nenhum race válido, falha com log e retorna

3. **Registrar raceId**
   ```lua
   if mask.bosstiary.bossRaceId then
       mtype:bossRaceId(...)
   ```
   - bossRaceId é obrigatório

4. **Aplicar Race**
   ```lua
   mtype:bossRace(mask.bosstiary.bossRace, bossClass)
   ```

**Error Handling:** Validation em cascata, return early se falha

### Função Global: MonsterType:createLoot(lootTable)

```lua
function MonsterType:createLoot(lootTable)
	SortLootByChance(lootTable)
	local lootError = false

	for _, loot in pairs(lootTable) do
		local parent = Loot()
		if loot.name then
			if not parent:setIdFromName(loot.name) then
				lootError = true
			end
		else
			if not isInteger(loot.id) or loot.id < 1 then
				lootError = true
			end
			parent:setId(loot.id)
		end

		configureLootAttributes(parent, loot)

		if loot.child and addChildrenLoot(parent, loot.child) then
			lootError = true
		end

		self:addLoot(parent)
	end

	if lootError then
		logger.warn("[MonsterType:createLoot] - Monster: {} loot could not be loaded correctly", self:getName())
	end
end
```

**Propósito:** Carregar em hierarquia de loot com validação em cascata.

**Fluxo:**

1. **Ordenar por Chance**
   ```lua
   SortLootByChance(lootTable)
   ```
   - Se config diz para ordenar, ordena (opcional)

2. **Para cada item loot**
   ```lua
   for _, loot in pairs(lootTable) do
   ```

3. **Criar Loot object**
   ```lua
   local parent = Loot()
   ```

4. **Definir Item ID (por nome ou ID)**
   ```lua
   if loot.name then
       if not parent:setIdFromName(loot.name) then
           lootError = true
       end
   else
       -- ... setId
   end
   ```

5. **Configurar Atributos**
   ```lua
   configureLootAttributes(parent, loot)
   ```
   - Chama função local

6. **Processar Children (opcional)**
   ```lua
   if loot.child and addChildrenLoot(parent, loot.child) then
       lootError = true
   end
   ```
   - Hierarquia: item principal pode ter items filhos

7. **Adicionar ao MonsterType**
   ```lua
   self:addLoot(parent)
   ```

8. **Log de Erros (graceful)**
   ```lua
   if lootError then
       logger.warn(...)
   end
   ```
   - Loga warning, não falha

```lua
local function configureLootAttributes(lootObject, lootProperties)
	if lootProperties.subType or lootProperties.charges then
		lootObject:setSubType(lootProperties.subType or lootProperties.charges)
	else
		local itemType = ItemType(lootProperties.name or lootProperties.itemId)

		end

	lootObject:setChance(lootProperties.chance or 0)
	if lootProperties.minCount ~= nil then
		lootObject:setMinCount(lootProperties.minCount)
	end
	if lootProperties.maxCount ~= nil then
		lootObject:setMaxCount(lootProperties.maxCount)
	end
	-- ... 8 mais setAttributes
```

### Função Local: addChildrenLoot()

```lua
local function addChildrenLoot(parent, childrenLoot)
	SortLootByChance(childrenLoot)
	for _, child in pairs(childrenLoot) do
		local childLoot = Loot()
		if child.name then
			if not childLoot:setIdFromName(child.name) then
				return true  -- Erro
			end
		else
			if not isInteger(child.id) or child.id < 1 then
				return true  -- Erro
			end
			childLoot:setId(child.id)
		end
		configureLootAttributes(childLoot, child)
		parent:addChildLoot(childLoot)
	end
	return false
end
```

**Propósito:** Processar items filhos em estrutura hierarchical de loot.

**Validação:** Retorna true se erro (previne corrupta do loot hierárquico)

### Função Local: loadSpellSoundType()

```lua
local function loadSpellSoundType(incomingLua, mtype)
	local castSound, impactSound = SOUND_EFFECT_TYPE_SILENCE, SOUND_EFFECT_TYPE_MONSTER_CLOSE_ATK_FIST

	if incomingLua.shootEffect ~= nil then
		castSound = loadcastSound(incomingLua.shootEffect, incomingLua, mtype)
	end

	impactSound = loadImpactSound(incomingLua, mtype)
	return { cast = castSound, impact = impactSound }
end
```

**Propósito:** Gerar castSound e impactSound automaticamente baseado spell type.

**Delegação:**
- `loadcastSound()` - Mapeia shootEffect → castSound (throw, crossbow, bow, magical)
- `loadImpactSound()` - Mapeia spell type/damage → impactSound (200+ casos)

**Categorias:**

### Função Local: loadImpactSound() (Complex 200+ lines)

Mapeia spell type, damage type, radius → impactSound específico.

**Exemplos:**
```lua
if incomingLua.name == "melee" then
	-- Melee: FIST, CLAW, BITE (close) ou RIP, MAGIC (ranged)
elseif incomingLua.name == "combat" then
	-- Combat: type = COMBAT_FIRE/ENERGY/etc
	-- Se tem radius: SMALL_AREA_* ou LARGE_AREA_*
	-- Se tem length/spread: WAVE_*
	-- Senão: SINGLE_TARGET_*
elseif incomingLua.name == "drunk" then
	return incomingLua.duration > superDrunkDuration ?
		SOUND_EFFECT_TYPE_MONSTER_SPELL_SUPER_DRUNKEN :
		SOUND_EFFECT_TYPE_MONSTER_SPELL_DRUNKEN
end
```

**Mapeamento:**
- melee + distance ≤ 1 → FIST/CLAW/BITE
- melee + distance > 1 → RIP/MAGIC
- combat + radius ≤ 3 → SMALL_AREA_*
- combat + radius > 3 → LARGE_AREA_*
- combat + length/spread → WAVE_*
- spell type (drunk, speed, outfit, etc) → efeito específico

**Resultado:** 200+ switch cases para validar cada combinação

## 🎯 Padrões & Boas Práticas

### Padrón 1: Multi-Parser Dispatcher Pattern

**Técnica:** Iterar table de functions, cada parser é una função única.

```lua
registerMonsterType = {}
setmetatable(registerMonsterType, {
	__call = function(self, mtype, mask)
		for _, parse in pairs(self) do
			parse(mtype, mask)
		end
	end,
})

registerMonsterType.name = function(...) ... end
registerMonsterType.health = function(...) ... end
-- ... 30+ parsers
```

**Vantagem:**
- Modular: cada parser é isolado
- Extendable: adicionar novo parser = uma função
- Order-independent: parsers executam sem ordem
- Compartmented concerns: cada parser foca em uma coisa

**Aplicação:** Massive configuration systems.

---

### Padrón 2: Nested Table Validation

**Técnica:** Validar sub-propriedades em cascata antes de aplicar.

```lua
registerMonsterType.Bestiary = function(mtype, mask)
	if mask.Bestiary then
		if mask.Bestiary.race then
			mtype:Bestiaryrace(...)
		end
		if mask.Bestiary.class then
			mtype:Bestiaryclass(...)
		end
		-- ... cada uma validada
	end
end
```
