## 💡 Tip

<Aside type="tip">
**Propósito de NPC Registration (Declarative Configuration)**

Configurar um NPC requer múltiplas propriedades (nome, saúde, outfit, shop items, vozes):

**Sem registration DSL:**
```lua
local npc = NpcType()
npc:name("Merchant")
npc:nameDescription("A friendly merchant")
npc:outfit({lookType = 128})
npc:maxHealth(100)
npc:health(100)
local shop = Shop()
shop:setNameItem("Gold Coin")
shop:setBuyPrice(1)
shop:setSellPrice(1)
npc:addShopItem(shop)
npc:addVoice("Hello!", 10, 100, false)
-- Verbose demais
```

**Com registration (declarative):**
```lua
NpcType():register({
	name = "Merchant",
	description = "A friendly merchant",
	outfit = {lookType = 128},
	maxHealth = 100,
	health = 100,
	shop = {
		{
			itemName = "Gold Coin",
			buy = 1,
			sell = 1
		}
	},
	voices = {
		{
			text = "Hello!",
			interval = 10,
			chance = 100
		}
	}
})
```

**Pattern:**
```
registerNpcType metatable
  ├─ __call intercepta: NpcType(def_table)
  ├─ Itera 15 parsers
  ├─ Cada parser valida/aplica sua seção
  └─ NPC configurado completo
```

**Benefício:** DSL limpa, validação global de preços, mantenível
</Aside>

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `register_npc_type.lua` implementa **NPC configuration DSL**:

- **Define registerNpcType** metatable com dispatcher e 15 parsers
- **Estende NpcType** com método `.register(definitionTable)`
- **Suporta shop items** com hierarquia parent-child
- **Valida preços globalmente** via NpcPriceChecker (detecta sell > buy)
- **Processa vozes/sons** com intervals e chances
- **Gerencia flags** de movimento e física
- **Registra eventos** dinamicamente

### Arquitetura

Script usa padrão de **multi-parser dispatcher**:

```lua
registerNpcType = {}
setmetatable(registerNpcType, {
	__call = function(self, npcType, mask)
		for _, parse in pairs(self) do
			parse(npcType, mask)
		end
	end,
})

NpcType.register = function(self, mask)
	return registerNpcType(self, mask)
end
```

15 parsers especializados: `name`, `description`, `outfit`, `health`, `flags`, `shop`, `voices`, `sounds`, etc.

### Fluxo Lógico Resumido

| Fase | Ação | Validação |
|------|------|-----------|
| **Definição** | Table com propriedades é passado | Cada propriedade é chave do parser |
| **Dispatch** | `__call` intercepta | Itera todos parsers em registerNpcType |
| **Per-Parser** | Parser específico executa se mask.propriedade existe | `if mask.propriedade then` |
| **Aplicação** | Chama métodos C++ do NpcType | `npcType:method(value)` |
| **Shop Validation** | Shop items são rastreados em NpcPriceChecker | Detecta sell > buy |
| **Persistência** | Configuração salva no NpcType | Sobrevive ao jogo |

**Propósito Principal:**

registerNpcType.shop = function(npcType, mask)

#### Fluxo de cada Shop Item:

**1. Criar Shop Object Parent**

**2. Extrair Variáveis**

**Nota:** Case insensitivity (itemName vs itemname, clientId vs clientid)

**3. Configurar Parent Shop Item**
```lua

	parent:setNameItem(itemName)
end
if clientId then
	parent:setId(clientId)
end
if shopItems.subType or shopItems.subtype or shopItems.count then
	parent:setCount(...)
end

	parent:setBuyPrice(buyPrice)
end
if sellPrice then
	parent:setSellPrice(sellPrice)
end
```

**4. Global Price Validation via NpcPriceChecker**

```lua
-- Global item tracker to track buy and sell prices across all NPCs
NpcPriceChecker = NpcPriceChecker or {}

if clientId then
	if not NpcPriceChecker[clientId] then
		NpcPriceChecker[clientId] = { buy = nil, sell = nil, buyNpc = nil, sellNpc = nil }
	end

	if buyPrice then
		NpcPriceChecker[clientId].buy = buyPrice
		NpcPriceChecker[clientId].buyNpc = npcName
	end

	if sellPrice then
		NpcPriceChecker[clientId].sell = sellPrice
		NpcPriceChecker[clientId].sellNpc = npcName
	end

	if NpcPriceChecker[clientId].buy and NpcPriceChecker[clientId].sell then
		if NpcPriceChecker[clientId].sell > NpcPriceChecker[clientId].buy then
			logger.warn("The item {} ({}) is being sold for a value greater than the value it is purchased for by the NPCs. Buy NPC: {}, Sell NPC: {}", 
				itemName, clientId, NpcPriceChecker[clientId].buyNpc, NpcPriceChecker[clientId].sellNpc)
		end
	end
end
```

**Validação:** Detecta quando sell > buy (economia inválida, avisa)

## 🎯 Padrões & Boas Práticas

### Padrón 1: Multi-Parser Dispatcher Pattern

**Técnica:** Iterar table de functions, cada parser é função independente.

```lua
registerNpcType = {}
setmetatable(registerNpcType, {
	__call = function(self, npcType, mask)
		for _, parse in pairs(self) do
			parse(npcType, mask)
		end
	end,
})

registerNpcType.name = function(...) ... end
registerNpcType.health = function(...) ... end
-- ... 15 parsers
```

**Vantagem:**
- Modular: cada parser isolado
- Extendable: novo parser = uma função
- Order-independent: sem dependências
- Clean: separação de concerns

**Aplicação:** Massive configuration systems.

---

### Padrón 2: Nested Table Validation

**Técnica:** Validar sub-propriedades antes de aplicar.

```lua
registerNpcType.flags = function(npcType, mask)
	if mask.flags then
		if mask.flags.floorchange ~= nil then
			npcType:floorChange(...)
		end
		if mask.flags.pushable ~= nil then
			npcType:isPushable(...)
		end
	end
end
```

**Vantagem:**
- Safe: sub-propriedades são opcionais
- Flexible: cada uma pode existir ou não
- Explicit: claro quando algo é aplicado

**Aplicação:** Complex nested configurations.

---

### Padrón 3: Global State Validation (Price Checking)

**Técnica:** Track valores globais de múltiplos NPCs para validação cross-instance.

```lua
NpcPriceChecker = NpcPriceChecker or {}

if NpcPriceChecker[clientId].sell > NpcPriceChecker[clientId].buy then
	logger.warn("Economy inconsistency: sell > buy")
end
```

**Vantagem:**
- Holistic: vê economia inteira, não item individual
- Preventive: avisa antes de problema se manifestar
- Tracked: logs qual NPC é culpado

**Aplicação:** Cross-system validation.

---

### Padrón 4: Case Insensitivity Pattern

**Técnica:** Aceitar múltiplas variantes de case para mesma propriedade.

```lua
local itemName = shopItems.itemName or shopItems.itemname
local clientId = shopItems.clientId or shopItems.clientid
```

**Vantagem:**
- Forgiving: typos de case não quebram config
- Backwards Compatible: aceita legacy names
- User-Friendly: não depende de case exato

**Aplicação:** Configuration loading from multiple sources.

---

### Padrón 5: Hierarchical Shop Items (Parent-Child)

**Técnica:** Items principais podem ter sub-items (containers, bundles).

```lua
if shopItems.child then
	for _, children in pairs(shopItems.child) do
		local child = Shop()
		-- Configure child
		parent:addChildShop(child)
	end
end
```

**Vantagem:**
- Realistic: backpack contém items
- Logical: organiza shop items em grupos
- Flexible: profundidade ilimitada

**Aplicação:** Complex shop hierarchies.
