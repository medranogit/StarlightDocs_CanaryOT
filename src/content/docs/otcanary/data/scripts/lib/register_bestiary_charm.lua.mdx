## 💡 Tip

<Aside type="tip">
**Propósito de Charm Registration (Declarative Configuration)**

Charms são bônus/efeitos especiais. Registration permite definição limpa:

**Sem registro metatable:**
```lua
local charm = Charm(1)
charm:name("Fire Protection")
charm:category("defense")
charm:damageType(COMBAT_FIRE)
charm:percentage(10)
-- Verbose, repetitivo
```

**Com registro (declarative):**
```lua
Charm({
	init = {1},
	name = "Fire Protection",
	category = "defense",
	damageType = COMBAT_FIRE,
	percent = 10
})
```

**Pattern:**
```
registerCharm metatable
  ├─ __call intercepta: Charm(def_table)
  ├─ Itera parsers em registerCharm
  ├─ Cada parser aplica sua propriedade
  └─ Retorna Charm com tudo aplicado
```

**Benefício:** DSL style, menos código, mais legível
</Aside>

## 📄 Visão Geral do Código (Resumo Executivo)

### Propósito Principal

O script `register_bestiary_charm.lua` implementa **parser dispatcher system** para Charm:

- **Define registro metatable** com `__call` hook
- **Implementa 11 parsers** especializados
- **Valida propriedades condicionalmente** (se existem na definição)
- **Aplica transformações** (ex: percent → percentage)
- **Estende Charm.register()** method

### Arquitetura

Script usa padrão de **metatable dispatcher com parser functions**:

```lua
registerCharm = {}
setmetatable(registerCharm, {
	__call = function(self, charm, mask)
		for _, parse in pairs(self) do
			parse(charm, mask)
		end
	end,
})

-- Parsers
registerCharm.name = function(charm, mask) ... end
registerCharm.description = function(charm, mask) ... end
-- ... 9 mais
```

Cada chamada `registerCharm(charm, table)` itera e aplica todos os parsers.

### Fluxo Lógico Resumido

| Fase | Ação | Condição |
|------|------|----------|
| **Definição** | Table com propriedades é passado | `{name = "...", category = "..."...}` |
| **Dispatch** | `__call` intercepta | Iteração de parsers |
| **Validação** | Cada parser valida se propriedade existe | `if mask.name then` |
| **Aplicação** | Parser aplica método ao charm object | `charm:name(mask.name)` |
| **Retorno** | Charm totalmente configurado | Com todas as propriedades aplicadas |

## 🔧 Estrutura de Funcionalidades

### Setup: registerCharm Table com Metatable

```lua
registerCharm = {}
setmetatable(registerCharm, {
	__call = function(self, charm, mask)
		for _, parse in pairs(self) do
			parse(charm, mask)
		end
	end,
})
```

**Propósito:** Criar dispatcher que itera parsers.

**Fluxo:**
1. `registerCharm(charm, definitionTable)` é chamado
2. Metatable `__call` intercepts
3. Loop: `for _, parse in pairs(self) do`
   - `self` = tabela registerCharm (contém parser functions)
   - `parse` = cada função parser (name, description, etc)
4. Cada parser é executado com `parse(charm, mask)`

---

### Charm.register Extension

```lua
Charm.register = function(self, mask)
	return registerCharm(self, mask)
end
```

**Propósito:** Estender método `register()` de Charm class.

**Uso:**
```lua
local charm = Charm(1)
charm:register({
	name = "Fire Charm",
	category = "offense"
})
```

**Equivalente a:**
```lua
registerCharm(charm, { name = "...", category = "..." })
```

## 🎯 Padrões & Boas Práticas

### Padrão 1: Metatable Dispatcher

**Técnica:** Usar `__call` para interceptar função e dispatch para múltiplos handlers.

```lua
registerCharm = {}
setmetatable(registerCharm, {
	__call = function(self, charm, mask)
		for _, parse in pairs(self) do
			parse(charm, mask)
		end
	end,
})
```

**Vantagem:**
- Extensível: adicionar novo parser é trivial (append função)
- Centralizado: todos os parsers em um lugar
- Genérico: mesmo pattern pode ser reusado para outras classes

**Aplicação:** Multi-parser registration systems.

---

### Padrón 2: Conditional Property Application

**Técnica:** Validar existência de propriedade antes de aplicar.

```lua
if mask.name then
	charm:name(mask.name)
end
```

**Vantagem:**
- Seguro: não aplica se undefined
- Opcional: alguns parsers podem ser skipped
- Claro: explícito o que foi validado

**Aplicação:** Optional property handling.

---

### Padrön 3: Property Name Transformation

**Técnica:** Usuário escreve `percent`, método chama percentage()`.

```lua
-- Definição
percent = 10

-- Parser
charm:percentage(mask.percent)
```

**Vantagem:**
- API mais intuitiva (percent é termo comum)
- Abstração: hiding method naming differences
- Backwards compatibility: renaming métodos internos sem afetar API externa

**Aplicação:** Bridging de naming conventions.

---

### Padrön 4: Nested Property Handling

**Técnica:** Propriedades aninhadas (table dentro de table).

```lua
if mask.sounds then
	if mask.sounds.castSound then
		charm:castSound(...)
	end
end
```

**Vantagem:**
- Organização: propriedades relacionadas agrupadas
- Flexibilidade: adicionar sounds sem quebrar API

**Aplicação:** Propriedades compostas/relacionadas.

## 🐛 Issues Identificados

### Bug Potencial em registerCharm.category

```lua
registerCharm.category = function(charm, mask)
	if mask.type then      -- ❌ Checa mask.type
		charm:category(mask.category)  -- ✓ Mas aplica category
	end
end
```

**Problema:** Validação e aplicação não combinam

**Fix Sugerido:**
```lua
registerCharm.category = function(charm, mask)
	if mask.category then      -- ✓ Checa category
		charm:category(mask.category)
	end
end
```

## 📈 Performance & Extensibilidade

### Setup Time
- Uma vez na boot: ~1-2ms para criar metatable e parsers

### Runtime Overhead
- Por charm: O(n) onde n = número de parsers ativo
- Tipicamente 11 parsers, mas muitos são skipped (if mask.prop)
- ~0.1-0.5ms por charm registration

### Extensibilidade
Fácil adicionar novo parser:

```lua
registerCharm.newProperty = function(charm, mask)
	if mask.newProperty then
		charm:newProperty(mask.newProperty)
	end
end
```

Nenhuma mudança necessária no dispatcher!
