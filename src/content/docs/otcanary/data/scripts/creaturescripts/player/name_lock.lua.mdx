## 📄 Visão Geral do Código

### Resumo Executivo

O script registra listener de login que valida namelock via KV storage. Função `CheckNamelock(player)` obtém "namelock" do KV, se não tem retorna true (sem ação). Se tem: bloqueia movimento, teleporta para temple, envia mensagem com razão, abre loja de extras, requesteia namechange (GameStore), reschedula CheckNamelock a cada 30s. CreatureEvent "NamelockLogin" schedula primeira checagem em 1s. Padrão de enforcement com global events.

### Estrutura de Funcionalidades

```
FUNÇÃO: CheckNamelock(player)
  ├─ Validação: player:kv():get("namelock")?
  │   ├─ NÃO → return true (sem ação)
  │   └─ SIM → Continua (tem namelock)
  │
  ├─ player:setMoveLocked(true)
  │   └─ Bloqueia movimento
  │
  ├─ player:teleportTo(temple)
  │   └─ Teleporta para temple
  │
  ├─ player:sendTextMessage(MESSAGE_ADMINISTRATOR, "Your name has been locked...")
  │   └─ Avisa razão
  │
  ├─ player:openStore("extras")
  │   └─ Abre loja de namechange
  │
  ├─ addPlayerEvent(sendRequestPurchaseData, 50ms, player, ...)
  │   └─ Request namechange offer
  │
  ├─ addPlayerEvent(CheckNamelock, 30000ms, player)
  │   └─ Reschedula verificação
  │
  └─ return (implícito true)

EVENT: "NamelockLogin"
  └─ onLogin(player)
      ├─ addPlayerEvent(CheckNamelock, 1000ms, player)
      │   └─ Schedula primeira checagem
      │
      └─ return true
```

## Funções Locais

### CheckNamelock(player)

Valida e enforça namelock:

```lua
function CheckNamelock(player)
	-- Obter namelock reason
	local namelockReason = player:kv():get("namelock")
	if not namelockReason then
		return true  -- Sem namelock
	end

	-- Bloquear movimento
	player:setMoveLocked(true)
	
	-- Teleportar para temple
	player:teleportTo(player:getTown():getTemplePosition())
	
	-- Aviso
	player:sendTextMessage(MESSAGE_ADMINISTRATOR, 
		"Your name has been locked for the following reason: " .. namelockReason .. ".")
	
	-- Abrir loja
	player:openStore("extras")
	
	-- Request namechange
	addPlayerEvent(sendRequestPurchaseData, 50, player, 65002, 
		GameStore.ClientOfferTypes.CLIENT_STORE_OFFER_NAMECHANGE)
	
	-- Reschedula (30s)
	addPlayerEvent(CheckNamelock, 30000, player)
end
```

| Parâmetro | Tipo | Descrição |
|-----------|------|-----------|
| player | Player | Player a verificar |

### CheckNamelock - Função Principal

```lua
function CheckNamelock(player)
	local namelockReason = player:kv():get("namelock")
	if not namelockReason then
		return true
	end

	player:setMoveLocked(true)
	player:teleportTo(player:getTown():getTemplePosition())
	player:sendTextMessage(MESSAGE_ADMINISTRATOR, 
		"Your name has been locked for the following reason: " .. namelockReason .. ".")
	player:openStore("extras")
	addPlayerEvent(sendRequestPurchaseData, 50, player, 
		65002, GameStore.ClientOfferTypes.CLIENT_STORE_OFFER_NAMECHANGE)
	addPlayerEvent(CheckNamelock, 30000, player)
end
```

### onLogin - Event Trigger

```lua
local playerLogin = CreatureEvent("NamelockLogin")

function playerLogin.onLogin(player)
	addPlayerEvent(CheckNamelock, 1000, player)
	return true
end

playerLogin:register()
```

## Checkpoint de Aprendizagem

### Conceitos-chave

- **CreatureEvent onLogin**: Callback disparado ao fazer login
- **addPlayerEvent()**: Scheduler de eventos per-player
- **kv():get()**: Obter valor persistente
- **setMoveLocked()**: Bloquear movimento
- **teleportTo()**: Teleportar para posição
- **getTown():getTemplePosition()**: Obter posição de temple
- **sendTextMessage()**: Enviar mensagem (admin)
- **openStore()**: Abrir loja (namechange)
- **Reschedule Pattern**: Chamar função recursivamente
- **Global Events**: Executar per-player, não global

### Responsabilidades do Handler

**CheckNamelock:**
1. **Validar**: Existe namelock?
2. **Bloquear**: setMoveLocked(true)
3. **Teleportar**: Para temple
4. **Avisar**: Mensagem com razão
5. **Oferta**: openStore + request
6. **Reschedular**: Próxima verificação
7. **Confirmar**: return true

**onLogin:**
1. **Schedular**: Primeira CheckNamelock
2. **Timing**: 1s de delay
3. **Confirmar**: return true
