## 🛠️ Informações do Arquivo

**Descrição**: Módulo de **limpeza automática de parcels** que implementa rotina ao login capaz de detectar e remover pacotes stamped vazios (10 slots) do Store Inbox do jogador. Executa varredura simples da inbox checando cada item (`parcel:getId() == ITEM_PARCEL_STAMPED and parcel:getEmptySlots() == 10`), acumula parcels vazios em tabela, remove todos em lote, e notifica jogador via mensagem. Previne acúmulo de lixo de parcels não-abertos ou já esvazidos na inbox.

**Caminho Original**: `data/scripts/creaturescripts/others/remove_empty_parcel.lua`

**Tipo**: CreatureEvent (onLogin trigger)

**Dependências**:
- CreatureEvent API (engine C++)
- Player object methods: `getStoreInbox()`, `sendTextMessage()`
- Item object methods: `getId()`, `getEmptySlots()`, `remove()`
- Constants: `ITEM_PARCEL_STAMPED`, `MESSAGE_EVENT_ADVANCE`

<Aside>
Este evento executa silenciosamente durante login sem impactar jogador. A limpeza é **preventiva** para evitar inbox ficar poluída. Parcels que tiveram itens removidos deixam 10 slots vazios (capacidade total), servindo como critério único de identificação.
</Aside>

## 📄 Visão Geral do Código

### Resumo Executivo

O módulo `remove_empty_parcel.lua` implementa **rotina de housekeeping** durante onLogin que varre o Store Inbox do jogador em busca de parcels stamped completamente vazios (10 slots livres), acumula-os em tabela temporária, remove todos em batch, e notifica jogador do número de parcels eliminados. Padrão simples de **scan-and-cleanup** com feedback opcional, mantendo inbox limpa de containers obsoletos sem impactar items válidos.

### Arquitetura de Componentes

```
Remove Empty Parcels on Login
│
├─ CONSTANTES (2 referências)
│  ├── ITEM_PARCEL_STAMPED (ID do item parcel)
│  └── MESSAGE_EVENT_ADVANCE (tipo de mensagem)
│
├─ EVENT REGISTRATION (1 função)
│  └── removeEmptyParcelsEvent:register() (registra handler na engine)
│
└─ CLEANUP SUBROUTINE (1 função)
   └── onLogin(player)
      ├─ 1. getStoreInbox() e listar todos items
      ├─ 2. Loop: verifica cada parcel
      ├─ 3. Acumula: parcel vazio → emptyParcelsToRemove[]
      ├─ 4. Remove batch: loop e :remove() para cada
      └─ 5. Notifica: sendTextMessage ao jogador
```

```

    │
```

### Tabelas de Dados

**Estrutura de Parcel (Item Object)**:

| Propriedade | Tipo | Descrição |
|---|---|---|
| `getId()` | number | ID do item (ITEM_PARCEL_STAMPED = 2597) |
| `getEmptySlots()` | number | Número de slots livres (0-10) |
| `getItemCount()` | number | Quantidade de items dentro |
| `remove()` | void | Deleta o parcel do jogo |

**Critério de Vazio**:
- `parcel:getId() == ITEM_PARCEL_STAMPED` → É um parcel
- `parcel:getEmptySlots() == 10` → Todos os 10 slots vazios
- **Conclusão**: Parcel não tem nenhum item dentro

## Detalhes da Função Global

### `removeEmptyParcelsEvent.onLogin(player)`

**Tipo**: CreatureEvent callback

**Descrição**: Função disparada automaticamente quando um jogador faz login, executando varredura e remoção de parcels vazios da Store Inbox. Notifica jogador se algum parcel foi removido.

**Parâmetros**:

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `player` | userdata | Referência ao jogador que fez login |

**Retorna**: 
- `true` (sempre, event processado com sucesso)

**Algoritmo**:

```lua
function removeEmptyParcelsEvent.onLogin(player)
    -- PASSO 1: Preparar tabela temporária
    local emptyParcelsToRemove = {}
    
    -- PASSO 2: Varrer todos items do store inbox
    for _, parcel in ipairs(player:getStoreInbox():getItems(true)) do
        -- Validações em cascata
        if parcel:getId() == ITEM_PARCEL_STAMPED and
           parcel:getEmptySlots() == 10 then
            -- Este parcel está vazio: adicionar à lista de remoção
            table.insert(emptyParcelsToRemove, parcel)
        end
    end

    -- PASSO 3: Se há parcels para remover
    if #emptyParcelsToRemove > 0 then
        -- PASSO 3A: Remove cada um
        for _, parcel in pairs(emptyParcelsToRemove) do
            parcel:remove()
        end
        
        -- PASSO 3B: Notificar jogador
        player:sendTextMessage(
            MESSAGE_EVENT_ADVANCE,
            #emptyParcelsToRemove .. " empty parcels were removed from your store inbox!"
        )
    end
    
    return true
end
```

**Características Principais**:

| Característica | Valor | Notas |
|---|---|---|
| Tempo de Execução | O(n) onde n = inbox size | Geralmente < 50 items |
| Critério de Match | Exato (ID + slots) | Sem false positives |
| Notificação | Opcional (if removed) | Apenas se > 0 parcels |
| Segurança | Coleta primeiro, depois remove | Evita iterator invalidation |
| Rollback | Sem transação | Remover é permanente |

## Detalhes das Variáveis Locais

### `emptyParcelsToRemove`

**Tipo**: `table<number, userdata>`

**Escopo**: Local (função)

**Inicialização**: `local emptyParcelsToRemove = {}`

**Descrição**: Acumulador temporário de referências a parcels vazios encontrados na varredura. Coleta todos os parcels que matizam critério (ID + slots) antes de remover, prevenindo invalidação de iterator enquanto modifica tabela.

**Conteúdo**:
```lua
emptyParcelsToRemove = {
    [1] = parcel_object_1,
    [2] = parcel_object_2,
    ...
    [n] = parcel_object_n
}
```

**Ciclo de Vida**:
1. Inicializada vazia na função
2. Populated em loop (`table.insert` no iterator)
3. Consumida no loop de remoção (`parcel:remove()`)
4. Garbage collected ao sair função

**Vantagem de Pré-Coleta**:
```lua
-- ❌ INSEGURO: Modificar enquanto itera
for _, parcel in ipairs(inbox:getItems(true)) do
    if isEmpty(parcel) then
        parcel:remove()  -- Invalida iterator!
    end
end

-- ✅ SEGURO: Coletar então modificar
for _, parcel in ipairs(inbox:getItems(true)) do
    if isEmpty(parcel) then
        table.insert(toRemove, parcel)
    end
end
for _, parcel in pairs(toRemove) do
    parcel:remove()
end
```

## Padrões & Implementação

### 1. Padrão de Scan-and-Cleanup (Two-Pass)

Separar **leitura** de **modificação** em dois loops:

```lua
-- PASS 1: Scan (leitura somente)
for _, item in ipairs(collection) do
    if matches_criteria(item) then
        table.insert(toRemove, item)
    end
end

-- PASS 2: Cleanup (modificação)
for _, item in pairs(toRemove) do
    item:remove()
end
```

**Por Quê**?
- Iterators podem ser invalidados durante modificações
- Correr riscos: `Lua error: bad iterator`
- Solução: Coletar referências, depois processar

**Aplicação no Parcel Cleanup**:
```lua
-- PASS 1: Scan inbox, acumula vazios
for _, parcel in ipairs(inbox:getItems(true)) do
    if parcel:getId() == PARCEL and parcel:getEmptySlots() == 10 then
        table.insert(toRemove, parcel)
    end
end

-- PASS 2: Remove batch
for _, parcel in pairs(toRemove) do
    parcel:remove()
end
```

**Onde Usar**:
- Iterando collections que são listas
- Modificando estado durante loop
- Batch operations em userdata objects

### 2. Padrão de Critério em Cascata (AND Logic)

Múltiplas condições combinadas com **AND lógico**:

```lua
if condition1 and condition2 and condition3 then
    -- Executa somente se TODAS as condições são true
end
```

**Aplicação no Parcel**:
```lua
if parcel:getId() == ITEM_PARCEL_STAMPED and
   parcel:getEmptySlots() == 10 then
    -- Ambas verdadeiras: é parcel **E** está vazio
end
```

**Alternativa com Negação** (se contrário):
```lua
if not (parcel:getId() == ITEM_PARCEL_STAMPED) or
   parcel:getEmptySlots() ~= 10 then
    -- Negação: NOT (parcel AND empty) = NOT parcel OR NOT empty
end
```

**Otimização (Short-Circuit)**:
```lua
if parcel:getId() == ITEM_PARCEL_STAMPED then
    -- Só checa getEmptySlots se ID macheou
    -- Evita chamar função se primeira falha
    if parcel:getEmptySlots() == 10 then
        table.insert(toRemove, parcel)
    end
end
```

### 3. Padrão de Notificação Condicional

Feedback ao jogador apenas em sucesso/mudança:

```lua
if #toRemove > 0 then
    -- Apenas notificar se algo foi feito
    local message = string.format("%d items removed", #toRemove)
    player:sendTextMessage(MESSAGE_INFO, message)
else
    -- Silencioso se nada a fazer
end
```

**Vantagens**:
- Spam zero se inbox já está limpa
- Feedback claro quando ação ocorreu
- Mensagem contém contador (`#emptyParcelsToRemove`)

**Variant com Sempre Notificar**:
```lua
local count = #emptyParcelsToRemove
local message = count > 0 
    and count .. " empty parcels removed" 
    or "Your inbox is already clean"
player:sendTextMessage(MESSAGE_INFO, message)
```

```

    │
    ├─ Scan: ambos têm items
    ├─ emptyParcelsToRemove = {} (vazio)
    │
    ├─ if #emptyParcelsToRemove > 0: FALSE
    │  └─ Nenhuma ação
    │

```

```
    │

    │  ├─ Parcel_A: ID OK, slots = 5 → NÃO adiciona
    │  ├─ Parcel_B: ID OK, slots = 10 → adiciona
    │  ├─ Parcel_C: ID OK, slots = 10 → adiciona
    │
    ├─ emptyParcelsToRemove = [Parcel_B, Parcel_C]

    ├─ if #emptyParcelsToRemove > 0: TRUE (2)
    │  ├─ Remove batch: Parcel_B:remove(), Parcel_C:remove()
    │  ├─ sendTextMessage: "2 empty parcels were removed..."
    │
    └─ Inbox depois: [Parcel_A (5 items)] (2 removidos)
```
