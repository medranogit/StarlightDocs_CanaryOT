## 📄 Visão Geral do Código

### Resumo Executivo

O script implementa consumível de comida especial que concede buff de defesa (+10 shield) por 1 hora. Usa cooldown compartilhado "special-foods-cooldown" (10 min) com outras comidas especiais. Inclui condition pré-compilada, efeito visual, emote e mensagem customizada. Um exemplo de buff defensivo com parâmetros otimizados.

### Estrutura de Funcionalidades

```
CONDITION PRÉ-COMPILADA:
  └─ defenseCondition (CONDITION_ATTRIBUTES)
      ├─ SUBID: JeanPierreDefense
      ├─ BUFF_SPELL: 1
      ├─ TICKS: 60*60*1000 (1 hora)
      ├─ SKILL_SHIELD: +10
      └─ FORCEUPDATE: true

HANDLER:
  └─ roastedDragonWings.onUse()
      ├─ hasExhaustion("special-foods-cooldown")? → bloqueia
      ├─ addCondition(defenseCondition)
      ├─ sendTextMessage("You feel less vulnerable.")
      ├─ say("Chomp.")
      ├─ sendMagicEffect(CONST_ME_MAGIC_RED)
      ├─ setExhaustion("special-foods-cooldown", 10*60)
      ├─ item:remove(1)
      └─ return true
```

## Fluxo de Operação

### Operação Principal

```lua
local defenseCondition = Condition(CONDITION_ATTRIBUTES)
defenseCondition:setParameter(CONDITION_PARAM_SUBID, JeanPierreDefense)
defenseCondition:setParameter(CONDITION_PARAM_BUFF_SPELL, 1)
defenseCondition:setParameter(CONDITION_PARAM_TICKS, 60 * 60 * 1000)
defenseCondition:setParameter(CONDITION_PARAM_SKILL_SHIELD, 10)
defenseCondition:setParameter(CONDITION_PARAM_FORCEUPDATE, true)

function roastedDragonWings.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	-- Validação: cooldown compartilhado
	if player:hasExhaustion("special-foods-cooldown") then
		player:sendTextMessage(MESSAGE_EVENT_ADVANCE, "You need to wait before using it again.")
		return true  -- Item NÃO removido
	end

	-- Aplicar condition de defesa
	player:addCondition(defenseCondition)
	
	-- Feedback ao jogador
	player:sendTextMessage(MESSAGE_EVENT_ADVANCE, "You feel less vulnerable.")
	player:say("Chomp.", TALKTYPE_MONSTER_SAY)
	
	-- Efeito visual na posição do jogador
	player:getPosition():sendMagicEffect(CONST_ME_MAGIC_RED)
	
	-- Ativar cooldown
	player:setExhaustion("special-foods-cooldown", 10 * 60)
	
	-- Consumir item
	item:remove(1)
	return true
end
```

Vantagem: Performance (não cria nova condition a cada uso, apenas aplica).

## Checkpoint de Aprendizagem

### Conceitos-chave

- **Condition Pré-compilada**: Criada uma vez, reutilizada para cada jogador
- **SUBID (Substitution ID)**: Identificador único que permite remover/substituir condições
- **BUFF_SPELL**: Parâmetro boolean que marca condition como buff positivo (não debuff)
- **FORCEUPDATE**: Força atualização imediata de atributos (aplicação instantânea)
- **Cooldown Compartilhado**: Múltiplos items com mesmo cooldown ("special-foods-cooldown")
- **TICKS vs Segundos**: Ticks = millisegundos (3.6M ticks = 1 hora)
- **Return True Sem Consumir**: Se cooldown bloqueia, return true mas não remove item
- **Efeito em getPosition()**: Efeito aplicado à posição atual do jogador
- **JeanPierre Pattern**: SUBID naming convention (JeanPierreDefense, JeanPierreMelee, etc)

### Responsabilidades do Handler

1. **Validar cooldown**: hasExhaustion("special-foods-cooldown")
2. **Bloquear se necessário**: Return true de forma graciosa se bloqueado
3. **Aplicar condition**: addCondition(defenseCondition)
4. **Enviar mensagem**: Notificar jogador do buff
5. **Produzir emote**: say("Chomp.", ...)
6. **Efeito visual**: sendMagicEffect(MAGIC_RED)
7. **Atualizar cooldown**: setExhaustion(10 min)
8. **Consumir item**: item:remove(1)

## Patterns e Implementação

### Padrão Condition Pré-compilada

Este script usa condition global pré-compilada para performance:

```lua
-- Global scope: declaração única
local defenseCondition = Condition(CONDITION_ATTRIBUTES)
defenseCondition:setParameter(CONDITION_PARAM_SUBID, JeanPierreDefense)
-- ... configuração ...

-- Handler: reutilização
function handler.onUse(player, ...)
	player:addCondition(defenseCondition)
end
```

Alternativa dinâmica (menos performance):
```lua
-- Criar nova condition A CADA USO
local condition = Condition(CONDITION_ATTRIBUTES)
-- ... configuração ...
player:addCondition(condition)
```
