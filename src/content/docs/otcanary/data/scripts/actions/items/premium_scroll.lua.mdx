## 📄 Visão Geral do Código

### Resumo Executivo

O script implementa um item consumível que adiciona 30 dias de premium ao jogador. Inclui validação de limite máximo (365 dias) para prevenir abuse. Quando bem-sucedido, consome o item e requer logout/login para ativar. O script demonstra validação de limite com mensagem de cancelamento.

## Fluxo de Operação

### Operação Principal

```lua
function premiumScroll.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	-- Define limite máximo de dias
	local maxDays = 365
	
	-- Verifica se jogador pode comprar mais premium
	if player:getPremiumDays() <= maxDays then
		-- Pode comprar: adiciona 30 dias
		item:remove(1)
		player:addPremiumDays(30)
		player:sendTextMessage(MESSAGE_EVENT_ADVANCE, 
		  "You have activated your 30 day premium time, relog to make it effective.")
		player:getPosition():sendMagicEffect(CONST_ME_TELEPORT)
	else
		-- Não pode: excederia limite
		player:sendCancelMessage("You can not buy more than " .. maxDays .. " days of premium account.")
	end
	return true
end
```

### Logica de Validação

```lua
-- Implementação: checagem <= ao invés de <
if player:getPremiumDays() <= maxDays then
	-- Permite compra se: 0-365 dias (inclusive 365)
else
	-- Bloqueia se: > 365 dias (366+)
end

-- Exemplos:
-- Dias Atuais | Pode Comprar? | Total Após
-- 0           | SIM          | 30
-- 200         | SIM          | 230
-- 335         | SIM          | 365
-- 365         | SIM          | 395 (ultrapassa)
-- 400         | NÃO          | Mantém 400
```

### Diferença Entre os Limites

```
Comparação (<=):
  ├─ 0 <= 365? → SIM (permite)
  ├─ 335 <= 365? → SIM (permite)
  └─ 365 <= 365? → SIM (permite, resultando em 395)

Comparação (<):
  ├─ 0 < 365? → SIM
  ├─ 335 < 365? → SIM
  └─ 365 < 365? → NÃO (bloquearia em 365)
```

**Nota:** A implementação usa `<=` ao invés de `<`, permitindo compra mesmo COM 365 dias exatos. Isso resulta no overflow possível de 395 dias. Comportamento intencional ou bug?

## Patterns e Implementação

### Padrão de Validação com Limite Máximo

Este script demonstra implementação de cap-limit:

```lua
-- Padrão geral
local maxLimit = 365
if currentValue <= maxLimit then
	-- Permitir ação
	consumeItem()
	updateValue(currentValue + 30)
else
	-- Rejeitar ação
	sendCancelMessage("You can not exceed " .. maxLimit .. " units.")
end
```

### Comparação: `<=` vs `<`

| Operador | Teste | 365 Dias | 366 Dias | Resultado |
|----------|-------|---------|---------|---|
| `<= 365` | `current <= maxDays` | Sim | Não | Permite em 365 (overflow criador) |
| `< 365` | `current < maxDays` | Não | Não | Bloqueia em 365 |

A escolha de `<=` no script sugere design intencional que permite sobrepassar em pequenas quantidades.

### Fluxo de Compra Múltipla

```
Primeira Compra:
  ├─ Dias atual: 0
  ├─ Checar: 0 <= 365? SIM
  ├─ Add: 0 + 30 = 30
  └─ Requer: relog

Segunda Compra (mesmo dia):
  ├─ Dias atual: 30
  ├─ Checar: 30 <= 365? SIM
  ├─ Add: 30 + 30 = 60
  └─ Requer: relog

No Limite:
  ├─ Dias atual: 335
  ├─ Checar: 335 <= 365? SIM
  ├─ Add: 335 + 30 = 365
  └─ Requer: relog

Tentar Exceder:
  ├─ Dias atual: 365
  ├─ Checar: 365 <= 365? SIM (!)
  ├─ Add: 365 + 30 = 395 (overflow!)
  └─ Requer: relog
```
