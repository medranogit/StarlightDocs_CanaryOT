## 📄 Visão Geral do Código

### Resumo Executivo

O script é extremamente simples: 3 water pipe IDs registrados para um único handler que envia efeito POFF na posição do item. Sem validação, sem mensagem, sem cooldown, sem achievement. Apenas efeito visual puro. A estrutura é: get item position, send effect, (implícito: game removes item).

### Estrutura de Funcionalidades

```
HANDLER:
  └─ waterPipe.onUse()
      └─ item:getPosition():sendMagicEffect(POFF)
          └─ (item:remove() implícito no framework)
```

## Fluxo de Operação

### Operação Principal

```lua
local waterPipe = Action()

function waterPipe.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	-- Enviar efeito na posição do item
	item:getPosition():sendMagicEffect(CONST_ME_POFF)
	return true
end

-- Registrar 3 IDs
waterPipe:id(2974, 2980, 21323)
waterPipe:register()
```

### Execução Simples

```
Jogador ativa water_pipe
  │
  └─ item:getPosition():sendMagicEffect(POFF)
      └─ Efeito visual emitido
      (Item removido pelo framework)
      return true
```

## Checkpoint de Aprendizagem

### Conceitos-chave

- **item:getPosition()**: Obtém coordenadas do item
- **sendMagicEffect()**: Envia efeito visual
- **CONST_ME_POFF**: Efeito de "pop" (explosão menor)
- **No Validation**: Sem checks
- **No Message**: Sem feedback textual
- **No Cooldown**: Sem exhaustion
- **No Achievement**: Sem progresso
- **Implicit Removal**: item:remove() ocorre externamente

### Responsabilidades do Handler

1. **Enviar efeito**: sendMagicEffect(POFF)
2. **Return**: true

## Patterns e Implementação

### Padrão Ultra-Minimal

Sem cuerpo no handler:

```lua
function waterPipe.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	item:getPosition():sendMagicEffect(CONST_ME_POFF)
	return true
end
```

Vs normal:
```lua
function handler.onUse(player, item, ...)
	-- validações
	-- operações
	-- consumir
```
