## 📄 Visão Geral do Código

### Resumo Executivo

O script implementa sistema onde jogador precisa coletar 4 spiritual horseshoes para desbloquear o mount "Spirit of Purity". Usa KV storage para rastrear quantidade acumulada por jogador. Cada horseshoe consumida incrementa contador. Quando atinge 4 horseshoes, o mount é concedido automaticamente junto com achievement. Dynamic registration por config table permite fácil adição de novos items.

### Estrutura de Funcionalidades

```
CONFIG TABLE:
  ├─ requiredItems[44048]
  │   ├─ key: "spiritual-horseshoe"
  │   └─ count: 4 (horseshoes necessárias)
  │
  └─ mountId: 217

HANDLER:
  └─ spiritualHorseshoe.onUse()
      ├─ Validação: itemInfo = config[item:getId()]?
      ├─ Guard: player:hasMount(mountId)?
      ├─ Increment: kv():set(key, currentCount+1)
      ├─ Effect: HOLYDAMAGE
      ├─ Check: Todas as items somaram count total?
      │   ├─ NÃO → return true (aguardar próximas)
      │   └─ SIM → addMount + achievement
      └─ item:remove(1)

REGISTRATION:
  └─ Loop pairs(requiredItems) para registrar dinamicamente
```

## Fluxo de Operação

### Operação Principal

```lua
function spiritualHorseshoe.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	-- Carrega config do item
	local itemInfo = config.requiredItems[item:getId()]
	if not itemInfo then
		return true  -- Item desconhecido
	end

	-- Guard: já tem mount?
	if player:hasMount(config.mountId) then
		return true  -- Não fazer novamente
	end

	-- Incrementar contador
	local currentCount = (player:kv():get(itemInfo.key) or 0) + 1
	player:kv():set(itemInfo.key, currentCount)
	
	-- Efeito visual
	player:getPosition():sendMagicEffect(CONST_ME_HOLYDAMAGE)
	
	-- Consumir item
	item:remove(1)

	-- Verificar se completou
	for _, info in pairs(config.requiredItems) do
		if (player:kv():get(info.key) or 0) < info.count then
			return true  -- Ainda faltam items
		end
	end

	-- Completou: conceder mount + achievement
	player:addMount(config.mountId)
	player:addAchievement("The Spirit of Purity")
	player:sendTextMessage(MESSAGE_EVENT_ADVANCE, "Spirit of Purity is now yours!")
	return true
end

-- Dynamic registration
for itemId, _ in pairs(config.requiredItems) do
	spiritualHorseshoe:id(itemId)
end
spiritualHorseshoe:register()
```

## Checkpoint de Aprendizagem

### Conceitos-chave

- **KV Storage Cumulativo**: `player:kv():get(key)` carrega valor persistido
- **Incremento**: `(kv().get(key) or 0) + 1` com default 0
- **Persistência**: `kv().set(key, value)` salva para próximas ativações
- **Guard Clause**: `hasMount()` previne duplicação
- **Check Loop**: Validar todos os items atingiram count
- **Dynamic Registration**: `pairs(config.requiredItems)` para registrar IDs
- **Early Return**: Retorna true após consumir se não completo
- **Final Reward**: Mount + Achievement apenas quando completo
- **Efeito na Coleta**: HOLYDAMAGE para feedback visual

### Responsabilidades do Handler

1. **Validar item**: Verificar se item está em config
2. **Guard contra duplicação**: Não prosseguir se já tem mount
3. **Carregar contador**: Obter valor atual de KV
4. **Incrementar**: Somar 1 ao contador
5. **Persistir**: Salvar novo valor em KV
6. **Efeito visual**: HOLYDAMAGE
7. **Consumir item**: remove(1)
8. **Verificar completude**: Loop todos os items
9. **Premiar se completo**: addMount + achievement

Este script demonstra sistema cumulativo:

```lua
-- Incrementar
local currentCount = (player:kv():get(key) or 0) + 1

if currentCount >= requiredCount then
	-- Conceder recompensa
	player:addMount(mountId)

end
```

### Padrão Dynamic Registration

Config-driven registration:

```lua
for itemId, _ in pairs(config.requiredItems) do
	handler:id(itemId)
end
handler:register()
```

Adicionar novos items à config registra automaticamente.
