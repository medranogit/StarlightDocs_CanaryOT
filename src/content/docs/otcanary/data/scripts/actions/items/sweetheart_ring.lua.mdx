## 📄 Visão Geral do Código

### Resumo Executivo

O script é trivialmente simples: verifica se o anel está equipado (item == getSlotItem), emite efeito HEARTS se verdadeiro, e retorna false se não equipado. Não consumi o item, não há cooldown, não há mensagem. É handler puramente visual com validação de slot.

### Estrutura de Funcionalidades

```
sweetheartRing (Action)
  ├─ onUse(player, item, fromPosition, target, toPosition, isHotkey)
  │   ├─ item == player:getSlotItem(CONST_SLOT_RING)?
  │   │   ├─ SIM → Equipado
  │   │   │   ├─ sendMagicEffect(CONST_ME_HEARTS)
  │   │   │   └─ return true
  │   │   │
  │   │   └─ NÃO → Não equipado
  │   │       └─ return false (recusa total)
  │   │
  │   └─ (sem consumo de item)
  │
  └─ register() → ID 3002
```

## Fluxo de Operação

### Operação Principal

```lua
function sweetheartRing.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	-- Verificar se o anel está equipado
	if item == player:getSlotItem(CONST_SLOT_RING) then
		-- Anel equipado: enviar efeito
		player:getPosition():sendMagicEffect(CONST_ME_HEARTS)
		return true
	end
	
	-- Anel não equipado: recusar
	return false
end
```

### Árvore de Decisão

```
Jogador executa ação sobre sweetheart_ring
  │
  ├─ item == player:getSlotItem(CONST_SLOT_RING)?
  │   │
  │   ├─ SIM → Anel no dedo
  │   │   ├─ sendMagicEffect(HEARTS)
  │   │   ├─ Efeito visual aparece
  │   │   └─ return true (sucesso)
  │   │
  │   └─ NÃO → Anel no inventário (não equipado)
  │       ├─ Sem efeito
  │       ├─ System message: "You must equip it first."
  │       └─ return false (falha/recusa)
```

### Return True vs Return False

```
return true:
  ├─ Handler executado com sucesso
  ├─ Item consumido OU permanece (conforme script)
  ├─ Sistema permite ação
  └─ Neste caso: Permanece (não removido)

return false:
  ├─ Handler NOÃ pode ser executado (item fora de uso)
  ├─ VS Code mostra mensagem automática: "You must equip it first"
  ├─ Item não consumido
  ├─ Ação recusada pelo sistema
  └─ Neste caso: Anel deve estar no dedo
```

- **Object Comparison**: Compara objetos item, não IDs

1. **Comparar objetos**: item == getSlotItem()
2. **Se equipado**: Enviar efeito HEARTS
3. **Se não equipado**: Return false (recusar)

5. **Nenhum feedback**: Apenas efeito visual

## Patterns e Implementação

### Padrão Trivial - Slot Verification

Este script é minimal:

```lua
if item == player:getSlotItem(CONST_SLOT_RING) then
	player:getPosition():sendMagicEffect(CONST_ME_HEARTS)
	return true
end
return false
```

Comparação entre objetos item (do inventário) vs getSlotItem (do slot).

### Return False Edge Case

Diferente da maioria dos handlers que sempre retornam true:

```
Padrão comum:
  └─ if not condition then
       └─ return true (sem consumir)
     end
     └─ (consumir ou processar)

Sweetheart Ring:
  └─ if item == equipado then
       └─ return true (com efeito)
     end
     └─ return false (RECUSA ação)
```

Only 3 scripts na batch documentada até aqui usam return false.
