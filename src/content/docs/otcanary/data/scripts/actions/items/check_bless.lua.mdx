## 📄 Visão Geral do Código

**Resumo Executivo**

O script `check_bless.lua` é wrapper extremamente simples que atua como passthrough para sistema de bênçãos externo. Carrega módulo blessing.lua do core directory e delega toda lógica de verificação para Blessings.checkBless(). Suporta 2 item IDs diferentes com mesmo comportamento.

**Estrutura de Funcionalidades**

```
[Carrega external: blessing.lua]
    ↓
[Create checkBless Action]
    ↓
[onUse function]
    └─ return Blessings.checkBless(player)
    ↓
[Register Action on 2 item IDs]
    ├─ 6561 (verificação tipo 1)
    └─ 11468 (verificação tipo 2)
```

## Variáveis Globais

### Blessings (external module)

```lua
dofile(CORE_DIRECTORY .. "/libs/systems/blessing.lua")
```

Carrega módulo externo de bênçãos.

**Localização**: `CORE_DIRECTORY/libs/systems/blessing.lua`

**Namespace Fornecido**: Blessings global com funções relacionadas a bênçãos.

**Função Utilizada**: `Blessings.checkBless(player, [item])`

## Funções

### checkBless.onUse(player, item, fromPosition, target, toPosition, isHotkey)

Callback que delega verificação para módulo externo.

**Parâmetros:**
- player: Creature player
- item: Item sendo usado para checar bênçãos
- fromPosition: Posição do uso
- target: Target opcional
- toPosition: Posição destino
- isHotkey: Boolean se via hotkey

**Implementação:**

```lua
function checkBless.onUse(player, item, fromPosition, target, toPosition, isHotkey)
	return Blessings.checkBless(player)
end
```

Passthrough direto sem lógica local.

**Return Value:**

Retorna resultado de Blessings.checkBless(player):
- true: Operação bem-sucedida (verificação realizada)
- false: Operação falhou
- Possível nil: Sem feedback requerido

```
[Player usa verificador (6561 ou 11468)]
    ↓

    ├─ ID match? → onUse triggered
    └─ ID not in list? → no handler
    ↓

    ↓

    └─ Retorna sucesso/falha

```

## Arquitetura de Módulo

**Padrão": Wrapper com Delegação

```
check_bless.lua (wrapper, 7 linhas)
    ↓ delegates to
CORE_DIRECTORY/libs/systems/blessing.lua
    └─ Blessings.checkBless(player)
```

### Vantagens dessa Arquitetura

1. **Separação de Concerns**: Lógica centralizada em blessing.lua
2. **Reutilização**: Múltiplos scripts podem usar Blessings
3. **Manutenibilidade**: Alterações em blessing.lua afetam todos
4. **Escalabilidade**: Novos item IDs podem ser adicionados sem alterar lógica
5. **Legibilidade**: Wrapper claramente indica delegação
