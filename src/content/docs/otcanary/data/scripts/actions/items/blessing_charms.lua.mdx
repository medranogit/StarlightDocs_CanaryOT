## 📄 Visão Geral do Código

**Resumo Executivo**

O script `blessing_charms.lua` é um wrapper simples que delega toda lógica de charm para módulo externo Blessings. Suporta 7 item IDs de charms diferentes todos com mesmo comportamento. Carrega arquivo blessing.lua do core directory e usa sua função useCharm().

**Estrutura Fundamental**

```
[Carrega external: blessing.lua]
    ↓
[Create blessingCharms Action]
    ↓
[onUse function]
    └─ return Blessings.useCharm(player, item)
    ↓
[Register Action on 7 charm IDs]
    ├── 10341 (charm type 1)
    ├── 10342 (charm type 2)
    ├── 10343 (charm type 3)
    ├── 10344 (charm type 4)
    ├── 10345 (charm type 5)
    ├── 25360 (charm type 6)
    └── 25361 (charm type 7)
```

## Variáveis Globais

### Blessings (external module)

```lua
dofile(CORE_DIRECTORY .. "/libs/systems/blessing.lua")
```

Carrega módulo externo Blessings que contém implementação real.

**Localização**: `CORE_DIRECTORY/libs/systems/blessing.lua`

**Namespace**: Blessings global

## Funções

### blessingCharms.onUse(player, item, fromPosition, target, toPosition, isHotkey)

Callback que delega para módulo externo.

**Parâmetros:**
- player: Creature player
- item: Charm sendo usado
- fromPosition: Posição do uso
- target: Target (pode ser nil)
- toPosition: Posição destino
- isHotkey: Boolean se via hotkey

**Implementação:**

```lua
function blessingCharms.onUse(player, item, fromPosition, target, toPosition, isHotkey)
  return Blessings.useCharm(player, item)
end
```

Passthrough simples para Blessings.useCharm().

**Return Value:**

Retorna resultado de Blessings.useCharm():
- true: Uso bem-sucedido
- false: Uso rejeitado

## Fluxo de Operação

```
[Player usa charm]
    ↓
[Script checked against 7 registered IDs]
    ├─ ID match? → onUse triggered
    └─ ID not in list? → no handler
    ↓
[blessingCharms.onUse called]
    ↓
[Blessings.useCharm(player, item)]
    ↓
[External module processes charm logic]
    ├─ Validações (level, quest, etc)
    ├─ Aplicar bênção
    ├─ Consumir item
    └─ Retorna sucesso/falha
    ↓
[return true/false]
```

## Arquitetura de Módulo

**Padrão**: Separação de concerns

```
blessing_charms.lua (wrapper, 10 linhas)
    ↓ delegates to
CORE_DIRECTORY/libs/systems/blessing.lua (implementation, N linhas)
    ├─ Blessings.useCharm()
    ├─ Blessings.applyBlessing()
    └─ ... mais funções
```

Vantagens:
- Código reutilizável (múltiplos scripts podem usar blessings)
- Centralização de lógica
- Fácil manutenção
- Separação clara de responsabilidades

## Checkpoint de Aprendizagem

**Conceitos-chave:**
1. Wrapper pattern delegando para módulo externo
2. Múltiplos item IDs mapeando para mesma ação
3. dofile() para carregar módulos do core
4. Blessings como namespace global
5. Passthrough simples sem lógica local

**Responsabilidades:**
1. Registrar todos os charm IDs
2. Delegar para Blessings.useCharm()
3. Retornar resultado da função externa
4. Manter carregamento do módulo blessing.lua
