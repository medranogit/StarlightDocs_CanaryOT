## 📄 Visão Geral do Código

**Resumo Executivo**

O script `quest_door.lua` implementa um sistema de portas com validação via storage value. Quando um player tenta usar uma porta, seu actionid especifica qual storage deve ser checado. Se player:getStorageValue(actionid) != -1, significa que completou a quest e acesso é permitido. Portas fornecem acesso bloqueado, revelado apenas após conclusão de quest.

**Estrutura Fundamental**

```
[Load QuestDoorTable]
    ↓
[Extract doorIds]
    ↓
[Create questDoor Action]
    ↓
[onUse function]
    ├─ Check if door exists in table
    ├─ Validate: player.storageValue(actionid) != -1
    ├─ Pass validation
    │   ├─ Open transform + sound
    │   └─ Teleport player
    └─ Fail validation
        └─ "The door seems to be sealed..." message
    ↓
[Register Action on all doorIds]
```

## Variáveis Globais

### doorIds (local array)

```lua
local doorIds = {}
```

Array contendo todos os IDs únicos de portas (abertas + fechadas) para registrar a ação.

**Preenchimento**:
```lua
for index, value in ipairs(QuestDoorTable) do
  if not table.contains(doorIds, value.openDoor) then
    table.insert(doorIds, value.openDoor)
  end
  if not table.contains(doorIds, value.closedDoor) then
    table.insert(doorIds, value.closedDoor)
  end
end
```

Itera QuestDoorTable, extrai openDoor e closedDoor, evita duplicatas.

### QuestDoorTable (global, externa)

Tabela global esperada:

```lua
QuestDoorTable = {
  {
    openDoor = 9000,     -- ID quando aberta
    closedDoor = 9001    -- ID quando fechada
  },
  { openDoor = 9002, closedDoor = 9003 },
  -- ... mais portas
}
```

## Funções

### questDoor.onUse(player, item, fromPosition, target, toPosition, isHotkey)

Callback principal acionado quando player usa a porta.

**Parâmetros:**
- player: Creature player
- item: Item da porta
- fromPosition: Posição origin
- target: Target (pode ser nil)
- toPosition: Posição destino
- isHotkey: Boolean se via hotkey

**Fluxo Lógico:**

```
1. Iterar QuestDoorTable procurando closedDoor:
   ├─ Encontrou?
   │   ├─ item.actionid > 0?
   │   │   ├─ player.storageValue(actionid) != -1?
   │   │   │   ├─ SIM (quest completa) → Transform + Som + Teleport → return true
   │   │   │   └─ NÃO (quest incompleta) → "The door seems to be sealed..." → return true
   │   │   └─ actionid <= 0? → continue (sem validação)
   │   └─ Não encontrou → continue
   └─ Final → return true
```

**Bloco 1: Quest Validation and Door Opening**

```lua
for index, value in ipairs(QuestDoorTable) do
  if value.closedDoor == item.itemid then
    if item.actionid > 0 and player:getStorageValue(item.actionid) ~= -1 then
      item:transform(value.openDoor)
      item:getPosition():sendSingleSoundEffect(SOUND_EFFECT_TYPE_ACTION_OPEN_DOOR)
      player:teleportTo(toPosition, true)
      return true
    else
      player:sendTextMessage(MESSAGE_EVENT_ADVANCE, "The door seems to be sealed against unwanted intruders.")
      return true
    end
  end
end
```

Valida storage (quest completion), abre porta com sound e teleporta. Mensagem de rejeição se quest não completa.

**Bloco 2: Creature Check (não implementado, apenas return)**

```lua
if Creature.checkCreatureInsideDoor(player, toPosition) then
  return true
end
return true
```

Fallback seguro.

## Storage Value System

**Storage Validation:**

```
getStorageValue(storageid):
  -1 → Storage não setado (quest não iniciada ou completa)
  0+ → Storage foi setado (quest em progresso ou completa)
```

**Lógica:**

```lua
player:getStorageValue(item.actionid) ~= -1
```

Retorna true se storage foi setado (valor != -1), indicando progressão de quest.

## Comparação com level_door.lua

| Aspecto | level_door | quest_door |
|---------|-----------|-----------|
| Validação | player.getLevel() | player.getStorageValue() |
| Fórmula | level >= actionid - 1000 | storage != -1 |
| Escalável | Por nível | Por quest |
| Múltiplas Contas | Não (level é global) | Sim (storage por player) |
| Msg Rejeição | "Only the worthy may pass." | "The door seems to be sealed..." |

## Fluxo de Operação

```
[Player clica na porta]
    ↓
[Door found in QuestDoorTable?]
    ├─ SIM → próximo
    └─ NÃO → return true (no-op)
    ↓
[item.actionid > 0?]
    ├─ SIM → Validar quest
    │   ├─ player.storageValue(actionid) != -1?
    │   │   ├─ SIM → Open + Sound + Teleport
    │   │   └─ NÃO → "The door seems to be sealed..." message
    │   └─ return true
    └─ NÃO → return true (sem validação, porta aberta)
```

## Mensagens de Erro

| Condição | Mensagem | Type |
|----------|----------|------|
| Quest não completa | "The door seems to be sealed against unwanted intruders." | MESSAGE_EVENT_ADVANCE |

### MESSAGE_EVENT_ADVANCE

Tipo de mensagem que aparece em cor destaque para o player (notificações de eventos importantes).

## Storage Integration

**Exemplo de Quest Setup:**

```lua
-- Quest início (NPC ou trigger)
player:setStorageValue(storageid, 1)  -- Marca quest iniciada

-- Quest completa (NPC ou trigger)
player:setStorageValue(storageid, 2)  -- Marca quest completa

-- Porta check
if player:getStorageValue(storageid) ~= -1 then
  -- Player iniciou ou completou a quest
end
```

Storage permitem quests complexas com múltiplos estágios (valor 1 = início, 2 = meio, 3 = completo).

## Checkpoint de Aprendizagem

**Conceitos-chave:**
1. Validação via storage value (quest-based)
2. Storage -1 significa não setado, qualquer outro valor permite acesso
3. Portas são closed, transformam para open ao validar
4. Teleport automático após passar validação
5. actionid especifica qual storage key checar
6. Storage é por-player (diferente de level que é global)

**Responsabilidades:**
1. Manter QuestDoorTable com openDoor e closedDoor
2. Extrair doorIds únicos para registrar
3. Validar player.storageValue(actionid) != -1
4. Emitir efeito sonoro na abertura
5. Teleportar player para toPosition se passou
6. Sincronizar actionids com sistema de quests
