## 🛠️ Storage Values

Sistema de **ranges numéricos** para organizar storage keys sem conflitos.

<Card title="Caminho Original" icon="document">
  `data/XML/storages.xml`
</Card>

<Aside type="tip">
  Cada range define um "namespace" para storage values. O valor real = range.start + storage.key
</Aside>

## 📄 Visão Geral

Organiza storage em ranges:

- **Namespace hierárquico**: snake_case (ex: `wheel.scroll.abridged`)
- **Cálculo**: Valor real = range_start + key
- **Sem conflitos**: Ranges não sobrepem-se
- **Escalável**: Fácil adicionar novos ranges

## 🔧 Estrutura

### Range

```xml
<range start="1000000" end="2000000">
    <storage name="wheel.scroll.abridged" key="1" />
    <storage name="wheel.scroll.basic" key="2" />
    ...
</range>
```

<Card title="Cálculo" icon="parameters">

**Fórmula:**
```
Valor Real = range_start + storage_key
```

**Exemplo:**
```
range.start = 1000000
storage[wheel.scroll.abridged].key = 1
real_value = 1000001
```

</Card>

## 💡 Utilidade

Este arquivo define o sistema de storage values do servidor. Usa ranges para organizar espaço numérico e evitar conflitos entre IDs. Cada storage tem um nome descritivo em snake_case e uma chave. O valor real é calculado como `range_start + storage_key`.

## 📄 Visão Geral do Código Resumo Executivo

O arquivo `storages.xml` implementa um sistema de nomeação de storage values:

- **Organisação em Ranges**: Espaço numérico dividido em faixas
- **Evitar Conflitos**: Ranges não sobrepõem (start...end)
- **Nomeclatura Clara**: Snake_case para identificação
- **Cálculo Automático**: Nome + key = valor real usado
- **Escalabilidade**: Permite expansão sem quebrar valores existentes

## 🔧 Estrutura de Funcionalidades

### Estrutura Geral

```xml
<storages>
    <range start="1000000" end="2000000">
```

### Elemento: Range

```xml
<range start="1000000" end="2000000">
    <storage name="wheel.scroll.abridged" key="1" />
    <storage name="wheel.scroll.basic" key="2" />
    <storage name="wheel.scroll.revised" key="3" />
    <storage name="wheel.scroll.extended" key="4" />
    <storage name="wheel.scroll.advanced" key="5" />
</range>
```

**Atributos:**

| Atributo | Tipo | Descrição |
|----------|------|-----------|
| `start` | number | Início da faixa numérica |
| `end` | number | Fim da faixa numérica |

**Descrição:**
Define um range (faixa) de valores válidos para storages dentro do intervalo.


**Atributos:**

| Atributo | Tipo | Descrição |
|----------|------|-----------|
| `name` | string | Nome descritivo (snake_case) |
| `key` | number | ID relativo ao range |

**Cálculo de Valor Final:**

```
Valor Real = range_start + storage_key
Exemplo: 1000000 + 1 = 1000001 para "wheel.scroll.abridged"
```

## 📋 Resumo de Implementação

**Propósito do Sistema:**

O sistema de ranges evita que valores de storage conflitem uns com outros:

```
Sem ranges (ERRADO):
- Quest storage: 1
- Quest progress: 1  ← CONFLITO!

Com ranges (CORRETO):
- Quest range (1000000-2000000): quest.name = 1000001
- Progress range (3000000-4000000): progress.name = 3000001
```

**Exemplo de Expansão:**

```xml
<storages>
    <!-- Range 1: Wheel scrolls -->
    <range start="1000000" end="2000000">
        <storage name="wheel.scroll.abridged" key="1" />
        ...
    </range>
    
    <!-- Range 2: Quest tracking (future) -->
    <range start="2000001" end="3000000">
        <storage name="quest.name1.status" key="1" />
        ...
    </range>
    
    <!-- Range 3: Event data (future) -->
    <range start="3000001" end="4000000">
        <storage name="event.name.progress" key="1" />
        ...
    </range>
</storages>
```

**Vantagens:**

1. **Sem Conflitos**: Ranges não sobrepem-se
2. **Escalável**: Fácil adicionar novas ranges
3. **Legível**: Nomes descritivos do que cada storage faz
4. **Organizado**: Agrupa funcionalidades relacionadas
5. **Documentado**: Nome indica propósito

**Prática Recomendada:**

```xml
<!-- Estrutura sugerida para novo range -->
<range start="10000000" end="11000000">
    <storage name="feature.subfeature.aspect" key="1" />
    <storage name="feature.subfeature.other" key="2" />
    ...
</range>
```

## 📋 Tabela de Conversão

**Como Usar em Código:**

```lua
-- Em vez de hardcoding:
player:setStorageValue(1000001, value)  -- ❌ Magic number

-- Usar constante definida:
Storage.WheelScrollAbridged = 1000001
player:setStorageValue(Storage.WheelScrollAbridged, value)  -- ✓ Correto
```

O arquivo `storages.xml` serve como fonte de verdade para esses valores constantes.
