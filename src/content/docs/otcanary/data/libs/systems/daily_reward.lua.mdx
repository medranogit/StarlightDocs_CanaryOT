## 📄 Visão Geral do Código

### Resumo Executivo

O módulo `daily_reward.lua` implementa **sistema de bonus de regeneração assíncrono** para stamina (regenera 1 minuto a cada 6 segundos em PZ quando stamina está em range bonus 2340-2520) e soul points (1 ponto a cada ciclo em PZ, com máximo diferenciado: 100 para regular, 200 para VIP/Premium). Sistema usa async event loop via addEvent() para reschedule contínuo, com registro global de event IDs em DailyRewardBonus tabelas para cleanup ao desconectar. Inclui string extension str:diff() para converter segundos em formato humanizado (e.g., "1 day, 2 hours, 3 minutes and 45 seconds"), e infrastructure de global storage (db upsert) para persistir timestamps críticos.

## Funções Globais

### 1. RegenStamina(playerId, delayMs) - REGENERAÇÃO STAMINA CRÍTICA

Regenera stamina de jogador assincronamente, com delay especial em PZ quando stamina está em range bonus.

**Parâmetros**:
- playerId (number): ID do jogador
- delayMs (number): Delay em milissegundos até próximo tick

**Retorna**: 
- (boolean): true se sucesso, false se jogador not found

**Lógica Detalhada**:

```lua
function RegenStamina(id, delay)
    -- 1. BUSCAR EVENT ANTERIORMENTE AGENDADO
    local staminaEvent = DailyRewardBonus.Stamina[id]
    local player = Player(id)
    
    -- 2. VALIDAÇÃO: JOGADOR DESCONECTOU
    if not player then
        stopEvent(staminaEvent)
        DailyRewardBonus.Stamina[id] = nil
        return false
    end
    
    -- 3. ONLY IN PZ
    if player:getTile():hasFlag(TILESTATE_PROTECTIONZONE) then
        local actualStamina = player:getStamina()
        
        -- 3A. BONUS LOGIC: Se stamina entre 2340-2520, delay = 6 minutos
        --     (Bonus stamina range = 39 minutos de exaustão)
        if actualStamina > 2340 and actualStamina < 2520 then
            delay = 6 * 60 * 1000  -- 6 minutos em ms
        end
        
        -- 3B. REGENERAR: Se stamina < 2520 (máximo)
        if actualStamina < 2520 then
            player:setStamina(actualStamina + 1)
            player:sendTextMessage(MESSAGE_FAILURE, "One minute of stamina has been refilled.")
        end
    end
    
    -- 4. RESCHEDULE EVENT
    stopEvent(staminaEvent)
    DailyRewardBonus.Stamina[id] = addEvent(RegenStamina, delay, id, delay)
    return true
end
```

**Comportamento de Delay**:

| Stamina Range | Delay | Motivo |
|---|---|---|
| 0 a 2339 | Standard (default) | Normal regen rate |
| 2340 a 2520 | 6 minutos | Bonus stamina range (39 min total) |
| 2520+ | Skipped (no regen) | Máximo atingido |

**Peculiaridades**:
- Stamina máximo é 2520 (42 minutos * 60 segundos)
- Range bonus 2340-2520 = últimos 3 minutos, regen é 6x mais rápido
- Reschedule ocorre mesmo se fora da PZ (mas sem regeneração)
- stopEvent() limpa evento anterior antes de adicionar novo (no leak)

### 2. RegenSoul(playerId, delayMs) - REGENERAÇÃO SOUL CRÍTICA

Regenera soul points de jogador assincronamente, com diferenciação VIP/Premium.

**Parâmetros**:
- playerId (number): ID do jogador
- delayMs (number): Delay em milissegundos até próximo tick

**Retorna**: 
- (boolean): true se sucesso, false se jogador not found

**Lógica Detalhada**:

```lua
function RegenSoul(id, delay)
    -- 1. BUSCAR EVENT ANTERIORMENTE AGENDADO
    local soulEvent = DailyRewardBonus.Soul[id]
    local player = Player(id)
    
    -- 2. VALIDAÇÃO: JOGADOR DESCONECTOU
    if not player then
        stopEvent(soulEvent)
        DailyRewardBonus.Soul[id] = nil
        return false
    end
    
    -- 3. CALCULAR MÁXIMO SOUL CONFORME VIP/PREMIUM
    local maxsoul = 100  -- Regular players
    if (configManager.getBoolean(configKeys.VIP_SYSTEM_ENABLED) and player:isVip()) 
       or player:isPremium() then
        maxsoul = 200  -- VIP ou Premium = 2x máximo
    end
    
    -- 4. REGENERAR APENAS EM PZ
    if player:getTile():hasFlag(TILESTATE_PROTECTIONZONE) then
        if player:getSoul() < maxsoul then
            player:addSoul(1)
            player:sendTextMessage(MESSAGE_FAILURE, "One soul point has been restored.")
        end
    end
    
    -- 5. RESCHEDULE EVENT
    stopEvent(soulEvent)
    DailyRewardBonus.Soul[id] = addEvent(RegenSoul, delay, id, delay)
    return true
end
```

**Diferenciação VIP/Premium**:

| Tipo Jogador | Máximo Soul | Vantagem |
|---|---|---|
| Regular | 100 | Standard |
| Premium | 200 | 2x máximo |
| VIP (se habilitado) | 200 | 2x máximo |
| VIP + Premium | 200 | Max é additive (200, não 300) |

**Peculiaridades**:
- configManager.getBoolean(configKeys.VIP_SYSTEM_ENABLED) = pode desabilitar VIP
- Reset de maxsoul **a cada tick** (não cached) permite change dinâmico de status
- Soul regenera 1 ponto por ciclo (não acumulativo)
- Only regenera se em PZ e abaixo de max

### 3. string.diff(secondsNum) - STRING EXTENSION

Estende objeto string Lua para converter segundos em format humanizado.

**Parâmetros**:
- self (number): Número de segundos a converter

**Retorna**: 
- (string): Formatação humanizada (e.g., "1 day, 2 hours, 3 minutes and 5 seconds")

**Implementação Complexa**:

```lua
function string.diff(self)
    -- 1. DEFINIR FORMATO: pares de (unidade, divisor)
    local format = {
        { "day", self / 60 / 60 / 24 },
        { "hour", self / 60 / 60 % 24 },
        { "minute", self / 60 % 60 },
        { "second", self % 60 },
    }
    
    -- 2. ACUMULAR UNIDADES COM VALOR > 0
    local out = {}
    for k, t in ipairs(format) do
        local v = math.floor(t[2])  -- Piso do valor
        if v > 0 then
        if v > 0 then
            -- Formatação especial: ", " ou " and "
            local separator = (k < #format and (#out > 0 and ", " or "") or " and ")
            local unitStr = t[1] .. (v ~= 1 and "s" or "")  -- Plural
            table.insert(out, separator .. v .. " " .. unitStr)
        end
    end
    
    -- 3. CONCATENAR
    local ret = table.concat(out)
    
    -- 4. POST-PROCESSING: Se muito curto e tem "second", remove tudo antes de " and "
    if ret:len() < 16 and ret:find("second") then
        local a, b = ret:find(" and ")
        ret = ret:sub(b + 1)  -- Keep apenas " and Xs second(s)"
    end
    
    return ret
end
```

**Exemplos de Output**:

| Segundos | Output |
|---|---|
| 5 | "5 seconds" |
| 65 | "1 minute and 5 seconds" |
| 3665 | "1 hour, 1 minute and 5 seconds" |
| 90061 | "1 day, 1 hour, 1 minute and 1 second" |

**Peculiaridades**:
- Pluralização: "1 second" vs "2 seconds"
- Separator logic: vírgulas entre múltiplos, " and " antes do último
- Post-processing: se string muito curta (menor que 16 chars) e tem "second", trunca tudo antes de " and "
  - Motivo: "5 seconds" é mantido, mas "0 minutes and 5 seconds" vira "5 seconds"

### 5. UpdateDailyRewardGlobalStorage(key, value) - UPSERT DB

Insere ou atualiza valor em global_storage table (SQL).

**Parâmetros**:
- key (number): Chave armazenada
- value (number): Valor a armazenar

**Retorna**: 
- (void)

**Implementação**:

```lua
function UpdateDailyRewardGlobalStorage(key, value)
    db.query("INSERT INTO `global_storage` (`key`, `value`) VALUES (" .. key .. ", " .. value .. ") ON DUPLICATE KEY UPDATE `value` = " .. value)
end
```

**SQL Executada**:
```sql
INSERT INTO `global_storage` (`key`, `value`) VALUES (key, value) 
ON DUPLICATE KEY UPDATE `value` = value
```

**Peculiaridades**:
- ON DUPLICATE KEY UPDATE = upsert pattern (insert if not exists, update if exists)
- String concatenation direta em SQL (sem prepared statement!) - vulnerável a SQL injection se key/value mal-validados
- Executa fire-and-forget (sem validação de resultado)

---

### 6. RetrieveGlobalStorage(key) - QUERY DB

Recupera valor de global_storage table (SQL).

**Parâmetros**:
- key (number): Chave a buscar

**Retorna**: 
- (number): Valor encontrado ou 1 (fallback/default)

**Implementação**:

```lua
function RetrieveGlobalStorage(key)
    local resultId = db.storeQuery("SELECT `value` FROM `global_storage` WHERE `key` = " .. key)
    if resultId ~= false then
        local val = Result.getNumber(resultId, "value")
        Result.free(resultId)
        return val
    end
    return 1
end
```

**Fluxo**:

1. db.storeQuery() executa SELECT, retorna resultId ou false
2. if resultId != false sem erro
3. Result.getNumber(resultId, "value") extrai coluna value
4. Result.free(resultId) libera resultado
5. Retorna val, ou 1 se não encontrado

## 🔄 Padrões de Uso

### Padrão 1: Iniciar Regeneração ao Login

```lua
function onPlayerLogin(player)
    local playerId = player:getId()
    local defaultDelay = 1000  -- 1 segundo inicial
    
    DailyRewardBonus.Stamina[playerId] = addEvent(RegenStamina, defaultDelay, playerId, defaultDelay)
    DailyRewardBonus.Soul[playerId] = addEvent(RegenSoul, defaultDelay, playerId, defaultDelay)
end
```

### Padrão 2: Limpar ao Logout

```lua
function onPlayerLogout(player)
    local playerId = player:getId()
    
    if DailyRewardBonus.Stamina[playerId] then
        stopEvent(DailyRewardBonus.Stamina[playerId])
        DailyRewardBonus.Stamina[playerId] = nil
    end
    
    if DailyRewardBonus.Soul[playerId] then
        stopEvent(DailyRewardBonus.Soul[playerId])
        DailyRewardBonus.Soul[playerId] = nil
    end
end
```

### Padrão 3: Usar string.diff() para Timeouts

```lua
function getTTLMessage(secondsRemaining)
    return "Seu buff expira em: " .. (secondsRemaining):diff()
end

-- Exemplo: getTTLMessage(3661) → "1 hour, 1 minute and 1 second"
```

### Padrão 4: Persistir Timestamp

```lua
function onServerSave()
    local timestamp = os.time()
    UpdateDailyRewardGlobalStorage(DailyReward.storages.lastServerSave, timestamp)
end
```

### Padrão 5: Query Timestamp

```lua
function getTimeSinceLastSave()
    local lastSave = GetDailyRewardLastServerSave()
    local now = os.time()
    return now - lastSave
end
```

## 📚 Conclusão

O módulo `daily_reward.lua` implementa **sistema de bonus de regeneração contínua** típico de MMOs, onde stamina e soul regeneram assincronamente enquanto jogador está em zona de proteção. Design é notável por sua **eficiência de delay dinâmico**: quando stamina está em range final (2340-2520), regeneração acelera 6x (6 minutos vs ~1 segundo default), incentivando jogadores a recuperar stamina em PZ antes de sair.

A diferenciação VIP/Premium é simples mas eficaz: soul máximo dobra para 200, retenção potencial de pagantes. O uso de **global storage para persistência** (DB upsert) permite tracking de timestamps críticos (últimó server save) sem perder dados entre restarts.

Particularmente elegante é a **string extension str:diff()** que converte segundos em formato humanizado (e.g., "1 day, 2 hours, 3 minutes and 5 seconds"), com pluralização automática e post-processing especial para valores curtos. O padrão de registro de event IDs em DailyRewardBonus tabelas garante **zero memory leaks** - cada resgate ao logout via stopEvent() elimina evento órfão.

<Aside type="caution">
**Atenção Crítica**:
- **SQL Injection Risk**: UpdateDailyRewardGlobalStorage usa concatenação direta - key/value devem ser validados/sanitizados antes
- **Event Leak**: Se RegenStamina/RegenSoul não chamar stopEvent() antes de addEvent(), event anterior vaza (porém código tem guard)
- **Stamina Máximo Hardcoded**: 2520 é constante (42 minutos), não configurável
- **Soul Diferenciação Dinâmica**: maxsoul recalculado a cada tick (permite change VIP status mid-regen, não cached)
- **PZ Requirement Crítico**: Se jogador sair de PZ, regeneração para mas async loop continua (esperando re-entrada PZ)
- **String Extension Global**: string.diff() estende TODAS as strings em Lua - pode colidir com outros mods
- **Fallback 1**: RetrieveGlobalStorage retorna 1 se não encontrado - pode causar problemas se 1 é valor inválido
- **No Validation**: RegenStamina/RegenSoul não validam se stamina/soul storage corrupto
</Aside>
