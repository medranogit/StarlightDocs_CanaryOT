## 🛠️ Informações do Arquivo

**Descrição**: Módulo de **sistema de bênçãos** que implementa proteção contra perda de itens e skills ao morrer. Define 8 tipos diferentes de bênçãos (com 3 tipos: Regular, Enhanced, PvP), calcula custos dinâmicos baseados em nível do jogador, gerencia queda de loot ao morrer com percentuais decrescentes conforme número de bênçãos, lida com crânios vermelhos/pretos, Amulet of Loss e bênçãos de aventureiro automáticas. Sistema sofisticado de economia de sobrevivência típico de MMO Tibia-like.

**Caminho Original**: `data/libs/systems/blessing.lua`

**Dependências**:
- GameStore (bênçãos compráveis)
- Player object (extensão via metatable)
- Config manager (settings de servidor)

## 📄 Visão Geral do Código

### Resumo Executivo

O módulo `blessing.lua` implementa **sistema econômico de proteção de morte** baseado em 8 bênçãos diferentes, cada uma reduzindo perda de itens/skills em percentuais específicos. Quando jogador morre sem crânio, percentual de itens perdidos depende do número de bênçãos possuído (0 bênçãos = 100% perda, 5+ bênçãos = 0% perda). Custa variável por nível (2k até 30, 200/260 multiplier até 120, 75/100 multiplier acima). Suporta múltiplas compras em batch, bênçãos de aventureiro automáticas para baixo level, sistema Inquisition NPC com preço multiplicado, e integração com Amulet of Loss para proteção adicional.

## Detalhes das Funções Globais

### 1. PlayerDeath(player, corpse, killer) - FUNÇÃO CRÍTICA

Evento disparado quando jogador morre. Determina loot drop baseado em crânio, Amulet of Loss e contagem de bênçãos.

**Parâmetros**:
- player (userdata): Jogador que morreu
- corpse (userdata): Container corpse created
- killer (userdata): Quem matou (pode ser nil)

**Retorna**: 
- (boolean): true (sempre processa)

**Lógica de Decisão**:

```lua
local hasAol = (player:getSlotItem(CONST_SLOT_NECKLACE) and 
                player:getSlotItem(CONST_SLOT_NECKLACE):getId() == ITEM_AMULETOFLOSS)
local hasSkull = table.contains({ SKULL_RED, SKULL_BLACK }, player:getSkull())
local currBlessCount = player:getBlessings()

if hasSkull then
    -- Crânio é absoluto: perda 100%
    Blessings.DropLoot(player, corpse, 100, true)
elseif #currBlessCount < 5 and not hasAol then
    -- Sem amulet e < 5 bênçãos: usa perda baseada em count
    local equipLossChance = Blessings.LossPercent[#currBlessCount].item
    Blessings.DropLoot(player, corpse, equipLossChance)
end

-- Garante backpack
if not player:getSlotItem(CONST_SLOT_BACKPACK) then
    player:addItem(ITEM_BAG, 1, false, CONST_SLOT_BACKPACK)
end
```

**Prioridade**:

1. **Red/Black Skull**: 100% perda obrigatória
2. **Amulet of Loss**: 0% perda (proteção total)
3. **5+ Bênçãos**: 0% perda de items
4. **< 5 Bênçãos**: Perda conforme Blessings.LossPercent[count].item

### 2. DropLoot(player, corpse, chance, skulled) - FUNÇÃO COMPLEXA

Implementa lógica de queda de loot com chance probabilística e remoção de store items se crânio.

**Parâmetros**:
- player (userdata): Jogador
- corpse (userdata): Corpse destination
- chance (number): Percentual de chance (0-100)
- skulled (boolean, opcional): Se true, força 100%

**Algoritmo de Drop**:

```lua
-- Multiplier para evitar floating point
local multiplier = 100
chance = chance * multiplier

-- Loop slots HEAD até AMMO
for i = CONST_SLOT_HEAD, CONST_SLOT_AMMO do
    local item = player:getSlotItem(i)
    if item then
        -- Container tem 1x chance, equipment tem 0.1x chance
        local thisChance = item:isContainer() and chance or (chance / 10)
        local thisRandom = math.random(100 * multiplier)
        
        if skulled or thisRandom <= thisChance then
            item:moveTo(corpse)  -- Drop para corpse
        end
    end
end
```

**Peculiaridade**: Containers são **sempre** dropped, items normais têm 10x menos chance

**Store Inbox Removal** (se skulled + config enable):

```lua
if skulled and Blessings.Config.SkulledDeathLoseStoreItem then
    local inbox = player:getStoreInbox()
    -- Loop inbox, coleta UIDs, remove todos
    for i = 0, inbox:getSize() do
        local item = inbox:getItem(i)
        if item then
            toBeDeleted[#toBeDeleted + 1] = item.uid
        end
    end
    -- Delete todos coletados
end
```

### 4. getBlessingCost(level, byCommand, enhanced) - FUNÇÃO DINÂMICA

Calcula custo de bênção regular ou enhanced conforme nível do jogador.

**Parâmetros**:
- level (number): Nível do jogador
- byCommand (boolean, opcional): Se true, aplica taxa comando
- enhanced (boolean, opcional): Se true, usa preços Enhanced

**Retorna**: 
- (number): Custo calculado

**Brackets de Nível**:

```lua
if level <= 30 then
    cost = 2000  -- Flat rate para low level
elseif level >= 120 then
    -- High level: base + multiplier * (level - 120)
    local base_cost = enhanced and 26000 or 20000
    local multiplier = enhanced and 100 or 75
    cost = base_cost + multiplier * (level - 120)
else
    -- Mid level: multiplier * (level - 20)
    local multiplier = enhanced and 260 or 200
    cost = multiplier * (level - 20)
end

return byCommand and Blessings.getCommandFee(cost) or cost
```

**Exemplos**:
- Level 10: 2,000 gold
- Level 50: 200 * (50 - 20) = 6,000 gold
- Level 120: 20,000 + 75 * 0 = 20,000 gold
- Level 150: 20,000 + 75 * 30 = 22,250 gold

### 6. useCharm(player, item) - FUNÇÃO CHARM RITUAL

Processa uso de charm item para ganhar bênção.

**Parâmetros**:
- player (userdata): Jogador usando item
- item (userdata): Item charm usado

**Retorna**: 
- (boolean): true (consume item)

**Lógica**:

```lua
-- Procura blessing que corresponde ao charm itemid
for index, value in pairs(Blessings.All) do
    if item.itemid == value.charm then
        if player:hasBlessing(value.id) then
            player:say("You already possess this blessing.", TALKTYPE_MONSTER_SAY)
            return true
        end
        
        player:addBlessing(value.id, 1)
        player:sendTextMessage(MESSAGE_EVENT_ADVANCE, value.name .. " protects you.")
        player:getPosition():sendMagicEffect(CONST_ME_LOSEENERGY)
        item:remove(1)  -- Consume item
        return true
    end
end
```

### 10. BuyAllBlesses(player) - FUNÇÃO TRANSAÇÃO COMPLEXA

Compra todas as bênçãos faltando com validações sofisticadas.

**Parâmetros**:
- player (userdata): Jogador comprando

**Retorna**: 
- (boolean): true

**Validações**:

1. **PZ/Battle Check**:
   ```lua
   if not Tile(player:getPosition()):hasFlag(TILESTATE_PROTECTIONZONE) 
      and (player:isPzLocked() or player:getCondition(CONDITION_INFIGHT)) then
       player:sendCancelMessage("You can't buy bless while in battle.")
       return true
   end
   ```

2. **Already Blessed Check**:
   ```lua
   if missingBlessAmt == 0 then
       player:sendCancelMessage("You are already blessed.")
       return true
   end
   ```

3. **Funds Check**:
   ```lua
   if not player:removeMoneyBank(totalCost) then
       player:sendCancelMessage("You don't have enough money...")
       return true
   end
   ```

**Cálculo de Custo**:

```lua
local totalCost = 0
for _, bless in ipairs(missingBless) do
    -- Enhanced blessings (id >= 7) têm enhanced = true
    totalCost = totalCost + Blessings.getBlessingCost(player:getLevel(), true, bless.id >= 7)
end

if not hasToF then
    totalCost = totalCost + Blessings.getPvpBlessingCost(player:getLevel(), true)
end
```

**Efeito**:

```lua
metrics.addCounter("balance_decrease", totalCost, {
    player = player:getName(),
    context = "blessings",
})

for _, bless in ipairs(missingBless) do
    player:addBlessing(bless.id, 1)
end

player:getPosition():sendMagicEffect(CONST_ME_HOLYAREA)
```

### 11. Player.getBlessings(self, filter, hasblessingFilter) - METATABLE FUNÇÃO

Query de bênçãos com filtros customizáveis.

**Parâmetros**:
- self (Player): Jogador (implicit)
- filter (function, opcional): Filtro sobre de bênção (default: só losscount)
- hasblessingFilter (function, opcional): Filtro se jogador tem bênção

**Retorna**: 
- (table): Array de bênçãos que match filtros

**Default Filters**:

```lua
if filter == nil then
    filter = function(b)
        return b.losscount  -- Só bênçãos que contam perda
    end
end

if hasblessingFilter == nil then
    hasblessingFilter = function(p, b)
        return p:hasBlessing(b)  -- Que o jogador tem
    end
end
```

### 12. Player.addMissingBless(self, all, tof) - METATABLE FUNÇÃO

Auto-adiciona bênçãos faltando (para leveling ou admin).

**Parâmetros**:
- self (Player): Jogador (implicit)
- all (boolean, opcional): true = todas, false = regular only
- tof (boolean, opcional): true = também adiciona Twist of Fate

**Retorna**: 
- (void)

**Lógica**:

```lua
for k, v in pairs(Blessings.All) do
    if all or (v.type == Blessings.Types.REGULAR) 
       or (tof and v.type == Blessings.Types.PvP) then
        if not self:hasBlessing(k) then
            self:addBlessing(k, 1)
        end
    end
end

self:sendBlessStatus()  -- Atualiza UI
```

## 📚 Conclusão

O módulo `blessing.lua` é exemplo sofisticado de **sistema econômico de sobrevivência** típico de MMO Tibia-like, onde morte tem consequências financeiras mitigáveis através de investimento em bênçãos. O design é notável por sua **elegância em cascata**: morte sem proteção custa 100%, cada bênção reduz 10-45%, até 5 bênçãos garantem 0% perda de items.

A complexidade reside não em funções individuais, mas em **coordenação de múltiplos sistemas**: preço dinâmico que respeita brackets de nível, charge de fee de comando, proteção especial para Adventurers, multiplicador Inquisition, validação de zona, remoção de store items se crânio. O padrão de **metatable extensions** (Player.getBlessings, Player.addMissingBless) mostra como estender objetos nativos sem modificar código core.

Particularmente sofisticado é algoritmo de DropLoot que diferencia containers (sempre dropped) vs equipment (1/10 chance), prevenindo exploração de containers como "safe storage". O sistema de **charm items** implementa ritual type Tibia de usar "items de bênção" para auto-bless, enquanto **auto-blessing de low level** garante jogadores novatos não morrem sem proteção.
