## 🛠️ Informações do Arquivo

**Descrição**: Módulo de **sistema de encontros/bosses dinâmicos** que implementa framework class-based para criar encontros multi-stage complexos com suporte a spawning automático de monstros, zone-based player/monster management, broadcast de mensagens, eventos assíncronos, auto-advance condicionado (por delay ou contagem de monstros), e sistema de reset. Ideal para dungeons, eventos de boss, raids com múltiplas fases, incluindo suporte a intermissões, broadcasts, e zone events (enter/leave).

**Caminho Original**: `data/libs/systems/encounters.lua`

**Dependências**:
- Zone system (Zone object para area management)
- Player/Monster/Game system (spawning, counting, removal)
- Event system (addEvent, stopEvent)
- Utility functions (ParseDuration para formatação de delay)
- Logger system (debug logging)
- Set class (tabela para armazenar events)

<Aside>
Este módulo implementa **paradigma de encontros dinâmicos** típico de MMOs, separando lógica de stages (fases), permitindo construir dungeons complexas via fluent API (addStage, addIntermission, addSpawnMonsters, etc).
</Aside>

## 📄 Visão Geral do Código

### Resumo Executivo

O módulo `encounters.lua` implementa **framework sofisticado de encontros multi-stage** com 2 classes principais (EncounterStage e Encounter) que usa metatable metatables para instanciação, suporta stages com callbacks (start, tick, finish), auto-advance com delay ou contagem de monstros, spawning automático de monstros em posições aleatórias com suporte a limits de tempo, broadcast de mensagens a jogadores (zone-wide ou global), zone events (enter/leave) para auto-start, e reset automático ao sair de todos os jogadores. Sistema de eventos assíncronos integrado permite delays de spawn com efeitos visuais (CONST_ME_TELEPORT) antes da aparição.

## Classes e Métodos

### Classe EncounterStage

**Estrutura Interna**:

```lua
EncounterStage = {
    encounter = Encounter,    -- Referência ao Encounter pai
    start = function() end,   -- Callback ao entrar stage
    tick = function() end,    -- Callback a cada tick (opcional)
    finish = function() end,  -- Callback ao sair stage
}
```

#### EncounterStage:autoAdvance(config)

Auto-avança para próximo stage com configuração flexível.

**Parâmetros**:
- config (AutoAdvanceConfig | number | string): Configuração ou delay direto

**Estrutura de Config**:
```lua
{
    delay = number|string,     -- Delay até próximo stage (default: 50ms = instant)
    monstersKilled = boolean   -- Se true, avança quando monstros = 0
}
```

**Implementação**:

```lua
function EncounterStage:autoAdvance(config)
    if type(config) == "number" or type(config) == "string" then
        config = { delay = config }
    end
    
    local originalStart = self.start
    local delay = config.delay
    local delayElapsed = false
    
    function self.start()
        delay = delay or 50  -- 50ms mínimo (instant)
        if originalStart then
            originalStart()
        end
        self.encounter:addEvent(function()
            delayElapsed = true
            if not config.monstersKilled then
                self.encounter:nextStage()
            end
        end, delay)
    end
    
    if config.monstersKilled then
        local originalTick = self.tick
        function self.tick()
            if originalTick then
                originalTick()
            end
            if delayElapsed and self.encounter:countMonsters() == 0 then
                self.encounter:nextStage()
            end
        end
    end
end
```

**Padrão**: Wrapping de callbacks para injetar auto-advance logic.

#### addEvent(callable, delay, ...)

Agenda evento assíncrono com rastreamento.

**Parâmetros**:
- callable (function): Função a executar
- delay (number | string): Delay em ms ou ParseDuration string
- ... (variadic): Argumentos passthrough para callable

**Retorna**: Event ID (pode ser usado com stopEvent)

**Implementação**:

```lua
function Encounter:addEvent(callable, delay, ...)
    local event = addEvent(function(callable, ...)
        pcall(callable, ...)
        self.events:remove(event)  -- Remove do registry após exec
    end, ParseDuration(delay), callable, ...)
    self.events:insert(event)
    return event
end
```

**Peculiaridade**: Wrapping com pcall garante segurança; evento auto-removido após execução.

#### enterStage(stageNumber, abort)

Transiciona para novo stage com callbacks.

**Parâmetros**:
- stageNumber (number): Número do stage
- abort (boolean, opcional): Se true, pula callback finish da stage atual

**Retorna**: boolean (sucesso)

**Fluxo**:

```lua
function Encounter:enterStage(stageNumber, abort)
    -- 1. CHAMAR FINISH DA STAGE ANTERIOR (se não abort)
    if not abort then
        local currentStage = self:getStage(self.currentStage)
        if currentStage and currentStage.finish then
            currentStage:finish()
        end
    end
    
    -- 2. CANCELAR EVENTOS ASSÍNCRONOS ANTIGOS
    self:cancelEvents()
    
    -- 3. RETORNAR AO ESTADO UNSTARTED
    if stageNumber == Encounter.unstarted then
        self.currentStage = Encounter.unstarted
        return true
    end
    
    -- 4. BUSCAR STAGE E CHAMAR START
    local stage = self:getStage(stageNumber)
    if not stage then
        logger.error("Encounter:enterStage - stage {} not found", stageNumber)
        return false
    end
    
    self.currentStage = stageNumber
    if stage.start then
        stage:start()
    end
    
    return true
end
```

#### spawnMonsters(config)

Spawna monstros com delay, efeitos visuais, event registration, e time limits.

**Parâmetros**:
- config (SpawnMonsterConfig): Configuração de spawn

**Estrutura SpawnMonsterConfig**:

```lua
{
    name = string|string[],          -- Nome do monstro (ou array aleatório)
    amount = number|nil,             -- Número monstros (ou positions para positions)
    position = Position|nil,         -- Posição única (replicada amount vezes)
    positions = Position[]|nil,      -- Array de posições customizadas
    event = string|string[]|nil,     -- Event handler(s) a registrar
    spawn = function|nil,            -- Callback(monster) customizado
    timeLimit = number|nil           -- Tempo em ms antes auto-remove
}
```

**Lógica de Posições**:

```lua
if amount and amount > 0 then
    positions = {}
    for _ = 1, amount do
        if config.position then
            table.insert(positions, config.position)  -- Repetir posição
        else
            table.insert(positions, self:getSpawnZone():randomPosition())  -- Random
        end
    end
end
```

**Spawning Delay**:

```lua
-- Se timeToSpawnMonsters >= 1000ms, enviar efeitos visuais a cada 1000ms
if self.timeToSpawnMonsters >= 1000 then
    for i = 1, self.timeToSpawnMonsters / 1000 do
        self:addEvent(function(position)
            position:sendMagicEffect(CONST_ME_TELEPORT)
        end, i * 1000, position)
    end
end
```

**Spawn Real**:

```lua
self:addEvent(function(name, position, event, spawn, timeLimit)
    local monster = Game.createMonster(name, position)
    if not monster then return false end
    
    monster:setRewardBoss()
    
    if spawn then
        spawn(monster)
    end
    
    if event then
        if type(event) == "string" then event = { event } end
        for _, event in ipairs(event) do
            monster:registerEvent(event)
        end
    end
    
    if timeLimit then
        self:addEvent(function(monsterId)
            local monster = Monster(monsterId)
            if monster then monster:remove() end
        end, config.timeLimit, monster:getID())
    end
end, self.timeToSpawnMonsters, name, position, config.event, config.spawn, config.timeLimit)
```

#### broadcast(...)

Envia mensagem de texto a jogadores.

**Parâmetros**:
- ... (variadic): Argumentos para sendTextMessage (type, message, etc)

**Comportamento**:
- Se global=true: Todos jogadores do servidor
- Se global=false: Apenas jogadores na zone

```lua
function Encounter:broadcast(...)
    if self.global then
        for _, player in ipairs(Game.getPlayers()) do
            player:sendTextMessage(...)
        end
        return
    end
    self:getZone():sendTextMessage(...)
end
```

#### Métodos Convenience (adicionam stages pré-feitas)

**addIntermission(interval)**
- Pausa por interval, depois auto-avança

**addBroadcast(message, type)**
- Envia mensagem, depois auto-avança imediatamente

**addSpawnMonsters(configs)**
- Spawna monstros, continua até próximo stage (não auto-avança)
- configs pode ser array ou single config

**addRemoveMonsters / addRemovePlayers**
- Remove tudo de uma zona, depois auto-avança

---

#### startOnEnter()

Auto-inicia encontro quando players entram zone.

**Comportamento**:
- Cria ZoneEvent listener
- afterEnter: inicia encontro se jogador não tem IgnoredByMonsters
- afterLeave: reseta se último jogador sai (ignora IgnoredByMonsters)

#### register()

Registra encontro globalmente em Encounter.registry.

**Retorna**: boolean (sempre true)

## 🔄 Padrões de Uso

### Padrão 1: Criar Encontro Simples com Stages

```lua
local encounter = Encounter("goblin_cave", {
    zone = Zone("cave"),
    spawnZone = Zone("cave_spawn"),
    timeToSpawnMonsters = "2s"
})

encounter:addBroadcast("Goblins approaching!")
encounter:addSpawnMonsters({
    name = "Goblin",
    amount = 5,
})
encounter:addIntermission("5s")
encounter:addBroadcast("Final wave!")
encounter:addSpawnMonsters({
    name = {"Goblin", "Goblin Archer"},
    amount = 3,
})

encounter:register()
encounter:startOnEnter()
```

### Padrão 2: Stage com Autoadvance (Delay Base)

```lua
encounter:addStage({
    start = function()

        encounter:spawnMonsters({
            name = "Storm Dragon",
            positions = {pos1, pos2, pos3}
        })
    end
}):autoAdvance("10s")  -- Auto-avança após 10s
```

### Padrão 3: Auto-Advance ao Matar Todos Monstros

encounter:addStage({

    timeLimit = 30000,  -- 30s, depois auto-remove

## 📚 Conclusão

O módulo `encounters.lua` implementa **framework elegante e poderoso de encontros dinâmicos** que abstrai complexidade de multi-stage encounters em uma API fluente e intuitiva. Design notável por separação de concerns: stages como unidades de callback (start/tick/finish), spawning como configuração declarativa, zone management como queries simples.

Particularmente sofisticado é sistema de **auto-advance condicional**: não apenas delay-based (simples timer), mas também monsters-killed (verdadeira sincronização de gameplay), permitindo encontros que respondem dinamicamente ao progresso do player. O padrão de autoAdvance() como wrapper de callbacks garante non-invasive injection sem modificar stage configs originais.

A **metatable factory pattern** (Encounter(name, config)) permite reutilização de encontros pelo nome, essencial para respawn de bosses ou rotas compartilhadas entre múltiplas salas. O sistema de events com cleanup automático (pcall na execução, remove do Set) previne memory leaks mesmo com cancelation manual.

<Aside type="caution">
**Atenção Crítica**:
- **Zone Names Persist**: self.zone e self.spawnZone armazenam nome (string), não referência - permite serialização
- **Stage Numbers 1-indexed**: currentStage começa em 1, não 0 (unstarted = 0)
- **monstersKilled Não Conta**: countMonsters sem filtro retorna TODOS monstros na zone (não apenas spawnados)
- **autoAdvance Injeção**: Substitui callbacks start/tick da stage - callbacks originais perdidos se não preservados
- **Abort Skip Finish**: enterStage(stageNum, true) pula finish() da atual - cuidado com cleanup
- **Global Broadcast Custo**: broadcast com global=true itera TODOS jogadores do servidor - pesado
- **TimeToSpawnMonsters Mín**: Hardcoded minimum 50ms (instant) - valores maiores geram efeitos visuais
- **No Persistence**: Events, currentStage, registered não persistem cross-restart
- **IgnoredByMonsters Check**: startOnEnter ignora players com flag IgnoredByMonsters (GMs, admins)
</Aside>

<Aside type="note">
**Notas de Manutenção**:
- Encounter.unstarted = 0 é constante, não deve ser usado como stageNumber válido
- Zone:randomPosition() em spawnZone deve estar implementada para amount-based spawn
- ParseDuration() suporta "3s", "2m", "1h" e números ms direto
- Game.createMonster() deve ser global (não method)
- Monster:setRewardBoss() marca monstro como reward boss
