## 🛠️ Informações do Arquivo

Módulo que define **constants globais do sistema de loja do Canary**: 16 tabelas mapeando tipos de ofertas, ações, estados, packet IDs, valores padrão, e limites. Developed por Cjaker, metabob, Rick, Dudantas. Version 2.0 (atualizado 21-10-2025).

**Caminho Original**: `data/libs/gamestore/constants.lua`

<Aside type="tip">
O arquivo `constants.lua` é **central constants repository** para todo sistema de loja. Define 29 tipos de ofertas, packet network IDs, estados de items, erros, defaults, e limites. Essencial para qualquer operação com gamestore.
</Aside>

## 📄 Visão Geral do Código

### Resumo Executivo

Arquivo com **16 submaps de constants**:

1. **OfferTypes** (29): Tipos de ofertas (items, outfits, mounts, bênçãos, etc)
2. **SubActions** (16): Sub-ações especiais para itens (bênçãos, prey, hireling, etc)
3. **ActionType** (6): Tipos de ação na loja (abrir categoria, oferta, etc)
4. **CoinType** (2): Tipos de moeda (normal, transferível)
5. **Kv** (2): Key-value pairs para storage
6. **ConverType** (5): Tipos de conversão/visualização
7. **ConfigureOffers** (2): Estados de configuração
8. **ClientOfferTypes** (3): Tipos para protocol cliente
9. **HistoryTypes** (3): Tipos de histórico de transações
10. **States** (4): Estados de items (novo, venda, timed)
11. **StoreErrors** (5): Tipos de erro
12. **ServiceTypes** (4): Tipos de serviço
13. **SendingPackets** (8): Packet IDs do servidor para cliente
14. **RecivedPackets** (8): Packet IDs do cliente para servidor
15. **ExpBoostValues** (5): Durações em minutos para XP boosts
16. **ItemLimit** (4): Limites de quantidade por item
17. **DefaultDescriptions** (8): Descrições padrão de items
18. **DefaultValues** (1): Valores padrão da UI

Todas constantes agrupadas em `GameStore` table. Total de 150+ constantes mapeadas.

### Estrutura de Submaps

```
GameStore (Module)
├── OfferTypes (29)
```

## 🌐 Network Packets

### SendingPackets (Servidor → Cliente) - 8 Packets

| Nome | Hex | Dec | Propósito |
|------|-----|-----|-----------|
| S_CoinBalance | 0xDF | 223 | Saldo de moedas |
| S_StoreError | 0xE0 | 224 | Erro da loja |
| S_RequestPurchaseData | 0xE1 | 225 | Solicitar dados de compra |
| S_CoinBalanceUpdating | 0xF2 | 242 | Atualizar saldo |
| S_OpenStore | 0xFB | 251 | Abrir loja |
| S_StoreOffers | 0xFC | 252 | Listar ofertas |
| S_OpenTransactionHistory | 0xFD | 253 | Abrir histórico |
| S_CompletePurchase | 0xFE | 254 | Compra completa |

**Uso**:
```lua
-- Send coin balance to client
local msg = NetworkMessage()
msg:addByte(GameStore.SendingPackets.S_CoinBalance)
msg:addU64(playerCoins)
player:sendExtendedOpcode(0, msg:getString())
```

## 🔄 Padrões de Uso

### Padrão 1: Validar Tipo de Oferta

```lua
function isValidOfferType(offerType)
    for _, type in pairs(GameStore.OfferTypes) do
        if type == offerType then
            return true
        end
    end
    return false
end

if isValidOfferType(offer.type) then
    -- Process offer
end
```

### Padrão 2: Get Randomized Description

```lua
function getOfferDescription(offer)
    local descriptions = GameStore.DefaultDescriptions[offer.descKey]
    if descriptions then
        return descriptions[math.random(#descriptions)]
    end
    return "No description available"
end

local desc = getOfferDescription({descKey = "OUTFIT"})
```

### Padrão 3: Check Item Purchase Limit

```lua
function canPurchaseMore(itemType, playerCount)

end
```

<Aside type="note">
**Nota de Manutenção**: Arquivo é pura constants/configuration. Nenhuma função ou lógica - apenas dados. Mudanças aqui afetam todo gamestore. Packet IDs devem ser sincronizados entre servidor e cliente. OfferTypes 1-27 são sequenciais mas type 16 está empty (evitar). ExpBoostValues keys são levels [1-5]. DefaultDescriptions keys devem corresponder a types válidos. ItemLimit aplica limites globais por tipo.

**Novas Ofertas**: Ao adicionar novo OFFER_TYPE, incrementar número e adicionar subaction se necessário. Manter sincronizado com client protocol.
</Aside>
