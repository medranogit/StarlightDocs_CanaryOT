## 🛠️ Informações do Arquivo

Módulo que implementa extensões de métodos auxiliares para a classe ItemType do engine. Fornece verificação eficiente se um item utiliza um slot específico (cabeça, pescoço, mochila, armadura, etc) através de operações bitwise contra a posição de slot do item.

<Aside type="tip">
O arquivo `itemtype.lua` é **minimalista mas essencial**, encapsulando operação bitwise complexa em interface simples. Útil em validações de equipamento e checks de compatibilidade de slots.
</Aside>

## 📄 Visão Geral do Código

### Resumo Executivo

O arquivo `itemtype.lua` é um **exemplo de module simplista** que implementa apenas **1 método extension** e **1 variável local**. Apesar del tamanho pequeno, demonstra padrão de design importante em sistemas de RPG: verificação de bits para flags.

O sistema de slots usa **bitwise flags** para representar múltiplos slots que um item pode ocupar (ex: um anel pode estar no slot anel OU ammo):

```
SLOTP_HEAD     = 1
SLOTP_NECKLACE = 2
SLOTP_BACKPACK = 4
SLOTP_ARMOR    = 8
... etc
```

Um item com `slotPosition = 5` ocupa **SLOTP_HEAD + SLOTP_NECKLACE** (1 + 4).

### Estrutura de Funcionalidades

```
ItemType Module Extensions
├── Local Variables
│   └── slotBits (table)
│       └── Mapping CONST_SLOT_* → SLOTP_*
└── Method Extension
    └── ItemType.usesSlot(self, slot) → boolean
        └── Verifica se item pode usar dado slot
```

## 📋 Variáveis Locais

### `slotBits` (Table)

Tabela local que mapeia constantes de slot da UI para flags bitwise de posição.

**Tipo**: Variável Local  
**Escopo**: Arquivo (não acessível externamente)

**Definição**:
```lua
local slotBits = {
    [CONST_SLOT_HEAD] = SLOTP_HEAD,
    [CONST_SLOT_NECKLACE] = SLOTP_NECKLACE,
    [CONST_SLOT_BACKPACK] = SLOTP_BACKPACK,
    [CONST_SLOT_ARMOR] = SLOTP_ARMOR,
    [CONST_SLOT_RIGHT] = SLOTP_RIGHT,
    [CONST_SLOT_LEFT] = SLOTP_LEFT,
    [CONST_SLOT_LEGS] = SLOTP_LEGS,
    [CONST_SLOT_FEET] = SLOTP_FEET,
    [CONST_SLOT_RING] = SLOTP_RING,
    [CONST_SLOT_AMMO] = SLOTP_AMMO,
}
```

**Constantes de Slot (CONST_SLOT_)**:
- `CONST_SLOT_HEAD`: índice 1 (cabeça)
- `CONST_SLOT_NECKLACE`: índice 2 (pescoço)
- `CONST_SLOT_BACKPACK`: índice 3 (mochila)
- `CONST_SLOT_ARMOR`: índice 4 (armadura)
- `CONST_SLOT_RIGHT`: índice 5 (mão direita)
- `CONST_SLOT_LEFT`: índice 6 (mão esquerda)
- `CONST_SLOT_LEGS`: índice 7 (pernas)
- `CONST_SLOT_FEET`: índice 8 (pés)
- `CONST_SLOT_RING`: índice 9 (anel)
- `CONST_SLOT_AMMO`: índice 10 (munição)

**Flags de Posição (SLOTP_)**:
- `SLOTP_HEAD`: bit 1
- `SLOTP_NECKLACE`: bit 2
- `SLOTP_BACKPACK`: bit 4
- `SLOTP_ARMOR`: bit 8
- etc. (cada uma é potência de 2)

**Propósito**: Centralizar mapeamento para facilitar manutenção e evitar hardcoding.

## 🔧 Métodos de Extensão

### `ItemType.usesSlot(self, slot)`

Verifica se um ItemType pode ser equipado em um slot específico.

**Tipo**: Method Extension  
**Parâmetros**:
- `self` (ItemType): ItemType a verificar
- `slot` (number): Uma das constantes CONST_SLOT_*

**Retorna**: boolean (true se pode usar slot, false caso contrário)

**Implementação**:
```lua
function ItemType.usesSlot(self, slot)
    return bit.band(self:getSlotPosition(), slotBits[slot] or 0) ~= 0
end
```

**Operação Bitwise**:
- `self:getSlotPosition()`: retorna bitmask do ItemType (ex: 5 = HEAD + NECKLACE)
- `slotBits[slot]`: busca flag bitwise do slot (ex: SLOTP_HEAD = 1)
- `bit.band()`: operação AND bitwise
- Resultado não-zero = bit está setado

**Exemplos**:
```lua
local swordType = ItemType(2400)  -- Iron Sword

-- Verificar se pode usar em mão direita
if swordType:usesSlot(CONST_SLOT_RIGHT) then
    print("Espada pode ser equipada na mão direita")
end

-- Verificar se pode usar em cabeça (deve retornar false)
if not swordType:usesSlot(CONST_SLOT_HEAD) then
    print("Espada não pode ser equipada na cabeça")
end
```

**Exemplo de Validação em Equipamento**:
```lua
local function canEquipItem(player, item, slot)
    local itemType = item:getType()
    
    -- Verificar se tipo suporta o slot
    if not itemType:usesSlot(slot) then
        return false, "Item cannot be equipped in this slot"
    end
    
    -- Verificar level require
    if player:getLevel() < itemType:getReqLevel() then
        return false, "You need level " .. itemType:getReqLevel()
    end
    
    -- Verificar vocation require
    if itemType:getReqVocation() ~= "" and 
       not itemType:getReqVocation():find(player:getVocation():getName()) then
        return false, "Your vocation cannot use this item"
    end
    
    return true
end
```

## 🎯 Casos de Uso

### Caso 1: Validação de Equip

```lua
local function validateEquipment(player, item, slot)
    local itemType = item:getType()
    
    if not itemType:usesSlot(slot) then
        player:sendCancelMessage("You cannot equip this item in that slot")
        return false
    end
    
    return true
end
```

### Caso 2: Listar Slots Disponíveis

```lua
local function getSlotsForItemType(itemType)
    local slots = {}
    local slotNames = {
        [CONST_SLOT_HEAD] = "Head",
        [CONST_SLOT_NECKLACE] = "Necklace",
        [CONST_SLOT_BACKPACK] = "Backpack",
        [CONST_SLOT_ARMOR] = "Armor",
        [CONST_SLOT_RIGHT] = "Right Hand",
        [CONST_SLOT_LEFT] = "Left Hand",
        [CONST_SLOT_LEGS] = "Legs",
        [CONST_SLOT_FEET] = "Feet",
        [CONST_SLOT_RING] = "Ring",
        [CONST_SLOT_AMMO] = "Ammo",
    }
    
    for slot, name in pairs(slotNames) do
        if itemType:usesSlot(slot) then
            table.insert(slots, name)
        end
    end
    
    return slots
end

-- Uso
local swordType = ItemType(2400)
local slots = getSlotsForItemType(swordType)
print("Sword can be equipped in: " .. table.concat(slots, ", "))
```

### Caso 3: Proteção contra Equip Inválido

```lua
local function equipItem(player, item, slot)
    if not item:getType():usesSlot(slot) then
        print("ERROR: Item " .. item:getId() .. " cannot use slot " .. slot)
        return false
    end
    
    return player:equipItem(item, slot)
end
```

## 🔍 Aprofundamento em Bitwise

### Como os Bits Funcionam

```
Cada slot é representado por um bit (potência de 2):

SLOTP_HEAD     = 0b0000000001 = 1
SLOTP_NECKLACE = 0b0000000010 = 2
SLOTP_BACKPACK = 0b0000000100 = 4
SLOTP_ARMOR    = 0b0000001000 = 8
...

Um item que pode usar HEAD e ARMOR tem:
slotPosition = 0b0000001001 = 9 (1 + 8)

Verificação com bit.band:
bit.band(9, 1) = 1 (não-zero, usa HEAD) ✓
bit.band(9, 4) = 0 (zero, não usa BACKPACK) ✗
```

### Vantagens do Bitwise

1. **Eficiência**: Operação O(1), sem loops
2. **Espaço**: Um número inteiro representa 32 flags
3. **Semântica**: Perfeito para "pode usar múltiplos slots"

## ✅ Checkpoint de Aprendizagem

### Conceitos Principais

1. **Bitwise Flags**: Usar bits como flags para múltiplas propriedades booleanas
2. **Encapsulamento**: Esconder complexidade bitwise em método simples
3. **Constant Mapping**: Mapear UI constants para flags internas

### Padrão Identificado

- **Bitfield Pattern**: Representar múltiplas propriedades booleanas em um inteiro
- **Encapsulation**: Método simples `usesSlot()` esconde `bit.band()` complexo
- **Lazy Lookup**: `slotBits[slot] or 0` retorna 0 para slot inválido

### Quando Usar Bitwise

✅ Múltiplas propriedades booleanas (slots, spells, imunidades)
❌ Strings, valores contínuos, listas dinâmicas
