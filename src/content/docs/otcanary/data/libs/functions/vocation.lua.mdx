## 📄 Visão Geral do Código

### Resumo Executivo

Arquivo com **1 tabela global + 1 função**:

1. **VOCATION Table** (3 submaps):
   - ID: Server-side vocation IDs (0-10)
   - CLIENT_ID: Client-side mapping (0-15)
   - BASE_ID: Base vocation IDs only (0, 1, 2, 3, 4, 9)

2. **Vocation.getBase(self)**: Resolve base vocation via demotion chain traversal

O design usa **nested tables para ID mapping**, **vocation demotion chain traversal**, e **server/client ID separation**. Suporta 5 base vocações (SORCERER, DRUID, PALADIN, KNIGHT, MONK) + 6 promoções (MASTER_SORCERER, ELDER_DRUID, ROYAL_PALADIN, ELITE_KNIGHT, EXALTED_MONK, MONK promotional).

```lua
	EXALTED_MONK = 10,
}
```

**Vocações (11 total)**:
- **5 Base**: NONE, SORCERER, DRUID, PALADIN, KNIGHT, MONK
- **6 Promoções**: MASTER_SORCERER, ELDER_DRUID, ROYAL_PALADIN, ELITE_KNIGHT, EXALTED_MONK

**Uso**:

### VOCATION.CLIENT_ID

Mapa de **vocation IDs client-side** (para rendering no cliente).

**Estrutura**:
```lua
VOCATION.CLIENT_ID = {
	NONE = 0,
	KNIGHT = 1,
	PALADIN = 2,
	SORCERER = 3,
	DRUID = 4,
	MONK = 5,
	ELITE_KNIGHT = 11,
	ROYAL_PALADIN = 12,
	MASTER_SORCERER = 13,
	ELDER_DRUID = 14,
	EXALTED_MONK = 15,
}
```

**Diferenças vs SERVER ID**:
- Client usa ordem diferente (KNIGHT = 1, PALADIN = 2, SORCERER = 3, DRUID = 4)
- Server é mais sequencial (SORCERER = 1, DRUID = 2, PALADIN = 3, KNIGHT = 4)
- Promotional IDs também diferem (Server 5-8 vs Client 11-15)

**Nota**: Mapa bidirecional necessário para converti server ↔ client IDs

**Uso**:
```lua
local clientId = VOCATION.CLIENT_ID.MASTER_SORCERER  -- 13
```

## 🔧 Funções

### `Vocation.getBase(self)` → Vocation

Resolve base vocation navegando demotion chain.

**Tipo**: Função estendida  
**Parâmetro**: self (Vocation object)  
**Retorna**: Vocation (base vocation)

**Implementação**:
```lua
function Vocation.getBase(self)
	local base = self
	while base:getDemotion() do
		base = base:getDemotion()
	end
	return base
end
```

**Lógica**:
1. Inicializa base = self (current vocation)
2. Loop enquanto getDemotion() retorna valor
3. Move base para demoted vocation
4. Retorna quando nenhuma demoção exists

**Fluxo de Demoção** (exemplo):
```
ELITE_KNIGHT (ID 8)
  ↓ getDemotion()
KNIGHT (ID 4)
  ↓ getDemotion()
nil (retorna KNIGHT como base)
```

**Exemplo**:
```lua
local promoted = Vocation(VOCATION.ID.ELITE_KNIGHT)  -- Promoted vocation
local base = promoted:getBase()
print(base:getId())  -- VOCATION.ID.KNIGHT (4)

local alreadyBase = Vocation(VOCATION.ID.KNIGHT)
print(alreadyBase:getBase():getId())  -- 4 (sem mudança)
```

```lua
function getVocationName(vocId)
	for name, id in pairs(VOCATION.ID) do
		if id == vocId then
			return name
		end
	end
	return "UNKNOWN"
end

print(getVocationName(VOCATION.ID.SORCERER))  -- "SORCERER"
```

### Padrão 2: Server ↔ Client ID Conversion

```lua
function serverToClientVoc(serverId)
	for name, clientId in pairs(VOCATION.CLIENT_ID) do
		if VOCATION.ID[name] == serverId then
			return clientId
		end
	end
	return VOCATION.CLIENT_ID.NONE
end

local clientVoc = serverToClientVoc(VOCATION.ID.MASTER_SORCERER)
-- clientVoc = VOCATION.CLIENT_ID.MASTER_SORCERER (13)
```

### Padrão 3: Promotion Detection

```lua
function isPromoted(vocation)
	local base = vocation:getBase()
	return vocation:getId() ~= base:getId()
end

local promoted = Vocation(VOCATION.ID.ELITE_KNIGHT)
print(isPromoted(promoted))  -- true

local baseVoc = Vocation(VOCATION.ID.KNIGHT)
print(isPromoted(baseVoc))  -- false
```

### Padrão 4: Base Vocation Grouping

```lua
function getVocationGroup(vocation)
	local baseVoc = vocation:getBase()
	local baseId = baseVoc:getId()
	
	if baseId == VOCATION.BASE_ID.SORCERER then
		return "MAGE_CLASS"
	elseif baseId == VOCATION.BASE_ID.DRUID then
		return "HEALER_CLASS"
	elseif baseId == VOCATION.BASE_ID.PALADIN then
		return "SUPPORT_CLASS"
	elseif baseId == VOCATION.BASE_ID.KNIGHT then
		return "TANK_CLASS"
	elseif baseId == VOCATION.BASE_ID.MONK then
		return "HYBRID_CLASS"
	else
		return "UNCLASSIFIED"
	end
end

local voc = player:getVocation()
print(getVocationGroup(voc))  -- Retorna classe
```

### Padrão 5: Vocation Skill Check

```lua
function canCastSpell(player, spellVocations)
	local playerVoc = player:getVocation()
	local playerBase = playerVoc:getBase():getId()
	
	for _, requiredBase in ipairs(spellVocations) do
		if playerBase == requiredBase then
			return true
		end
	end
	return false
end

-- Spell somente para Mages/Sorcerers
local magicSpell = {VOCATION.BASE_ID.SORCERER}
if canCastSpell(player, magicSpell) then
	-- Execute spell
end
```

### Padrão 6: Demotion Chain Resolution

```lua
function getPromotionChain(vocation)
	local chain = {}
	local current = vocation
	
	while current do
		table.insert(chain, {
			id = current:getId(),
			name = current:getName()
		})
		current = current:getPromoted()  -- Próxima promoção
	end
	
	return chain
end

-- Retorna: {
--   {id: 4, name: "Knight"},
--   {id: 8, name: "Elite Knight"}
-- }
```

<Aside type="note">
**Nota de Manutenção**: VOCATION.ID é autoridade no servidor - use para todas validações internas. VOCATION.CLIENT_ID é somente para renderização cliente - não use para comparações no servidor. VOCATION.BASE_ID contém somente 5 base vocations (0, 1, 2, 3, 4, 9) - use para detetar promoção. Vocation.getBase() navega demotion chain - cada promoção tem uma demoção, base vocations retornam self. getBase().getId() sempre retorna um ID em VOCATION.BASE_ID. Mapping não é 1:1 entre schemes - necessário converter explicitamente. Server = 0-10, Client = 0-15 (gaps em client). Base IDs não são contíguos (0, 1, 2, 3, 4 depois 9).
</Aside>
