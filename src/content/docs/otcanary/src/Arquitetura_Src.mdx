# 🏗️ Arquitetura - Source Code (C++)

Guia completo sobre a arquitetura e estrutura técnica do código-fonte **C++** do servidor OTServ Canary. Entenda como o servidor é organizado, quais são os módulos principais e como interagem entre si.

---

## 🎯 Sobre o Código-Fonte

<Card title="O que é?" icon="information">
A pasta `src/` contém todo o **código-fonte C++** que compila para o executável do servidor Canary. É estruturada em **módulos temáticos** que juntos formam um servidor MMORPG completo:

- **Gerenciamento de Contas** (Account System)
- **Criaturas** (Players, Monsters, NPCs - a "vida" do mundo)
- **Sistema de Jogo** (Combate, movimento, efeitos)
- **Banco de Dados** (Persistência de dados)
- **Rede/Socket** (Comunicação com clientes)
- **Sistema de Itens** (Equipamentos, consumíveis)
- **Mapa** (Carregamento e gerenciamento do mundo)
- **Scripts Lua** (Programação do lado do servidor)

O código C++ forma o **núcleo performático** do servidor, enquanto scripts Lua permitem customização sem recompile.
</Card>

<Card title="Tecnologia Stack" icon="wrench">
- **Linguagem**: C++ (C++17/20 moderno)
- **Build System**: CMake
- **Compilador**: Microsoft Visual C++ (Windows) / GCC (Linux)
- **Banco de Dados**: MySQL/MariaDB via biblioteca nativa
- **Scripts**: Lua 5.4 integrado
- **Networking**: Socket.IO / Asio (async networking)
- **Serialização**: Protocol Buffers (protobuf)
- **Criptografia**: RSA (RSA.cpp), Argon2 (Argon.cpp)
</Card>

## 🔍 Visão Geral da Arquitetura

<Card title="Arquitetura em Camadas" icon="layers">

O servidor é estruturado em **camadas hierárquicas**:

```
┌─────────────────────────────────────────────────────┐
│ NETWORK LAYER          (server/ - Sockets/Protocol) │
├─────────────────────────────────────────────────────┤
│ GAME LOGIC LAYER       (game/ - Regras e Mecânicas) │
├─────────────────────────────────────────────────────┤
│ ENTITY LAYER           (creatures/, items/ - Dados) │
├─────────────────────────────────────────────────────┤
│ PERSISTENCE LAYER      (database/, io/ - Storage)   │
├─────────────────────────────────────────────────────┤
│ UTILITY LAYER          (utils/, lib/ - Helpers)     │
├─────────────────────────────────────────────────────┤
│ SCRIPT LAYER           (lua/ - Programação Custom)  │
└─────────────────────────────────────────────────────┘
```

### Fluxo de Dados Típico

```
Cliente (Player)
    ↓
Network Socket (server/)
    ↓
Game Logic (game/)
    ↓
Entity Processing (creatures/, items/)
    ↓
Database (database/)
    ↓
Persistence (io/)
    ↓
Back to Client
```

### Camadas Especializadas

```
1. ENTRY POINT
   └── main.cpp → canary_server.cpp
   
2. NETWORK HANDLING
   └── server/ (network, protocol parsing)
   
3. ACCOUNT & AUTH
   └── account/ + security/
   
4. CREATURES & ENTITIES
   └── creatures/ (players, monsters, npcs)
   
5. GAME MECHANICS
   └── game/ (combate, movimento, scheduling)
   
6. STORAGE & PERSISTENCE
   ├── database/ (queries)
   ├── io/ (serialização)
   └── kv/ (estado transiente)
   
7. SCRIPTING
   └── lua/ (callbacks, custom logic)
```

</Card>

## 🚀 Fluxo de Inicialização

<Card title="Sequência de Boot do Servidor" icon="zap">

### Fase 1: Startup

```
main.cpp
  ├── 1. Parse command-line arguments
  ├── 2. Load configuration (config/)
  ├── 3. Configure logging (lib/logging/)
  └── 4. Create Game instance
         └── game.cpp::Game::Game()
```

### Fase 2: Inicialização

```
canary_server.cpp
  ├── 1. Initialize database connection (database/)
  ├── 2. Load map from file (map/)
  ├── 3. Load items definitions (items/)
  ├── 4. Load creatures (monsters, npcs from data/)
  ├── 5. Setup account system (account/)
  ├── 6. Load Lua scripts (lua/)
  ├── 7. Initialize server socket (server/network/)
  └── 8. Start accepting connections
```

### Fase 3: Runtime Loop

```
Event Loop (asio/socket handling)
  ├── 1. Accept new connection → Create Player instance
  ├── 2. Receive packet from client
  ├── 3. Parse packet (server/protocol)
  ├── 4. Execute game logic (game/)
  ├── 5. Update creatures (creatures/)
  ├── 6. Execute Lua callbacks (lua/)
  ├── 7. Persist changes (database/)
  └── 8. Send response to client
```

### Fase 4: Shutdown

```
Server Shutdown (graceful)
  ├── 1. Stop accepting new connections
  ├── 2. Close all player connections
  ├── 3. Save player data (database/)
  ├── 4. Save map state (io/iomapserialize)
  ├── 5. Close database connections
  └── 6. Cleanup resources
```

</Card>

### account/ - Autenticação e Contas

**Responsabilidade**: Gerenciar contas de usuários, autenticação, dados de account.

**Arquivos principais:**
- `account.cpp/hpp` - Classe Account (dados de conta)
- `account_repository.cpp/hpp` - Interface de repositório de contas
- `account_repository_db.cpp/hpp` - Implementação via banco de dados

**Fluxo:**
```
Login Request
  ↓
account/account_repository::getAccount()
  ↓
Database Query (SELECT account WHERE name=?)
  ↓
Validate Password (Argon2)
  ↓
Return Account object ou null
```

**Tipos de Dados:**
- Account ID
- Username/Password (hash)
- Email
- Coins (Premium)
- Creation date
- Last login
- Account status/flags

class Creature {

### map/ - Carregamento de Mapa

**Responsabilidade**: Gerenciar o mapa (tiles, coordenadas, pathfinding).

class Map {

## 🧬 Stack de Criaturas

<Card title="Como Criaturas Funcionam" icon="dna">

### Inicialização

```
Monster spawna no mapa
  ↓
Game::createCreature(monsterId)
  ↓
MonsterType::loadMonster()
  ↓
Load from database:
  ├── Stats (HP, skills)
  ├── Attacks/Spells
  ├── Loot table
  └── Behavior
  ↓
Create instance: monster = new Monster(type)
  ↓
Adicionar ao mapa e ao Game
```

### Thinking Loop (Principal)

```cpp
// Executado periodicamente (50ms típico)
creature->onThink() {
    ├── if (isDead) return;
    ├── updateSpeed();
    ├── updateWithDistanceEffects();
    ├── checkCombatReset();
    ├── if (canAct) {
    │   ├── Player: Process input from client
    │   ├── Monster: Execute AI
    │   │   ├── Chase target
    │   │   ├── Cast spell
    │   │   ├── Heal self
    │   │   └── Update direction
    │   └── NPC: Wait for interaction
    ├── updateAbsorb();
    └── update(diff); // Timer management
}
```

### Combate

```
Player attacks Creature
  ↓
Game::createPlayerAttack()
  ↓
CalculateDamage():
  ├── Base damage (weapon)
  ├── Skills modifier
  ├── Resistances
  ├── Distance/Accuracy
  └── Rng/Miss chance
  ↓
creature->receiveDamage(damage)
  ↓
Apply condition if any (poison, paralyze)
  ↓
If health <= 0:
  ├── creature->onDeath()
  ├── Broadcast to spectators
  ├── Drop loot
  └── Remove from map
```

</Card>

## 💾 Persistência de Dados

<Card title="Como Dados São Salvos" icon="database">

### On-Demand Saving

```
Player faz ação significativa:
  ├── Kill monster
  ├── Trade item
  ├── Gain experience
  └── Trigger save
      ↓
      DatabaseManager.addTask(
          INSERT into player_stats ...
      )
```

### Periodic Saving

```
Servidor tem timer (30s típico):
  ├── Iterar todos players
  └── player->onSave()
      ├── Save inventory state
      ├── Save storage values
      ├── Save quest progress
      └── DATABASE INSERT
```

### Map Serialization

```
Server shutdown gracefully:
  ├── Close player connections
  ├── IOMapSerialize::saveMap()
  └── Salvar estado de cada tile
      ├── Items em tiles
      ├── Houses
      └── Temporal changes
```
